# 파일 / Files 화면 상세 기획

## 1. 화면 목적

`파일` 화면은 사용자가 업로드하거나 외부 저장소에서 가져온 파일을 안전하게 보관하고, AI가 읽을 수 있는 자료로 처리한 뒤 주제, 기억, 스크랩, 채팅에 연결하는 관리 화면이다. PRD의 원칙상 파일은 `file_asset` 객체이며, 원자료로서 스크랩이나 기억의 근거가 될 수 있다. 따라서 이 화면의 핵심은 파일 저장 자체가 아니라 “어떤 파일이 어디서 왔고, AI가 처리했는지, 어디에 연결되어 쓰이는지”를 사용자가 통제하는 것이다.

이 화면이 해결해야 하는 사용자 문제는 다음이다.

| 사용자 문제 | 화면에서의 해결 방식 |
| --- | --- |
| 파일이 여러 대화와 주제에 흩어져 다시 찾기 어려움 | 타입 탭, 검색, 필터, 연결된 주제 칩, 수정일 기준 목록 제공 |
| AI가 파일을 읽었는지 알기 어려움 | `요약 완료`, `요약 중` 같은 AI 요약 상태를 행 단위로 표시 |
| 로컬, Drive, 모바일, 생성 파일의 출처가 섞임 | 출처 컬럼에 업로드, Google Drive, 내 장치, 모바일 기기, 생성물 출처를 구분 표시 |
| 파일을 어떤 주제나 기억에 연결했는지 추적하기 어려움 | 목록의 연결된 주제와 상세 패널의 연결된 기억 섹션 제공 |
| 민감 파일이 채팅이나 AI 분석에 무심코 쓰일 수 있음 | 권한 컬럼, 파일별 접근 범위, 분석/첨부 전 승인 정책 제공 |
| 파일 요약만 보고 바로 활용하고 싶음 | 우측 상세 패널에서 미리보기, AI 추출 요약, 관련 기억, 분석/주제 연결/채팅 첨부 액션 제공 |

첨부 이미지 기준 선택 파일은 `도쿄 여행 일정.pdf`다. 파일은 2.4 MB PDF이며, 중앙 목록에서 `도쿄 여행` 주제에 연결되어 있고 AI 요약은 `요약 완료`, 권한은 `나만 보기`로 표시된다. 우측 상세 패널은 `미리보기`, `요약`, `세부 정보`, `연결` 탭과 하단 액션 `분석`, `주제에 연결`, `채팅에 첨부`를 제공한다.

## 2. 화면 범위와 전제

- 이 문서는 첨부 이미지와 `/docs/personal-agent-platform-prd.md` 기준의 PC 웹 화면 상세다.
- 소유 범위는 `파일 목록 + 업로드 영역 + 우측 파일 상세 패널`이다. 좌측 글로벌 내비게이션은 공통 셸로 간주하되, 이 화면에서 보이는 상태와 이동 요구사항은 기록한다.
- 파일은 원본 바이너리, 메타데이터, 텍스트 추출 결과, AI 요약 결과, 연결 관계를 분리해 관리한다.
- 파일 화면은 스크랩, 기억, 주제 화면과 겹치지만 역할이 다르다. 파일은 원본 객체, 스크랩은 수집 inbox, 기억은 검증된 장기 지식이다.
- MVP에서는 단일 사용자 개인 허브 기준으로 설계한다. 공유 허브가 도입되면 권한과 감사 로그 요구사항을 확장한다.
- 이 화면에서는 파일 내용을 직접 편집하지 않는다. 이름, 폴더, 연결, 권한, 요약 재처리, 삭제 같은 관리 작업만 수행한다.

### 3.4 우측 상세 패널 구조

선택 파일이 있을 때 우측 패널을 표시한다. 패널은 목록 선택 상태와 연결되며, 닫기 버튼을 누르면 선택을 해제하거나 패널만 접는다.

| 영역 | 구성 | 역할 |
| --- | --- | --- |
| 파일 헤더 | 타입 아이콘, 파일명, 크기, 닫기 | 선택 파일 식별 |
| 상세 탭 | 미리보기, 요약, 세부 정보, 연결 | 정보 범위 전환 |
| 미리보기 탭 | 문서/이미지/표 미리보기 | 원본 내용을 빠르게 확인 |
| AI 추출 요약 | 생성일, 체크 목록형 요약 | AI가 파일에서 추출한 핵심 내용 확인 |
| 연결된 기억 | 관련 기억 3개, `모두 보기` | 기억과 파일의 근거 관계 확인 |
| 하단 액션 | 분석, 주제에 연결, 채팅에 첨부 | 파일 활용 플로우 시작 |

이미지의 미리보기는 `도쿄 여행 일정 (5박 6일)` 표를 보여준다. 표 컬럼은 `일자`, `주요 일정`, `숙소`이며, 1일차 인천 출발과 나리타 도착, 2일차 시부야와 하라주쿠와 신주쿠, 3일차 디즈니랜드, 4일차 츠키지 시장과 긴자와 오다이바, 5일차 우에노와 아메요코와 이케부쿠로, 6일차 나리타 출발과 인천 도착이 보인다.

## 4. 진입 / 종료 / 전환 동선

### 4.1 진입 동선

| 진입점 | 동작 |
| --- | --- |
| 좌측 내비게이션 `파일` 클릭 | 마지막 검색/필터/선택 파일을 복원한다. 없으면 전체 목록과 최근 수정 파일을 표시한다. |
| 오늘 화면 채팅의 첨부 아이콘 | 기존 파일 선택 모달로 진입하거나 새 업로드 후 채팅 첨부 상태로 돌아간다. |
| 오늘 화면 빠른 의도 `자료 정리` | 업로드 영역 또는 파일 선택 플로우를 열고 업로드 완료 후 분석을 제안한다. |
| 주제 상세의 연결 파일 클릭 | 해당 파일을 선택한 상태로 파일 화면에 진입하고 우측 상세 패널을 연다. |
| 기억 상세의 출처 파일 클릭 | 해당 기억의 근거 파일 상세로 진입한다. |
| 스크랩 상세의 원본 파일 클릭 | 파일 상세를 열고 스크랩 연결 정보를 표시한다. |
| 맡긴 일 결과 파일 클릭 | run이 생성한 파일을 선택하고 `생성물` 타입 필터를 적용할 수 있다. |
| 외부 Drive 연결 동기화 후 | 새 외부 파일을 목록에 추가하고 출처를 Google Drive 등으로 표시한다. |
| URL 직접 접근 | `fileId`가 있으면 상세 패널을 열고, 권한 없거나 삭제된 파일이면 에러 상태 표시. |

## 5. 핵심 시나리오

### 5.1 파일을 업로드하고 AI 요약까지 확인

1. 사용자가 파일 화면에서 업로드 박스를 클릭하거나 파일을 드래그한다.
2. 시스템은 확장자, MIME type, 용량, 중복 파일 여부, 권한 정책을 검증한다.
3. 업로드가 시작되면 새 행을 `업로드 중` 또는 `요약 대기` 상태로 추가한다.
4. 업로드 완료 후 텍스트 추출과 AI 요약 작업을 비동기로 실행한다.
5. 요약 처리 중에는 `요약 중` 배지를 표시하고, 완료 시 `요약 완료`로 바꾼다.
6. 사용자가 파일 행을 선택하면 우측 패널에서 미리보기와 AI 추출 요약을 확인한다.
7. 요약이 유용하면 `주제에 연결`, `기억 추출`, `채팅에 첨부` 중 다음 활용 액션을 선택한다.

### 5.2 도쿄 여행 PDF를 주제와 기억에 연결

1. 사용자가 `도쿄 여행 일정.pdf` 행을 선택한다.
2. 우측 미리보기에서 5박 6일 일정표를 확인한다.
3. AI 추출 요약에서 주요 지역, 디즈니랜드 일정, 교통수단, 예산 추정 내용을 확인한다.
4. `주제에 연결`을 눌러 기존 `도쿄 여행` 주제를 선택하거나 새 여행 주제를 만든다.
5. 연결 완료 후 목록의 `연결된 주제` 칩이 갱신된다.
6. 시스템은 파일 요약에서 기억 후보를 제안한다.
7. 사용자가 `여행 선호도`, `도쿄 맛집 기준`, `여행 예산 범위` 같은 기억으로 저장할 항목을 확정한다.

### 5.3 기존 파일을 채팅에 첨부

1. 사용자가 오늘 화면이나 주제 채팅에서 첨부 아이콘을 클릭한다.
2. 파일 선택 모달 또는 파일 화면 딥링크가 열린다.
3. 사용자는 검색/타입 탭으로 `투자 리포트.xlsx`를 찾는다.
4. 권한과 요약 상태를 확인한 뒤 `채팅에 첨부`를 누른다.
5. 시스템은 호출한 채팅으로 파일 참조를 전달한다.
6. 채팅 입력창에는 파일 칩이 표시되고, 전송 시 AI는 파일 요약 또는 원문 추출 결과를 함께 참조한다.
7. 파일 접근이 제한되거나 요약이 실패한 경우 채팅 전송 전에 재처리 또는 권한 변경을 안내한다.

### 5.4 외부 Drive 파일을 가져와 분석

1. 사용자가 연결 화면에서 Google Drive를 연결한다.
2. 파일 화면 목록에 Google Drive 출처 파일이 표시된다.
3. 사용자가 `투자 리포트.xlsx`를 선택한다.
4. 시스템은 외부 파일 원문 접근 권한과 최신 동기화 시간을 확인한다.
5. 사용자가 `분석`을 누르면 스프레드시트 구조를 읽고 투자 리서치 주제에 맞춘 분석을 실행한다.
6. 분석 결과는 채팅 답변, 파일 요약, 주제 활동, 필요 시 생성 파일로 저장된다.
7. Drive 연결이 끊긴 경우 기존 메타데이터와 캐시 요약은 표시하되 원문 재분석은 차단한다.

### 5.5 폴더를 만들어 파일을 정리

1. 사용자가 `폴더 만들기`를 클릭한다.
2. 시스템은 폴더명 입력 모달을 연다.
3. 사용자는 `여행 자료` 같은 이름을 입력한다.
4. 폴더 생성 후 파일 목록 필터나 폴더 트리에서 해당 폴더를 볼 수 있다.
5. 사용자가 파일 행 overflow 메뉴에서 `폴더로 이동`을 선택한다.
6. 이동 완료 후 파일의 `folderId`가 갱신되고 현재 필터 조건에 따라 목록 위치가 바뀐다.

### 5.6 run 또는 에이전트가 만든 생성물을 파일로 관리

1. 맡긴 일 run 또는 에이전트 테스트가 PDF, CSV, 이미지 같은 산출물을 만든다.
2. 시스템은 산출물을 `생성물` 타입의 `file_asset`으로 등록한다.
3. 파일 화면의 `생성물` 탭에서 해당 파일을 볼 수 있다.
4. 상세 패널의 출처는 `맡긴 일`, `에이전트`, `채팅`, `문서 빌더` 중 생성 경로를 표시한다.
5. 사용자는 생성물을 다운로드하거나 주제에 연결하거나 다음 채팅에 첨부한다.

## 6. 컴포넌트별 상세 기능

### 6.1 좌측 글로벌 내비게이션

| 요소 | 기능 |
| --- | --- |
| 허브명 `내 AI 허브` | 워크스페이스 전환 드롭다운 진입 |
| 알림 아이콘 | 요약 실패, 업로드 실패, 권한 승인 대기, 외부 Drive 연결 끊김 알림 |
| 메뉴 목록 | 현재 `파일` 메뉴를 파란색 활성 상태로 표시 |
| 설정/도움말 | 파일 보관 정책, 업로드 제한, 권한 정책, 도움말 문서로 이동 |
| 사용자 카드 | 사용자명, 플랜, 저장소 사용량, 계정 메뉴 진입 |

### 6.2 화면 헤더

| 요소 | 기능 |
| --- | --- |
| 제목 `파일` | 현재 페이지의 최상위 제목 |
| 보조 문구 | “모든 파일을 안전하게 저장하고, AI와 함께 활용해 보세요.” |
| `폴더 만들기` | 새 폴더 생성 모달 열기 |
| 더보기 메뉴 | 일괄 선택, 보기 설정, 정렬 기본값, 보관함, 휴지통, 외부 파일 동기화, 저장소 사용량 보기 |

`폴더 만들기`는 단순 UI 폴더다. 파일의 원본 출처나 주제 연결을 대체하지 않는다. 폴더 이동은 파일 탐색 편의를 위한 `folderId` 변경이며, 주제나 기억 연결은 그대로 유지한다.

### 6.3 업로드 영역

| 요소 | 기능 |
| --- | --- |
| 드래그 앤 드롭 영역 | 파일을 끌어 놓으면 업로드 대기열 생성 |
| 클릭 업로드 | OS 파일 선택 창 열기 |
| 지원 형식 안내 | PDF, DOCX, XLSX, PPTX, TXT, CSV, PNG, JPG |
| 용량 안내 | 파일당 최대 100MB |
| 업로드 진행 | 파일별 진행률, 취소, 실패 사유, 재시도 표시 |

업로드 완료 후 처리 흐름은 `업로드 중 -> 요약 대기 -> 추출 중 -> 요약 중 -> 요약 완료`가 기본이다. 이미지 파일은 OCR 또는 이미지 분석 가능 여부에 따라 `요약 대기` 없이 `분석 가능` 상태가 될 수 있다.

### 6.4 타입 탭

| 탭 | 포함 대상 | 기준 |
| --- | --- | --- |
| 전체 | 모든 파일 | 보관/삭제 제외 기본 |
| 문서 | DOCX, PPTX, TXT, MD 등 | 텍스트 기반 문서 |
| 이미지 | PNG, JPG | 이미지, 캡처, OCR 대상 |
| PDF | PDF | 문서형 PDF와 이미지형 PDF 모두 |
| 데이터 | XLSX, CSV | 표, 데이터셋, 비용표, 리포트 |
| 생성물 | AI나 run이 만든 파일 | 생성 경로가 platform/run/agent인 파일 |

타입은 확장자만으로 확정하지 않는다. MIME type, 원문 파서 결과, 생성 경로를 함께 사용한다. 예를 들어 PDF는 `PDF` 탭에 포함되며 동시에 넓은 의미의 문서지만, 이미지 기준 화면처럼 전용 탭을 우선한다.

### 6.5 검색과 필터

검색 대상은 파일명, 확장자, 출처 이름, 연결된 주제명, 연결된 기억명, AI 요약 텍스트, 업로더, 장치명이다.

고급 필터는 다음 조건을 지원한다.

| 필터 | 값 |
| --- | --- |
| 출처 | 업로드, 내 장치, 모바일, Google Drive, 생성물, 스크랩, 채팅 첨부 |
| 폴더 | 전체, 루트, 특정 폴더, 폴더 없음 |
| 타입 | 문서, 이미지, PDF, 데이터, 생성물 |
| AI 요약 상태 | 요약 대기, 추출 중, 요약 중, 요약 완료, 실패, 지원 안 함 |
| 권한 | 나만 보기, 주제 멤버 보기, 공유됨, 읽기 전용, 제한됨 |
| 연결 상태 | 연결된 주제 있음, 연결 없음, 연결된 기억 있음, 채팅 첨부 이력 있음 |
| 수정일 | 오늘, 최근 7일, 최근 30일, 직접 범위 |
| 크기 | 1MB 이하, 1-10MB, 10-100MB, 100MB 초과 차단 파일 |
| 생성 방식 | 사용자 업로드, 외부 동기화, 에이전트 생성, 채팅 생성, 문서 빌더 생성 |

필터 적용 상태는 URL query에 반영해 딥링크와 새로고침 복원이 가능해야 한다.

### 6.6 파일 목록 테이블

목록은 밀도 높은 테이블이다. 파일이 작업 대상이므로 카드보다 정렬과 비교가 쉬운 행 구성이 기본이다.

| 컬럼 | 기능 |
| --- | --- |
| 이름 | 파일 타입 아이콘, 파일명, 파일 크기 표시. 클릭 시 상세 패널 선택. |
| 출처 | 원본 출처와 하위 설명 표시. 예: `업로드 / 내가 업로드`, `Google Drive / drive.google.com`, `내 장치 / MacBook Pro`. |
| 연결된 주제 | topic 칩 표시. 클릭 시 주제 화면 또는 주제 작업실로 이동. |
| AI 요약 | 요약 상태 배지와 진행 상태 표시. 실패 시 재시도 진입. |
| 수정일 | 마지막 수정 또는 마지막 동기화 시각. 사용자 로컬 시간대 기준. |
| 권한 | `나만 보기`, `공유됨`, `읽기 전용`, `제한됨` 등 접근 범위 표시. |
| 행 overflow | 이름 변경, 폴더로 이동, 주제 연결, 기억 추출, 요약 재실행, 다운로드, 권한 변경, 보관, 삭제. |

행 클릭은 파일 선택이다. 주제 칩, 요약 재시도 버튼, 권한 배지, overflow 메뉴는 행 선택과 이벤트가 충돌하지 않아야 한다.

### 6.7 파일 타입 아이콘과 배지

| 타입 | 화면 표현 | 요구사항 |
| --- | --- | --- |
| PDF | 빨간 PDF 아이콘 | PDF 전용 미리보기와 페이지 단위 텍스트 추출 |
| XLSX | 초록 XLSX 아이콘 | 시트 목록, 표 요약, 데이터 분석 지원 |
| MD | 회색 MD 아이콘 | Markdown 미리보기와 문서 요약 |
| TXT | 파란 TXT 아이콘 | 텍스트 전체 또는 chunk 요약 |
| PNG/JPG | 보라 이미지 아이콘 | 이미지 미리보기, OCR, 이미지 분석 |
| CSV | 초록 CSV 아이콘 | 컬럼/행 수, 표 샘플, 데이터 요약 |

지원하지 않는 확장자는 업로드 자체를 차단하거나 `지원 안 함` 상태로 저장할 수 있다. 정책 결정 전에는 업로드 허용 목록을 화면 안내와 API 검증 모두에 동일하게 적용한다.

### 6.8 폴더 기능

| 기능 | 요구사항 |
| --- | --- |
| 폴더 생성 | 이름 필수, 같은 상위 폴더 내 중복 이름 처리 필요 |
| 폴더 이동 | 단일 파일과 다중 선택 파일 이동 지원 |
| 폴더 삭제 | 비어 있지 않은 폴더는 파일 이동/함께 보관/삭제 옵션 제공 |
| 폴더 검색 | 파일 검색과 별도로 폴더명 검색 또는 필터 제공 |
| 기본 폴더 | 루트 또는 `분류 없음` 상태 |

폴더는 화면 상단 이미지에 목록으로 보이지 않지만 `폴더 만들기` 버튼이 있으므로 개발 모델에는 포함해야 한다. 폴더와 주제는 다르다. 폴더는 개인 정리용 위치이고, 주제 연결은 AI 작업 scope와 지식 연결이다.

### 6.9 우측 상세 패널 헤더

| 요소 | 기능 |
| --- | --- |
| 타입 아이콘 | 파일 형식 식별 |
| 파일명 | 선택 파일 이름. 긴 이름은 줄임 표시, tooltip으로 전체 노출 |
| 파일 크기 | 원본 파일 크기 |
| 닫기 | 상세 패널 닫기 |

헤더에서 바로 이름 편집을 제공하지 않는다. 이름 변경은 overflow 메뉴나 세부 정보 탭의 편집 플로우에서 수행한다.

### 6.10 미리보기 탭

| 파일 타입 | 미리보기 요구사항 |
| --- | --- |
| PDF | 첫 페이지 또는 선택 페이지 미리보기, 페이지 이동, 텍스트 추출 실패 표시 |
| DOCX/PPTX | 문서 변환 미리보기 또는 요약 우선 표시 |
| XLSX/CSV | 시트/컬럼/샘플 행 표 표시 |
| TXT/MD | 텍스트/Markdown 렌더링, 긴 문서는 접기 |
| PNG/JPG | 이미지 fit, 확대, OCR 결과 진입 |
| 생성물 | 생성 원본 run과 출력 포맷에 맞는 미리보기 |

이미지 기준 PDF 미리보기는 일정표 카드로 렌더링된다. 원본 전체 렌더링이 늦으면 추출된 구조화 미리보기를 먼저 보여주고, 원본 렌더링이 완료되면 교체한다.

### 6.11 요약 탭과 AI 추출 요약

| 요소 | 기능 |
| --- | --- |
| 생성일 | AI 요약 생성 또는 마지막 갱신 날짜 표시 |
| 핵심 요약 | 체크 목록 형태의 요약 표시 |
| 근거 | 원문 페이지, 표 영역, 이미지 OCR 영역, 시트명 등 citation 연결 |
| 재요약 | 최신 모델 또는 다른 목적 기준으로 요약 재실행 |
| 기억 저장 | 요약 항목 중 장기 기억으로 저장할 후보 선택 |

이미지의 AI 추출 요약 예시는 다음이다.

| 요약 항목 |
| --- |
| 5박 6일 일정으로 도쿄 주요 지역을 고르게 포함 |
| 디즈니랜드는 3일차에 하루 일정으로 배치 |
| 교통은 스이카 카드 사용 예정 |
| 총 예산은 1인 약 120~150만원 예상 |

요약 상태가 `요약 중`이면 skeleton, progress, 취소 가능 여부를 표시한다. 실패하면 실패 원인과 재시도 액션을 제공한다.

### 6.12 세부 정보 탭

세부 정보 탭은 화면 이미지에는 내용이 열려 있지 않지만 탭이 보이므로 구현 범위에 포함한다.

| 섹션 | 필드 |
| --- | --- |
| 기본 정보 | 파일명, 확장자, MIME type, 크기, 타입 분류, 폴더, 생성 방식 |
| 출처 | 출처 유형, 원본 URL 또는 provider, 장치명, 업로더, 동기화 상태 |
| 처리 상태 | 업로드 상태, 텍스트 추출 상태, AI 요약 상태, 마지막 처리 시각, 실패 사유 |
| 권한 | 소유자, 공개 범위, 공유 대상, AI 참조 허용 여부, 채팅 첨부 허용 여부 |
| 변경 이력 | 업로드, 이름 변경, 권한 변경, 요약 재실행, 주제 연결, 삭제/복구 이력 |
| 저장소 | storage key, checksum, 버전, 바이러스 스캔 상태 |

### 6.13 연결 탭

연결 탭은 파일이 어디에 쓰이는지 보여주고 변경하는 곳이다.

| 연결 대상 | 표시/기능 |
| --- | --- |
| 주제 | 연결된 topic 칩, 연결 추가, 연결 해제, 주제 작업실 열기 |
| 기억 | 파일에서 추출된 기억 목록, 근거 연결, 기억 상세로 이동 |
| 스크랩 | 파일이 스크랩 inbox에서 들어온 경우 원본 스크랩 표시 |
| 채팅 | 첨부된 대화 목록, 사용 시각, 사용된 요약/citation |
| 맡긴 일 | 파일을 입력으로 사용한 run 또는 파일을 생성한 run |
| 문서/artifact | 파일을 근거로 만들어진 보고서, 표, 지도, 문서 |

연결 해제는 파일 원본을 삭제하지 않는다. 다만 기억의 유일한 출처인 파일 연결을 끊으면 기억 신뢰도 재계산 또는 출처 없음 경고가 필요하다.

### 6.14 연결된 기억 섹션

이미지 기준 우측 패널에는 `연결된 기억` 제목, `모두 보기` 링크, 3개 기억 항목이 보인다.

| 기억 | 보조 설명 | 연결 의미 |
| --- | --- | --- |
| 여행 선호도 | 교통 편의성을 중요하게 생각함 | PDF 일정과 사용자의 여행 취향 연결 |
| 도쿄 맛집 기준 | 현지 인기 맛집 위주로 방문 | 일정 내 맛집 선택 기준 |
| 여행 예산 범위 | 1인 100~150만원 선 | 일정 비용 추정 기준 |

기억 항목 클릭 시 기억 상세로 이동한다. `모두 보기`는 파일의 연결 탭 또는 기억 화면 필터로 이동한다.

### 6.15 하단 액션

| 액션 | 동작 |
| --- | --- |
| 분석 | 선택 파일을 현재 목적 없이 단독 분석하거나, 목적 입력 모달을 열어 분석 run을 시작한다. |
| 주제에 연결 | 기존 주제 선택 또는 새 주제 생성 후 파일을 topic source로 연결한다. |
| 채팅에 첨부 | 현재 또는 최근 채팅 scope에 파일 참조를 첨부한다. |

`분석`은 파일 원문 읽기, 텍스트 추출, 이미지 분석, 데이터 분석, 모델 호출 비용을 만들 수 있다. 비용 한도와 권한 정책에 따라 승인 카드가 필요할 수 있다.

### 6.16 행 overflow 메뉴

| 액션 | 요구사항 |
| --- | --- |

| 이름 변경 | 파일 표시 이름 수정. 확장자 변경은 별도 확인. |

| 주제에 연결 | 연결 대상 topic 선택. 다중 연결 허용 여부 결정 필요. |

| 삭제 | 영향 범위 확인 후 soft delete 또는 hard delete. |

## 7. 업로드 / 폴더 / 타입 / 출처 / 요약 / 권한 / 파일 상세 정책

### 7.1 업로드 정책

| 항목 | 정책 |
| --- | --- |
| 허용 형식 | PDF, DOCX, XLSX, PPTX, TXT, CSV, PNG, JPG |
| 최대 용량 | 파일당 100MB |
| 다중 업로드 | 지원. 파일별 진행률과 실패 사유 표시 |
| 중복 감지 | checksum, 파일명, 크기 기준 중복 후보 표시 |
| 바이러스/안전 검사 | 완료 전 AI 분석과 공유를 제한 |
| 실패 처리 | 네트워크 실패, 용량 초과, 형식 미지원, 권한 부족, 외부 저장소 오류를 구분 |

### 7.2 폴더 정책

폴더는 탐색 편의용 분류다. 주제 연결, 기억 연결, 스크랩 출처와 독립적으로 동작한다.

| 정책 | 설명 |
| --- | --- |
| 루트 파일 | 폴더가 없는 파일은 루트 또는 `분류 없음`으로 표시 |
| 중첩 폴더 | MVP에서는 1단계 폴더만 우선, 추후 중첩 허용 검토 |
| 폴더별 권한 | MVP에서는 파일별 권한 우선, 폴더 권한 상속은 오픈 질문 |
| 폴더 삭제 | 파일이 있으면 이동/보관/삭제 선택 필요 |

| 분류 | 기준 | 화면 영향 |

| 상태 | UI 표시 | 동작 |
| --- | --- | --- |
| 요약 대기 | 회색 배지 | 업로드 완료, 처리 queue 대기 |
| 추출 중 | 파란 진행 배지 | 텍스트/OCR/표 추출 중 |
| 요약 중 | 파란 spinner 배지 | 모델 요약 실행 중 |
| 요약 완료 | 초록 배지 | 요약 탭과 기억 추출 가능 |
| 실패 | 빨간 배지 | 실패 원인, 재시도, 원본 미리보기 가능 여부 표시 |
| 지원 안 함 | 회색 배지 | AI 처리 불가. 다운로드와 권한 관리만 가능 |

### 7.6 권한 정책

| 권한 | 의미 | UI 요구사항 |
| --- | --- | --- |
| 나만 보기 | 소유자만 접근 | 이미지 기본값. 채팅 첨부도 소유자 scope에서만 가능 |
| 주제 멤버 보기 | 연결된 주제 접근자에게 읽기 허용 | 공유 주제 도입 시 필요 |
| 공유됨 | 명시 공유 대상 있음 | 공유 대상 수와 링크 상태 표시 |
| 읽기 전용 | 원문/요약 조회 가능, 수정 불가 | 이름 변경, 삭제, 권한 변경 비활성 |
| 제한됨 | 민감, 외부 권한 만료, 정책 차단 | 미리보기/분석/첨부 차단 사유 표시 |
| AI 참조 제외 | 사용자 조회는 가능하지만 AI 분석에서 제외 | 분석과 채팅 첨부 전 경고 또는 차단 |

파일 삭제, 권한 완화, 외부 공유, 대량 다운로드는 승인 또는 확인이 필요하다. 민감 가능성이 있는 파일은 AI 분석 전 별도 확인을 요구할 수 있다.

### 7.7 파일 상세 정책

파일 상세는 원본과 AI 처리 결과를 함께 보여주되, 사용자가 혼동하지 않게 분리한다.

| 구분 | 내용 |
| --- | --- |
| 원본 | 파일명, 크기, 타입, 출처, 미리보기, 다운로드 |
| 처리 결과 | 텍스트 추출, OCR, 표 구조화, AI 요약, citation |
| 연결 관계 | 주제, 기억, 스크랩, 채팅, run, artifact |
| 운영 정보 | 권한, 변경 이력, 저장소, 동기화, 스캔 상태 |

## 8. 다른 화면과의 연계

| 대상 화면 | 연계 방식 |
| --- | --- |
| 오늘 | 전역 채팅 첨부, 빠른 의도 `자료 정리`, 추천 도구에서 파일 업로드/분석으로 진입 |
| 주제 | 파일을 topic source로 연결. 주제 자료 탭과 활동 timeline에 반영 |
| 기억 | 파일 요약에서 기억 후보 생성. 기억 상세에서 파일을 출처로 표시 |
| 스크랩 | 파일형 스크랩의 원본 파일 관리. 스크랩이 기억으로 승격될 때 파일 citation 유지 |
| 채팅 | 기존 파일 선택, 새 파일 업로드, 파일 칩 첨부, 사용한 파일 citation 표시 |
| 맡긴 일 | run 입력 파일과 결과 파일을 파일 화면에서 관리 |
| 에이전트 | agent 지식으로 파일 연결. 테스트/실행 산출물을 파일로 저장 |
| 연결 | Google Drive 같은 외부 저장소 연결 상태가 파일 동기화와 원문 재조회에 영향 |
| 캘린더 | 일정 PDF나 ICS 파일을 분석해 calendar event 제안 가능 |
| 할 일 | 파일에서 체크리스트나 task를 추출해 할 일로 생성 가능 |
| 설정 | 저장소 용량, 업로드 제한, 승인 정책, 비용 한도, AI 참조 기본값 적용 |

### 8.1 주제 연계

파일은 여러 주제에 연결될 수 있다. `도쿄 여행 일정.pdf`처럼 일정 파일은 `도쿄 여행` 주제 작업실의 자료 탭, 최근 활동, 채팅 citation에서 조회 가능해야 한다.

| 동작 | 결과 |
| --- | --- |
| 파일에서 주제 연결 | 파일 목록 주제 칩 갱신, 주제 자료 탭에 파일 추가 |
| 주제에서 파일 연결 해제 | 파일 원본은 유지, 해당 topic-source 관계만 삭제 |
| 주제 삭제 | 파일은 유지, 연결 관계는 제거 또는 삭제된 주제 표시 |
| 주제 권한 변경 | 파일 자체 권한과 주제 권한의 충돌을 검사 |

### 8.2 기억 연계

파일 요약에서 추출한 선호도, 결정, 기준, 자료는 기억으로 저장될 수 있다. 기억은 파일 전체가 아니라 특정 요약 항목이나 citation에 근거를 둔다.

| 동작 | 결과 |
| --- | --- |
| 기억 추출 | 후보 목록 생성, 사용자가 저장할 항목 선택 |
| 기억 상세에서 출처 확인 | 파일 상세 미리보기의 해당 위치로 이동 |
| 파일 삭제 | 연결 기억의 출처 제거, 신뢰도 재계산, 사용자 확인 필요 |
| 요약 재실행 | 기존 기억과 새 요약의 충돌 여부 표시 |

### 8.3 스크랩 연계

스크랩은 파일이 들어오는 또 다른 경로다. 예를 들어 PDF URL을 스크랩했거나 기사 첨부 파일을 저장한 경우 스크랩 객체와 파일 객체가 함께 존재한다.

| 동작 | 결과 |
| --- | --- |
| 스크랩에서 파일 생성 | 파일 출처를 `스크랩`으로 표시 |
| 파일에서 스크랩 열기 | 원본 스크랩 상세로 이동 |
| 스크랩 보관 | 파일 원본은 정책에 따라 유지 또는 함께 보관 후보 |
| 스크랩 삭제 | 파일을 함께 삭제할지 연결만 제거할지 선택 |

### 8.4 채팅 첨부 연계

채팅 첨부는 파일을 AI에게 쓰게 하는 명시 동작이다.

| 항목 | 요구사항 |
| --- | --- |
| 첨부 대상 | 전역 채팅, topic chat, agent test chat, run chat |
| 첨부 단위 | 원본 파일, 요약 결과, 특정 페이지/시트/이미지 영역 |
| 권한 확인 | 파일 읽기 권한, AI 참조 허용, 외부 연결 상태 확인 |
| 상태 확인 | 요약 완료가 아니어도 원문 추출이 가능하면 첨부 가능. 불가능하면 처리 유도 |
| 사용 기록 | 어떤 대화에서 어떤 파일을 참조했는지 상세 연결 탭에 기록 |
| citation | 답변에 파일명, 페이지, 시트, OCR 영역 등 근거 표시 |

## 11. 수용 기준

### 11.1 목록과 탐색

- 사용자는 `파일` 화면 진입 후 업로드 영역, 타입 탭, 검색/필터, 파일 목록, 페이지네이션을 볼 수 있다.
- 타입 탭 선택 시 전체/문서/이미지/PDF/데이터/생성물 기준으로 목록이 좁혀진다.
- 검색어 입력 시 파일명, 출처, 연결된 주제, 연결된 기억, AI 요약 텍스트 기준으로 결과가 좁혀진다.
- 필터 조건이 결과 0개일 때 원인과 다음 액션이 표시된다.
- 페이지 이동과 페이지 크기 변경은 현재 검색/필터 조건을 유지한다.

### 11.2 업로드와 처리 상태

- 사용자는 업로드 박스 클릭 또는 드래그 앤 드롭으로 허용 형식 파일을 업로드할 수 있다.
- 파일당 100MB 초과 또는 미지원 확장자는 업로드 전에 차단된다.
- 업로드 중인 파일은 진행률, 취소, 실패 사유, 재시도를 표시한다.
- 업로드 완료 후 AI 요약 상태가 `요약 대기`, `추출 중`, `요약 중`, `요약 완료`, `실패` 중 하나로 표시된다.
- 요약 완료 파일은 우측 패널에서 AI 추출 요약을 확인할 수 있다.

### 11.3 파일 목록 행

- 각 행에는 파일 타입 아이콘, 파일명, 크기, 출처, 연결된 주제, AI 요약 상태, 수정일, 권한, overflow 메뉴가 표시된다.
- 행 클릭 시 우측 상세 패널이 해당 파일로 갱신된다.
- 연결된 주제 칩 클릭 시 해당 주제 화면 또는 작업실로 이동할 수 있다.
- 요약 실패 행은 실패 상태와 재시도 진입점을 제공한다.
- 권한 제한 파일은 목록에서 제한 상태를 명확히 표시하고 제한된 액션을 비활성화한다.

### 11.4 상세 패널

- 선택 파일의 타입 아이콘, 파일명, 크기, 닫기 버튼이 표시된다.
- `미리보기`, `요약`, `세부 정보`, `연결` 탭 전환이 가능하다.
- 미리보기 탭은 파일 타입에 맞는 preview 또는 preview 실패 상태를 표시한다.
- 요약 탭은 생성일, 핵심 요약, citation 또는 근거 정보를 표시한다.
- 연결 탭은 주제, 기억, 스크랩, 채팅, run, artifact 연결을 확인하고 관리할 수 있다.
- 하단에는 `분석`, `주제에 연결`, `채팅에 첨부` 액션이 표시된다.

### 11.5 연계와 안전

- `주제에 연결` 완료 후 목록의 주제 칩과 상세 연결 탭이 즉시 갱신된다.
- `채팅에 첨부`는 파일 읽기 권한, AI 참조 허용 여부, 요약/추출 가능 여부를 확인한 뒤 실행된다.
- 파일 요약에서 기억 후보를 만들 수 있고, 저장된 기억은 파일을 출처로 가진다.
- 파일 삭제, 권한 완화, 고비용 분석, 대량 업로드는 영향 범위나 비용을 확인한 뒤 실행된다.
- 외부 Drive 연결이 끊기면 원문 재분석과 새 동기화는 차단하고 캐시된 메타데이터/요약은 표시한다.

## 12. 자체 Edge Case 리뷰

사용자 요청에 따라 nested subagent로 읽기 전용 엣지케이스 리뷰를 시도했다. `codex-subagent` wrapper가 agent 메시지를 만들지 못하고 빈 로그로 실패해 별도 리뷰 결과를 받을 수 없었다. 외부 전송이나 파일 수정 없이 자체 리뷰를 수행했고, 아래 항목을 문서에 반영했다.

| 검토 항목 | 확인 결과 |
| --- | --- |
| 이미지에 보이는 기능 누락 여부 | 좌측 내비, 알림, 사용자 플랜, 헤더, `폴더 만들기`, 더보기, 업로드 박스, 타입 탭, 검색, 필터, 테이블 컬럼 6개, 행 6개, 페이지네이션, 우측 상세 패널, 상세 탭, 미리보기, AI 추출 요약, 연결된 기억, 하단 액션 3개를 반영했다. |
| PRD 객체 경계 | 파일은 `file_asset`, 스크랩은 inbox, 기억은 검증된 장기 지식이라는 경계를 명시했다. |
| 업로드 리스크 | 용량/형식/중복/바이러스 검사/처리 queue/요약 실패/대량 업로드 비용을 포함했다. |
| 권한 리스크 | `나만 보기`, 읽기 전용, 제한됨, AI 참조 제외, 외부 권한 만료, 주제 권한 충돌을 포함했다. |
| 연계 리스크 | 주제, 기억, 스크랩, 채팅 첨부, 맡긴 일, 에이전트, 연결, 설정과의 데이터 흐름을 분리했다. |
| 개발 착수 가능성 | 주요 객체 필드, API 힌트, 이벤트, 수용 기준을 포함했다. 실제 route명과 삭제/버전 정책은 오픈 질문으로 남겼다. |

## 13. 오픈 질문

| 질문 | 후보/결정 필요 |
| --- | --- |
| 폴더 중첩을 MVP에서 허용할지 | 1단계 폴더만 우선하고 추후 중첩 확장 권장 |
| 파일과 스크랩의 생성 관계 | 파일형 스크랩이 항상 `file_asset`을 만들지, 필요할 때만 만들지 결정 필요 |
| PDF 타입 분류 | PDF를 `문서`에도 포함할지, 이미지처럼 전용 탭만 둘지 결정 필요 |
| 생성물의 보관 위치 | run 결과를 항상 파일에 저장할지, 다운로드 전까지 임시 artifact로 둘지 결정 필요 |
| 요약 버전 관리 | 요약 재실행 시 이전 요약과 citation을 보존할지 덮어쓸지 결정 필요 |
| 파일 버전 관리 | 외부 Drive 파일 변경 또는 같은 파일 재업로드 시 새 버전으로 둘지 새 파일로 둘지 결정 필요 |
| 권한 상속 | 주제에 연결된 파일을 주제 멤버에게 자동 공개할지, 파일 권한을 항상 우선할지 결정 필요 |
| AI 참조 기본값 | 업로드 직후 AI 요약을 자동 실행할지, 사용자가 명시적으로 분석할 때만 실행할지 결정 필요 |
| 민감 파일 감지 범위 | OCR/텍스트 추출 전에도 민감도 검사가 가능한지, 검사 실패 시 기본 차단할지 결정 필요 |
| 외부 Drive 원본 저장 | 외부 파일을 플랫폼에 캐시할지, 메타데이터와 요약만 저장할지 결정 필요 |
| 채팅 첨부 단위 | 전체 파일만 첨부할지, 페이지/시트/요약 항목 단위 첨부를 허용할지 결정 필요 |
| 삭제 정책 | soft delete, 휴지통 보관 기간, hard delete 시 기억/채팅 citation 처리 방식 결정 필요 |
| 저장소 quota | 사용자 플랜별 총 용량, 파일 수, 일일 업로드 제한을 어디에 표시할지 결정 필요 |
| 이미지 OCR 비용 | OCR과 이미지 분석을 같은 요약 상태로 볼지 별도 상태로 분리할지 결정 필요 |
| 페이지네이션 기본값 | 이미지의 `20개씩`을 기본으로 확정할지, 사용자가 마지막 선택값을 유지할지 결정 필요 |
