# 할 일 / Todo Board 화면 상세 기획

## 1. 화면 목적

`할 일` 화면은 사용자가 직접 관리하는 실행 항목을 오늘 해야 할 일, 예정된 일, 진행 중인 일, 완료된 일로 나눠 관리하는 작업 보드다. 동시에 채팅, 주제, 파일, 자동 생성 결과에서 나온 후속 액션을 한곳에 모아 AI 제안을 검토하고, 필요하면 `맡긴 일`의 run으로 넘기는 실행 준비 화면이다.

이 화면이 해결해야 하는 사용자 문제는 다음이다.

| 사용자 문제 | 화면에서의 해결 방식 |
| --- | --- |
| 오늘 실제로 무엇을 해야 하는지 헷갈림 | `오늘`, `이번 주`, `주제별`, `자동 생성` 탭과 칸반 보드로 우선순위별 할 일을 정리 |
| 채팅/파일/주제에서 나온 후속 액션이 흩어짐 | task에 주제, 파일, 대화, source, run 연결 정보를 보관하고 상세 패널에서 추적 |
| AI가 제안한 다음 액션을 바로 믿기 어려움 | 카드와 상세 패널에 `AI 제안` 문구, 제안 상태, 체크리스트, 근거 자료를 함께 노출 |
| 단순 할 일과 AI에게 맡길 일을 구분하기 어려움 | 사용자가 직접 처리할 task와 `AI에게 맡기기`로 run을 생성할 task를 같은 상세 패널에서 전환 |
| 목록, 보드, 맵이 서로 다른 데이터처럼 느껴짐 | 동일한 task 데이터를 칸반, 목록, 맵 view로만 바꿔 보여줌 |

PRD 기준으로 `할 일`은 내부 객체 `task`, `checklist`, `dependency`, `topic`, `conversation`, `source`, `file_asset`, `run`, `schedule`, `ai_suggestion`, `audit_log`가 만나는 실행 항목 관리면이다. `맡긴 일`이 실제 agent 실행 기록을 관제하는 화면이라면, `할 일`은 사람이 검토·정리·우선순위화한 뒤 일부를 AI 실행으로 승격시키는 화면이다.

## 2. 정보 구조

### 2.1 전체 레이아웃

```text
좌측 글로벌 내비
  └─ 할 일 메뉴 활성화

중앙 메인 영역
  ├─ 화면 제목 / 설명
  ├─ 상위 탭: 오늘 / 이번 주 / 주제별 / 자동 생성
  ├─ + 할 일 추가 / 더보기
  ├─ 필터: 우선순위 / 마감일 / 전체 선택 / 정렬
  └─ 작업 보드
      ├─ 오늘
      ├─ 예정
      ├─ 진행 중
      └─ 완료

우측 상세 패널
  ├─ 선택 task 헤더 / 완료 체크 / 우선순위 / 닫기
  ├─ 탭: 개요 / 연결된 정보 / 활동 기록
  ├─ AI 제안
  ├─ 체크리스트
  ├─ 연결된 대화
  ├─ 연결된 파일
  ├─ 다음으로 추천
  └─ AI에게 맡기기 / 더보기
```

### 2.2 좌측 글로벌 내비

첨부 화면의 글로벌 내비는 모든 화면 공통 셸을 유지한다.

| 영역 | 항목 | 동작 |
| --- | --- | --- |
| 상단 | 프로필 이미지, `내 AI 허브`, 드롭다운, 알림 | 허브 전환, 알림 센터 진입 |
| 주요 메뉴 | 오늘, 주제, 맡긴 일, 기억, 에이전트, 연결 | 상위 화면 이동 |
| 보조 메뉴 | 스크랩, 캘린더, 할 일, 파일 | 관련 관리 화면 이동. 현재 화면에서는 `할 일`이 파란색 활성 상태 |
| 하단 | 설정, 도움말 | 전역 설정과 도움말 이동 |
| 계정 카드 | `Minho`, `프로 플랜`, 드롭다운 | 계정, 플랜, 사용량 메뉴 표시 |

허브가 바뀌면 task, topic, source, file, run 범위가 해당 허브 기준으로 재조회된다.

### 2.3 중앙 메인 정보 구조

상단에는 제목 `할 일`과 설명 `오늘 해야 할 일과 자동 생성된 할 일을 한눈에 관리하세요.`를 둔다.

상위 탭은 task를 시간, 주제, 생성 방식 기준으로 재분류한다.

| 탭 | 이미지 카운트 | 포함 대상 |
| --- | ---: | --- |
| 오늘 | 8 | 오늘 마감, 오늘로 예약, 사용자가 오늘 보기로 고정한 task |
| 이번 주 | 18 | 이번 주 안에 마감되거나 시작 예정인 task |
| 주제별 | - | topic 단위로 묶은 task. 여행, 투자 리서치, 블로그 아이디어 같은 주제 기준 |
| 자동 생성 | 7 | AI 응답, 파일 요약, 주제 분석, 스크랩 처리 결과에서 생성된 task |

상단 오른쪽에는 `+ 할 일 추가` 버튼과 더보기 버튼을 둔다. `+ 할 일 추가`는 수동 task 생성 플로우를 열고, 더보기는 보기 설정, 완료 항목 숨김, 보관함, 내보내기, 도움말로 확장한다.

필터 줄은 보드 전체에 적용된다.

| 요소 | 이미지 표시 | 기능 |
| --- | --- | --- |
| 우선순위 | `우선순위` 드롭다운 | 높음, 보통, 낮음, 없음, 긴급 플래그 기준 필터 |
| 마감일 | `마감일` 버튼 | 오늘, 내일, 이번 주, 지남, 없음, 사용자 지정 날짜 범위 |
| 전체 선택 | `전체 선택` 버튼 | 현재 view의 visible task 일괄 선택 |
| 정렬 | `정렬` 버튼 | 우선순위순, 마감 임박순, 최근 수정순, 수동 순서, 생성순 |

### 2.4 칸반 보드 정보 구조

첨부 화면 기본 view는 칸반 보드다. 보드 컬럼은 task 상태와 직접 연결된다.

| 컬럼 | 이미지 카운트 | 상태 | 의미 |
| --- | ---: | --- | --- |
| 오늘 | 4 | `today` | 오늘 처리 대상으로 확정된 task |
| 예정 | 3 | `scheduled` | 특정 날짜나 미래 작업으로 잡힌 task |
| 진행 중 | 2 | `in_progress` | 이미 착수했고 진행률을 추적하는 task |
| 완료 | 6 | `done` | 체크 완료된 task. 제목은 취소선으로 표시 가능 |

카드에는 다음 정보가 표시된다.

| 요소 | 표시 방식 | 기능 |
| --- | --- | --- |
| 완료 체크박스 | 카드 좌상단 빈 체크박스 또는 완료 체크 아이콘 | 클릭 시 완료/미완료 상태 변경. 완료 컬럼에서는 초록 체크로 표시 |
| 제목 | 예: `도쿄 항공권 가격 모니터링` | task 상세 패널 열기 |
| 긴급 표시 | 제목 오른쪽 빨간 `!` | `priority=high` 또는 긴급 플래그 |
| 주제 배지 | 예: `도쿄 여행`, `투자 리서치`, `블로그 아이디어`, `주간 리뷰` | 연결 topic 표시 및 topic 필터 진입 |
| 마감 정보 | 예: `오늘 09:00`, `5월 25일 (일)` | deadline 또는 scheduledAt 표시 |
| 진행률 | 진행 중 카드의 `진행률 60%`, progress bar | checklist 완료율 또는 run 연결 진행률 기반 |
| AI 제안 | 예: `항공권 가격 변동 알림 설정` | AI가 제안한 다음 행동 요약 |
| 소스 수 | 예: `소스 2개` | 연결 source/file/conversation 수 |
| 담당자 아바타 | 카드 우하단 사용자 이미지 | owner 또는 assignee |
| 카드 테두리 강조 | 선택 카드 파란 테두리 | 우측 상세 패널의 현재 선택 task |

첨부 화면에 보이는 카드 예시는 다음이다.

| 컬럼 | task 예시 | 주제 | 마감/진행 | AI 제안 |
| --- | --- | --- | --- | --- |
| 오늘 | 도쿄 항공권 가격 모니터링 | 도쿄 여행 | 오늘 09:00 | 항공권 가격 변동 알림 설정 |
| 오늘 | AAPL 실적 발표 요약 확인 | 투자 리서치 | 오늘 10:30 | 실적 요약 후 투자 관점 정리 |
| 오늘 | 블로그 초안 1차 작성 | 블로그 아이디어 | 오늘 14:00 | 개요 기반 초안 작성 후 검토 |
| 오늘 | 주간 리뷰 정리 및 공유 | 주간 리뷰 | 오늘 17:00 | 핵심 인사이트 3가지 정리 |
| 예정 | 도쿄 호텔 후보 리스트업 | 도쿄 여행 | 5월 25일 (일) | 후기 기반 후보 5곳 정리 |
| 예정 | NVDA 리포트 심층 분석 | 투자 리서치 | 6월 26일 (월) | 성장성·리스크 요약 |
| 예정 | 블로그 썸네일 디자인 | 블로그 아이디어 | 5월 27일 (화) | 키워드 기반 3안 제작 |
| 진행 중 | 도쿄 맛집 조사 및 지도 정리 | 도쿄 여행 | 진행률 60% | 구글맵 리스트업 및 평점 정리 |
| 진행 중 | 포트폴리오 리밸런싱 검토 | 투자 리서치 | 진행률 35% | 자산 비중 조정 시뮬레이션 |
| 완료 | 여행 일정 초안 작성 | 도쿄 여행 | 5월 18일 (토) | AI 제안 적용 |
| 완료 | 시장 주요 뉴스 요약 | 투자 리서치 | 5월 19일 (일) | AI 제안 적용 |
| 완료 | 블로그 주제 아이디어 브레인스토밍 | 블로그 아이디어 | 5월 20일 (월) | AI 제안 적용 |

각 컬럼 하단의 `+ 할 일 추가`는 해당 컬럼 상태를 기본값으로 task 생성 모달을 연다.

### 2.5 우측 상세 패널 정보 구조

선택한 task의 상세 패널은 목록을 벗어나지 않고 세부 정보, 연결 자료, AI 실행 전환을 처리하는 영역이다. 첨부 화면에서는 `도쿄 항공권 가격 모니터링`이 선택되어 있다.

| 섹션 | 표시/기능 |
| --- | --- |
| 헤더 | 완료 체크박스, task 제목, 긴급 표시, 닫기 버튼 |
| 메타 줄 | 주제 배지, 날짜/시간, 우선순위 드롭다운 |
| 탭 | `개요`, `연결된 정보`, `활동 기록` |
| AI 제안 | task를 더 잘 처리하기 위한 AI 제안 요약 |
| 체크리스트 | 세부 액션과 완료 수. 예: `0/4` |
| 연결된 대화 | task가 생성되었거나 논의된 conversation message |
| 연결된 파일 | 스프레드시트, PDF 등 관련 파일 |
| 다음으로 추천 | 후속 task 또는 run 후보 |
| 하단 액션 | `AI에게 맡기기`, 더보기 |

상세 패널은 task 선택 시 열리고, 닫기 버튼을 누르면 중앙 보드가 넓어진다. 다른 카드를 클릭하면 같은 패널에서 대상 task만 바뀐다.

## 3. 진입 / 종료 / 전환 동선

### 3.1 진입

| 진입 지점 | 조건 | 랜딩 상태 |
| --- | --- | --- |
| 좌측 내비 `할 일` 클릭 | 기본 진입 | `오늘` 탭, 칸반 view, 최근 선택 task 또는 첫 번째 task 선택 |
| 오늘 화면의 추천/진행 항목 | task 카드 클릭 | 해당 task 선택, 우측 상세 패널 오픈 |
| 채팅에서 “이걸 할 일로 만들어줘” | conversation 기반 task 생성 | 생성된 task가 선택된 상태로 진입 |
| 주제 화면의 작업/후속 액션 | topic scope task 클릭 | 해당 topic 필터 적용, task 상세 오픈 |
| 파일 상세의 후속 작업 | file 기반 task 생성 또는 클릭 | 연결 파일이 표시되는 상세 패널로 진입 |
| 맡긴 일 완료 결과 | run 결과에서 후속 task 생성 | run 연결 정보가 있는 task 상세로 진입 |
| 캘린더 일정 | calendar_event 클릭 | 마감일 또는 scheduledAt이 연결된 task 상세로 진입 |
| 알림 센터 | 마감 임박, 체크리스트 지연, AI 제안 알림 | 관련 task 강조 |

### 3.2 종료

| 종료 동작 | 결과 |
| --- | --- |
| 우측 패널 X 클릭 | 상세 패널 닫힘. 선택 task는 URL/query state에 유지 가능 |
| 다른 좌측 내비 클릭 | 현재 탭, 필터, view, 선택 task 상태 저장 후 이동 |
| topic 배지 클릭 | 주제 화면으로 이동하거나 현재 화면에 topic 필터 적용 |
| 연결 대화 클릭 | 해당 conversation으로 이동하고 task 연결 맥락 강조 |
| 연결 파일 클릭 | 파일 상세 화면으로 이동 |
| `AI에게 맡기기` 실행 성공 | 생성된 run 상세 또는 맡긴 일 화면으로 이동할 수 있는 완료 toast 표시 |

### 3.3 화면 내 전환

| 전환 | 동작 |
| --- | --- |
| 상위 탭 전환 | task 목록 재조회. 필터/정렬은 유지하고 선택 task가 범위 밖이면 첫 항목 선택 |
| 보드 컬럼 이동 | 드래그 앤 드롭 또는 상태 변경 메뉴로 task 상태 변경 |
| 카드 클릭 | 우측 상세 패널 대상 task 변경 |
| 필터 변경 | visible task 재조회, 컬럼 카운트 갱신 |
| 전체 선택 | 현재 필터 결과의 visible task만 선택 |
| 정렬 변경 | 컬럼 안 카드 순서 변경. 수동 순서는 별도 저장 |
| 상세 탭 전환 | 같은 task 안에서 개요, 연결된 정보, 활동 기록 전환 |
| 칸반/목록/맵 전환 | 같은 task 데이터를 view만 바꿔 표시 |

## 4. 핵심 시나리오

### 4.1 오늘 해야 할 일을 정리

1. 사용자가 좌측 내비에서 `할 일`에 진입한다.
2. 기본으로 `오늘` 탭과 칸반 보드가 열린다.
3. 사용자는 `오늘` 컬럼에서 오늘 처리할 task 4개를 확인한다.
4. `우선순위` 필터로 높은 우선순위만 좁힌다.
5. `도쿄 항공권 가격 모니터링` 카드를 클릭해 상세 패널을 연다.
6. 체크리스트와 연결 파일을 보고 직접 처리할지 AI에게 맡길지 결정한다.

### 4.2 자동 생성된 task 검토

1. 사용자가 `자동 생성` 탭을 클릭한다.
2. AI 응답, 파일 요약, 주제 분석에서 만들어진 task 7개가 표시된다.
3. 사용자는 카드의 `AI 제안` 문구와 source 수를 확인한다.
4. 불필요한 task는 거절 또는 보관하고, 필요한 task는 `오늘`이나 `예정`으로 이동한다.
5. 적용/거절/보관 결과는 `ai_suggestion` 상태와 audit log에 남는다.

### 4.3 체크리스트로 task 진행률 관리

1. 사용자가 task 상세의 체크리스트를 확인한다.
2. `항공권 가격 추이 확인`, `가격 알림 설정`, `최적 구매 시점 예측`, `결과를 주제에 저장` 항목을 순서대로 처리한다.
3. 항목을 체크할 때마다 완료 수와 task 진행률이 갱신된다.
4. 진행률이 100%가 되면 task 완료 전환을 제안한다.
5. 사용자가 완료 처리하면 task는 `완료` 컬럼으로 이동하고 완료 시간이 기록된다.

### 4.4 진행 중 task의 상태 갱신

1. 사용자가 `도쿄 맛집 조사 및 지도 정리`를 시작한다.
2. task 상태가 `in_progress`로 바뀌고 `진행 중` 컬럼으로 이동한다.
3. 체크리스트 완료율 또는 연결 run 진행률이 progress bar에 반영된다.
4. source/file이 추가되면 카드의 `소스 N개`와 상세 패널 연결 정보가 갱신된다.
5. 마감 시간이 임박하면 알림과 우선순위 강조를 표시한다.

### 4.5 task를 AI에게 맡기기

1. 사용자가 상세 패널 하단의 `AI에게 맡기기`를 클릭한다.
2. 시스템은 task 제목, 목표, 체크리스트, 연결 주제, 연결 파일, 관련 대화를 run 입력값으로 변환한다.
3. 실행 전 사용할 agent, tool, 비용 상한, 외부 쓰기 권한, 결과 저장 위치를 확인한다.
4. 승인 필요 조건이 없거나 승인이 완료되면 `run`을 생성한다.
5. task에는 `delegatedRunId`가 저장되고 상태는 `in_progress` 또는 `waiting_approval`로 변경된다.
6. run 진행률이 task 카드의 진행률과 상세 패널 활동 기록에 반영된다.

### 4.6 주제 기반으로 할 일 보기

1. 사용자가 `주제별` 탭을 선택한다.
2. `도쿄 여행`, `투자 리서치`, `블로그 아이디어`, `주간 리뷰` 같은 topic 그룹이 표시된다.
3. 사용자는 특정 topic을 펼쳐 관련 task만 확인한다.
4. topic별 완료율, 마감 임박 수, 자동 생성 task 수를 비교한다.
5. topic 상세로 이동하면 같은 task들이 주제 화면의 작업/후속 액션 영역에도 표시된다.

### 4.7 파일과 대화에서 후속 task 생성

1. 사용자가 파일 요약 결과나 채팅 답변에서 “할 일로 추가”를 선택한다.
2. 시스템은 제목, 요약, 추천 마감일, 주제, 체크리스트 초안을 제안한다.
3. 사용자가 생성하면 task가 `자동 생성` 또는 지정한 상태에 추가된다.
4. 원본 conversation message와 file_asset이 task에 연결된다.
5. 상세 패널에서 연결된 대화와 파일을 다시 열 수 있다.

## 5. 컴포넌트별 상세 기능

### 5.1 페이지 헤더

| 요소 | 기능 |
| --- | --- |
| 제목 `할 일` | 현재 화면 목적 표시 |
| 설명 문구 | 오늘 해야 할 일과 자동 생성된 일을 관리한다는 범위 안내 |
| `+ 할 일 추가` | 수동 task 생성 모달 오픈 |
| 더보기 버튼 | 표시 설정, 완료 숨김, 보관함, 내보내기, 삭제된 항목 보기 |

`+ 할 일 추가` 클릭 시 최소 입력은 제목이다. 선택 입력으로 주제, 상태, 우선순위, 마감일, 체크리스트, 연결 파일, 담당자, AI 제안 생성 여부를 받는다.

### 5.2 상위 탭

| 기능 | 상세 |
| --- | --- |
| 카운트 표시 | 탭명 옆 숫자는 해당 탭의 전체 task 수를 표시 |
| 기본 탭 | 기본 진입은 `오늘` |
| 탭 유지 | 화면 이탈 후 복귀 시 마지막 탭 복원 |
| 자동 생성 탭 | AI가 만든 task 중 사용자가 아직 검토하지 않은 항목을 우선 노출 |
| 빈 상태 | 탭 목적에 맞는 안내와 `할 일 추가`, `채팅에서 만들기` CTA 표시 |

### 5.3 필터 / 정렬 / 일괄 선택

| 기능 | 상세 |
| --- | --- |
| 우선순위 필터 | 높음, 보통, 낮음, 없음, 긴급 플래그 다중 선택 |
| 마감일 필터 | 오늘, 내일, 이번 주, 지남, 없음, 날짜 범위 |
| 전체 선택 | 현재 탭과 필터에 보이는 task만 선택 |
| 일괄 액션 | 완료 처리, 상태 변경, 우선순위 변경, 마감일 변경, 보관, 삭제 |
| 정렬 | 우선순위, 마감일, 최근 수정, 생성일, 수동 순서 |

일괄 삭제는 즉시 영구 삭제하지 않고 보관 또는 휴지통 상태를 거친다. 연결된 run이 실행 중이면 삭제 대신 run 중지 여부를 먼저 확인한다.

### 5.4 task 카드

| 기능 | 상세 |
| --- | --- |
| 카드 선택 | 클릭 시 우측 상세 패널 오픈 |
| 완료 체크 | 체크 시 완료 컬럼 이동. 되돌리기 가능 |
| 제목 수정 | 카드 메뉴 또는 상세 패널에서 수정 |
| 상태 이동 | 드래그 앤 드롭, 상세 상태 변경, 일괄 변경 지원 |
| 주제 배지 | topic 연결 표시. 클릭 시 topic 필터 또는 주제 이동 |
| 마감 표시 | 날짜만 있으면 날짜, 시간이 있으면 시간까지 표시 |
| 진행률 표시 | checklist 완료율, 수동 진행률, 연결 run 진행률 중 정책 우선순위로 계산 |
| AI 제안 표시 | 가장 최근의 미처리 또는 적용된 제안 요약 표시 |
| 소스 수 표시 | 연결된 source, file, conversation, run 결과 수 합산 |
| 담당자 표시 | 기본은 현재 사용자. 공유 기능 확장 시 assignee 표시 |

카드에 표시할 정보가 많아도 2줄 이상 과도하게 늘리지 않는다. 상세 정보는 우측 패널에서 확인한다.

### 5.5 컬럼과 드래그 앤 드롭

| 기능 | 상세 |
| --- | --- |
| 컬럼 카운트 | 현재 필터 적용 후 컬럼별 task 수 표시 |
| 컬럼 추가 버튼 | 해당 상태를 기본값으로 task 생성 |
| 드래그 이동 | 상태 변경과 수동 정렬을 동시에 처리 |
| 완료 컬럼 | 완료 task는 체크 아이콘과 취소선으로 완료 상태를 명확히 표시 |
| 권한 제한 | 다른 사용자가 소유한 task는 이동/완료 권한에 따라 비활성화 |

`done`에서 다른 컬럼으로 이동하면 completedAt을 제거하거나 복원 이력으로 남긴다. `in_progress`에서 `done`으로 이동할 때 미완료 체크리스트가 있으면 확인 모달을 표시한다.

### 5.6 상세 패널 헤더

| 요소 | 기능 |
| --- | --- |
| 완료 체크박스 | task 완료/미완료 토글 |
| 제목 | inline 수정 가능 |
| 긴급 표시 | 높은 우선순위 또는 긴급 플래그 표시 |
| 닫기 | 상세 패널 닫기 |
| 주제 배지 | 연결 topic 표시 및 이동 |
| 날짜/시간 | deadline 또는 scheduledAt 수정 |
| 우선순위 드롭다운 | 높음, 보통, 낮음, 없음 선택 |

마감일과 예정일은 구분한다. 마감일은 사용자가 끝내야 하는 시점이고, 예정일은 시작하거나 알림을 받을 시점이다. 화면에는 기본적으로 사용자에게 중요한 날짜 하나를 노출하고, 상세 편집에서 둘 다 조정한다.

### 5.7 상세 탭

| 탭 | 기능 |
| --- | --- |
| 개요 | AI 제안, 체크리스트, 연결 대화, 연결 파일, 다음 추천, 주요 액션 표시 |
| 연결된 정보 | topic, conversation, file, source, run, calendar_event, dependency 전체 목록 표시 |
| 활동 기록 | 생성, 수정, 상태 변경, AI 제안 적용/거절, run 생성, 체크리스트 변경 이력 표시 |

활동 기록은 사용자 액션과 AI/시스템 액션을 구분해서 표시한다. 권한 변경, 외부 쓰기, run 생성은 audit log와 연결한다.

### 5.8 AI 제안

| 기능 | 상세 |
| --- | --- |
| 제안 요약 | task 맥락에서 다음 액션을 한두 문장으로 표시 |
| 제안 상태 | `proposed`, `applied`, `rejected`, `snoozed` |
| 제안 출처 | 어떤 대화, 파일, source, run 결과를 근거로 생성됐는지 표시 |
| 적용 | 체크리스트 추가, 마감일 제안 반영, topic/file 연결, 후속 task 생성 |
| 거절 | 제안 숨김 및 이유 선택 가능 |
| 보류 | 특정 날짜까지 다시 알림 |

첨부 화면의 예시는 `항공권 가격 변동 알림을 설정하고, 최적 구매 시점을 추천해드릴게요.`다. 이 제안은 task 자체를 완료하지 않고, 사용자가 적용하거나 `AI에게 맡기기`를 통해 실행으로 넘길 수 있는 추천이다.

### 5.9 체크리스트

| 기능 | 상세 |
| --- | --- |
| 완료 수 | 예: `0/4` |
| 항목 체크 | 개별 checklist item 완료/미완료 토글 |
| 항목 마감 | 각 항목별 날짜 표시. 첨부 화면은 모두 `오늘` |
| 항목 생성 | 수동 추가 또는 AI 제안 적용으로 생성 |
| 순서 변경 | 드래그로 순서 변경 |
| 진행률 연동 | 완료율이 task progress에 반영 |

체크리스트 항목 예시는 `항공권 가격 추이 확인`, `가격 알림 설정`, `최적 구매 시점 예측`, `결과를 주제에 저장`이다.

### 5.10 연결된 대화

| 기능 | 상세 |
| --- | --- |
| 대화 카드 | task 생성 또는 논의에 사용된 conversation message 표시 |
| 예시 | `항공권 가격 모니터링 설정 도와줘`, `오늘 08:41` |
| 클릭 | 해당 대화로 이동하고 관련 메시지 강조 |
| 연결 추가 | 기존 대화 검색 후 연결 |
| 연결 해제 | task와 대화 관계만 제거. 대화 원문은 삭제하지 않음 |

conversation scope는 global chat, topic chat, run chat 모두 가능하다. task가 topic에 연결되어 있으면 topic chat을 우선 표시한다.

### 5.11 연결된 파일

| 기능 | 상세 |

| 파일 목록 | 아이콘, 파일명, 타입, 최근 수정 시각 표시 |
| 예시 | `도쿄 항공권 가격 추이 (5월)` 구글 스프레드시트, `항공권 가격 알림 설정 가이드` PDF |
| 클릭 | 파일 상세 또는 외부 파일 미리보기로 이동 |
| 연결 추가 | 기존 파일 선택 또는 업로드 |
| 파일 권한 | 접근 불가 파일은 잠금 상태와 권한 요청 CTA 표시 |

연결 파일은 task의 근거 자료이자 AI 실행 입력값이 될 수 있다. `AI에게 맡기기` 전에 접근 권한과 외부 연결 상태를 검사한다.

### 5.12 다음으로 추천

| 기능 | 상세 |
| --- | --- |
| 추천 task | 현재 task 이후에 할 만한 후속 task 표시 |
| 예시 | `항공권 예약 시 체크할 포인트 정리`, `여행 예산 시뮬레이션 만들기` |
| 클릭 | 새 task 생성 또는 기존 task 연결 |
| 추천 근거 | 현재 주제, 마감일, 연결 파일, 완료된 checklist 기반 |
| 숨김 | 사용자가 불필요한 추천을 숨기면 다음 추천 품질에 반영 |

추천은 실행이 아니라 후보 제안이다. 생성 전에는 task 데이터에 반영하지 않는다.

### 5.13 AI에게 맡기기

| 기능 | 상세 |
| --- | --- |
| 기본 동작 | 선택 task를 기반으로 agent run 생성 |
| 입력값 | 제목, 설명, 체크리스트, topic, file, source, conversation, deadline |
| 실행 옵션 | 1회 실행, 반복 실행, 여러 담당에게 나눠 맡기기 |
| 권한 확인 | 외부 API, 파일 쓰기, 캘린더 등록, 비용 증가, 예약 실행은 승인 정책 확인 |
| 결과 | task에 run 연결, 맡긴 일 화면에 run 표시, 상세 패널 활동 기록 갱신 |
| 실패 | run 생성 실패 시 task 상태를 되돌리고 실패 사유 표시 |

하단 더보기 버튼은 `AI에게 맡기기` 외에 `대화로 이어가기`, `주제에 고정`, `캘린더에 추가`, `복제`, `보관`, `삭제` 같은 보조 액션을 제공한다.

## 6. 칸반 / 목록 / 맵 전환

### 6.1 공통 원칙

칸반, 목록, 맵은 서로 다른 데이터 모델이 아니다. 동일한 `task`와 `dependency` 데이터를 view 방식만 다르게 표현한다. 사용자가 한 view에서 수정한 상태, 우선순위, 마감일, 체크리스트, 연결 정보는 다른 view에 즉시 반영된다.

| view | 목적 | 기본 사용 상황 |
| --- | --- | --- |
| 칸반 | 상태별 흐름과 오늘 처리 순서 관리 | 첨부 화면의 기본 view |
| 목록 | 많은 task를 빠르게 검색, 정렬, 일괄 편집 | 주제별/마감일별 정리, 모바일 |
| 맵 | 큰 목표, 세부 task, 의존성, 진행률 관계 파악 | 프로젝트형 할 일, markmap형 브레인스토밍 |

### 6.2 칸반 view

| 기능 | 상세 |
| --- | --- |
| 컬럼 | 오늘, 예정, 진행 중, 완료 |
| 이동 | 드래그 앤 드롭으로 상태 변경 |
| 빠른 추가 | 컬럼 하단 `+ 할 일 추가` |
| 카드 밀도 | 제목, 주제, 마감, AI 제안, 소스 수, 담당자 중심 |
| 선택 | 카드 선택 시 우측 상세 패널 연동 |

### 6.3 목록 view

| 컬럼 | 표시 |
| --- | --- |
| 체크 | 완료 상태 |
| 제목 | task 제목, 긴급 표시 |
| 상태 | today, scheduled, in_progress, done 등 |
| 우선순위 | 높음, 보통, 낮음, 없음 |
| 마감 | deadline/scheduledAt |
| 주제 | topic |
| 진행률 | checklist/run 기반 progress |
| 연결 | 대화, 파일, source, run 개수 |
| 최근 활동 | updatedAt 또는 마지막 activity |

목록 view는 전체 선택, 다중 정렬, 빠른 inline 편집을 우선한다. 보드보다 정보 밀도가 높아야 한다.

### 6.4 맵 view

| 요소 | 기능 |
| --- | --- |
| 루트 노드 | topic 또는 큰 목표 |
| task 노드 | 제목, 상태, 진행률, 마감일, 우선순위 표시 |
| 하위 노드 | checklist 또는 subtask 표시 |
| edge | dependency, parent-child, related 관계 |
| 선택 | 노드 클릭 시 동일한 우측 상세 패널 표시 |
| 필터 | 상태, 우선순위, 마감일, topic 기준으로 노드 숨김/강조 |

맵 view는 PRD의 `할 일 맵` 요구사항과 연결된다. 사용자는 브레인스토밍으로 생성된 할 일을 구조화하고, 선행 task가 끝나야 가능한 후속 task를 의존성으로 관리한다.

## 7. task 상태 / 우선순위 / 마감 / 체크리스트 / AI 제안 / AI에게 맡기기

### 7.1 task 상태

| 상태 | 화면 표시 | 의미 |
| --- | --- | --- |
| `backlog` | 목록/맵에서 보관 또는 대기 | 아직 오늘/예정으로 배치하지 않은 task |
| `today` | 오늘 컬럼 | 오늘 처리 대상으로 선택 |
| `scheduled` | 예정 컬럼 | 특정 미래 날짜에 처리 예정 |
| `in_progress` | 진행 중 컬럼 | 착수했거나 run과 연결되어 진행 중 |
| `blocked` | 막힘 배지 | 사용자 입력, 권한, 선행 task, 외부 연결 때문에 진행 불가 |
| `done` | 완료 컬럼 | 완료 처리 |
| `archived` | 보관함 | 완료와 별개로 목록에서 숨김 |
| `waiting_approval` | 승인 대기 배지 | AI 실행 또는 외부 쓰기 전 사용자 승인 필요 |

첨부 화면의 컬럼은 `today`, `scheduled`, `in_progress`, `done` 4개를 기본으로 보여준다. `backlog`, `blocked`, `waiting_approval`, `archived`는 필터, 배지, 목록 view, 상세 패널에서 보완 표시한다.

### 7.2 우선순위

| 우선순위 | 표시 | 동작 |
| --- | --- | --- |
| 높음 | 빨간 계열 배지, 제목 옆 `!` | 정렬 시 상단, 마감 임박 알림 강화 |
| 보통 | 기본 배지 | 기본 정렬 |
| 낮음 | 회색 배지 | 낮은 노출 |
| 없음 | 표시 생략 가능 | 생성 기본값 |

우선순위는 사용자가 직접 지정하거나 AI가 제안할 수 있다. AI 제안 우선순위는 적용 전까지 실제 priority를 바꾸지 않는다.

### 7.3 마감과 일정

| 필드 | 의미 | 화면 표시 |
| --- | --- | --- |
| `deadlineAt` | 끝내야 하는 시점 | 카드와 상세 헤더의 날짜/시간 |
| `scheduledAt` | 시작하거나 알림 받을 시점 | 예정 컬럼 배치 기준 |
| `remindAt` | 알림 시점 | 알림 센터와 toast |
| `completedAt` | 완료 시점 | 완료 컬럼과 활동 기록 |

마감일이 지난 task는 카드에 지연 상태를 표시하고, 정렬 시 기본적으로 상단으로 올린다. 날짜가 없는 task는 `마감 없음` 필터로 찾을 수 있어야 한다.

### 7.4 체크리스트와 진행률

진행률 계산 우선순위는 다음을 기본값으로 한다.

| 우선순위 | 기준 | 설명 |
| ---: | --- | --- |
| 1 | 연결 run 진행률 | `delegatedRunId`가 있고 run이 진행 중이면 run progress를 우선 |
| 2 | 체크리스트 완료율 | checklist item이 있으면 완료 항목 수 / 전체 항목 수 |
| 3 | 수동 progress | 사용자가 직접 입력한 progress |
| 4 | 상태 기반 | 진행 중은 기본 10%, 완료는 100%, 그 외 0% |

진행률은 카드, 목록, 맵 노드에 동일하게 반영한다.

### 7.5 AI 제안 상태

| 상태 | 의미 | 사용자 액션 |
| --- | --- | --- |
| `proposed` | AI가 제안했지만 사용자가 아직 처리하지 않음 | 적용, 거절, 보류 |
| `applied` | 제안을 task 데이터에 반영함 | 되돌리기 가능 |
| `rejected` | 사용자가 제안을 거절함 | 활동 기록에 남김 |
| `snoozed` | 나중에 다시 보기로 미룸 | 지정 시간에 재노출 |

AI 제안은 task 수정과 분리된 객체로 관리한다. 제안 적용 시 어떤 필드가 바뀌는지 미리 보여주고, 적용 후 활동 기록에 남긴다.

### 7.6 AI에게 맡기기 상태

| 단계 | task/run 변화 |
| --- | --- |
| 실행 준비 | task 입력값, 연결 파일, 권한, 비용 조건 확인 |
| 승인 필요 | task에 `waiting_approval` 배지 표시, approval_request 생성 |
| run 생성 | `delegatedRunId` 저장, task 상태를 `in_progress`로 변경 |
| 실행 중 | run progress를 task progress에 반영 |
| 완료 | run 결과를 task 활동 기록과 연결 파일/문서에 반영. task 완료 전환 제안 |
| 실패 | 실패 사유 표시, 재시도 또는 직접 처리 전환 제공 |

반복 실행이 필요한 경우 task에서 바로 schedule을 만들 수 있다. 이때 task는 원본 실행 항목이고, 반복 실행 이력은 `맡긴 일`과 `캘린더`에 표시된다.

## 8. 주제 / 파일 / 대화 / run 연계

### 8.1 주제 연계

| 기능 | 상세 |
| --- | --- |
| topic 연결 | task는 0개 또는 1개 이상의 topic에 연결 가능 |
| 카드 표시 | 대표 topic 1개를 배지로 표시 |
| 주제별 탭 | topic 기준으로 task 그룹화 |
| 주제 화면 반영 | topic 상세의 작업/후속 액션 영역에 동일 task 노출 |
| topic 변경 | 기존 연결 제거/추가 이력을 활동 기록에 남김 |

대표 topic은 사용자가 지정하거나 생성 출처 기준으로 자동 지정한다. 여러 topic에 연결되면 대표 topic과 추가 개수를 표시한다.

### 8.2 파일/source 연계

| 객체 | 관계 |
| --- | --- |
| `file_asset` | 업로드 파일, 외부 파일, 생성 파일. task 실행 입력값 또는 결과물 |
| `source` | 스크랩/기억 자료. task 근거 또는 리서치 대상 |
| `artifact` | 문서, 표, 지도, markmap 같은 산출물. task 결과로 연결 가능 |

파일 접근 권한이 없거나 외부 연결이 만료되면 상세 패널에서 권한 문제를 먼저 해결하게 한다. AI 실행은 권한 확인 후 시작한다.

### 8.3 대화 연계

| 기능 | 상세 |
| --- | --- |
| 생성 출처 | 채팅에서 task 생성 시 원본 message를 연결 |
| 맥락 참조 | AI 제안과 AI 실행이 연결 대화를 입력 context로 사용 가능 |
| 이동 | 대화 카드 클릭 시 해당 conversation으로 이동 |
| 범위 | global, topic, run, agent test conversation 연결 가능 |

대화 연결은 사용자의 의도와 결정 근거를 복원하기 위한 정보다. task 제목이나 체크리스트만으로 맥락이 부족할 때 상세 패널에서 확인한다.

### 8.4 run/schedule 연계

| 기능 | 상세 |
| --- | --- |
| run 생성 | `AI에게 맡기기`로 task 기반 run 생성 |
| run 진행률 | task 진행률과 활동 기록에 반영 |
| run 결과 | 생성 파일, 문서, 요약, 로그를 task에 연결 |
| schedule 생성 | 반복 모니터링/알림 task는 schedule로 승격 가능 |
| 맡긴 일 이동 | 연결 run 클릭 시 맡긴 일 상세로 이동 |
| 캘린더 이동 | schedule 또는 deadline이 있으면 캘린더에 노출 가능 |

task와 run은 역할이 다르다. task는 사용자가 관리하는 실행 항목이고, run은 AI/agent가 실제 수행한 실행 기록이다.

## 9. Edge Case

| 상황 | 처리 |
| --- | --- |
| task가 없는 첫 진입 | 빈 보드와 `할 일 추가`, `채팅에서 만들기`, `자동 생성 확인` CTA 표시 |
| 오늘 탭에 task가 없음 | 오늘 할 일이 없음을 표시하고 이번 주/자동 생성 탭 추천 |
| 자동 생성 task가 너무 많음 | 유사 task 묶기, 낮은 신뢰도 숨김, 일괄 거절 제공 |
| 같은 대화에서 중복 task 생성 | 제목, source, conversation, topic 유사도로 중복 후보 표시 |
| 마감일이 지난 task | 지연 표시, 오늘로 이동 제안, 알림 발생 |
| 마감일과 예정일이 충돌 | 상세 편집에서 충돌 경고. 마감일 이전 예정일을 추천 |
| 완료하려는데 체크리스트 미완료 | 확인 모달 또는 남은 항목 자동 완료 옵션 |
| 완료 task에 연결 run이 아직 진행 중 | run 중지/분리/계속 실행 중 하나 선택 |
| task 삭제 시 연결 데이터 존재 | task만 삭제할지, 연결만 해제할지, run 중지 여부 확인 |
| 파일 권한 만료 | 상세 패널에 권한 요청 CTA 표시, AI 실행 비활성화 |
| 외부 연결 장애 | `AI에게 맡기기` 전 연결 화면으로 유도 |
| 비용 한도 초과 예상 | 승인 카드 표시 또는 실행 차단 |
| 드래그 중 네트워크 실패 | UI 낙관 업데이트 되돌림, 실패 toast 표시 |
| 여러 사용자가 같은 task 수정 | 최신 변경 충돌 표시, 필드 단위 병합 또는 새로고침 |
| 모바일 좁은 화면 | 우측 상세 패널은 bottom sheet 또는 별도 상세 화면으로 전환 |
| 맵 view에서 순환 의존성 생성 | 저장 전 차단하고 문제가 되는 edge 강조 |
| 필터 결과가 없음 | 필터 초기화 CTA와 현재 적용된 필터 표시 |
| `AI에게 맡기기` 실패 | task 상태 원복, 실패 사유와 재시도 CTA 표시 |
| AI 제안 근거가 삭제됨 | 제안에 근거 없음/만료 표시, 적용 전 재생성 유도 |
| 보관된 task 딥링크 접근 | 읽기 가능하면 보관 상태 표시, 없으면 fallback |

| AI 제안 생성 | `POST /api/tasks/{taskId}/suggestions` | 근거 자료 기반 제안 |
| AI 제안 적용 | `POST /api/tasks/{taskId}/suggestions/{suggestionId}/apply` | proposedPatch 적용 |
| AI 제안 거절 | `POST /api/tasks/{taskId}/suggestions/{suggestionId}/reject` | 사유 optional |
| task 위임 | `POST /api/tasks/{taskId}/delegate` | run 또는 approval_request 생성 |
| task 링크 추가 | `POST /api/tasks/{taskId}/links` | topic/file/conversation/run 연결 |
| task 링크 삭제 | `DELETE /api/tasks/{taskId}/links/{linkId}` | 연결만 해제 |
| 맵 조회 | `GET /api/tasks/map` | nodes, edges, filters 반환 |
| 의존성 변경 | `POST/DELETE /api/tasks/{taskId}/dependencies` | 순환 의존성 검사 필요 |

API 응답은 카드 목록용 경량 필드와 상세 패널용 확장 필드를 분리한다. 보드의 초기 로딩은 카드 표시 필드만 받고, 선택 task 상세는 별도 조회한다.

### 10.3 상태 변경 이벤트

| 이벤트 | 발생 조건 |
| --- | --- |
| `task.created` | 수동 생성, AI 자동 생성, run 결과 생성 |
| `task.updated` | 제목, 설명, 마감, 우선순위, topic 변경 |
| `task.status_changed` | 컬럼 이동, 완료, 보관 |
| `task.checklist_changed` | checklist 추가/수정/완료 |
| `task.suggestion_created` | AI 제안 생성 |
| `task.suggestion_applied` | AI 제안 적용 |
| `task.delegated` | run 생성 또는 approval 요청 |
| `task.linked` | topic/file/conversation/source/run 연결 |
| `task.dependency_changed` | 맵 의존성 생성/삭제 |

이 이벤트는 활동 기록, 알림, audit log, 다른 화면의 카운트 갱신에 사용한다.

## 11. 수용 기준

| 번호 | 기준 |
| --- | --- |
| AC-01 | 좌측 내비에서 `할 일` 진입 시 `오늘` 탭과 칸반 보드가 기본 표시된다. |
| AC-02 | 상위 탭 `오늘`, `이번 주`, `주제별`, `자동 생성`은 각 범위의 task를 필터링하고 카운트를 표시한다. |
| AC-03 | 보드 컬럼 `오늘`, `예정`, `진행 중`, `완료`는 task 상태와 매핑되고 컬럼별 카운트를 표시한다. |
| AC-04 | task 카드는 완료 체크, 제목, 주제 배지, 마감 정보, AI 제안, 소스 수, 담당자, 진행률을 조건에 맞게 표시한다. |
| AC-05 | 카드 클릭 시 우측 상세 패널이 열리고 선택 task의 개요, 체크리스트, 연결 대화, 연결 파일, 다음 추천을 표시한다. |
| AC-06 | 상세 패널의 우선순위, 마감일, 체크리스트 변경은 카드와 목록/맵 view에 즉시 반영된다. |
| AC-07 | task를 컬럼 간 드래그하면 상태가 변경되고 실패 시 이전 위치로 되돌아간다. |
| AC-08 | 완료 처리 시 `done` 상태, completedAt, 활동 기록이 갱신된다. |
| AC-09 | 미완료 체크리스트가 있는 task를 완료하려면 확인 절차를 제공한다. |
| AC-10 | `AI 제안`은 proposed/applied/rejected/snoozed 상태를 가지며 적용 시 변경 내용을 활동 기록에 남긴다. |
| AC-11 | `AI에게 맡기기` 클릭 시 task 기반 run 또는 approval_request가 생성되고 task에 연결된다. |
| AC-12 | 외부 연결, 파일 권한, 비용 한도 문제가 있으면 AI 실행 전 차단하거나 승인 플로우로 전환한다. |
| AC-13 | 연결된 대화와 파일을 클릭하면 해당 conversation/file 상세로 이동할 수 있다. |
| AC-14 | 칸반/목록/맵 view 전환 시 동일 task 데이터가 유지되고 선택 task 상세 패널이 연동된다. |
| AC-15 | 맵 view에서 dependency 순환이 발생하면 저장을 차단한다. |
| AC-16 | 전체 선택은 현재 탭과 필터 결과에 보이는 task에만 적용된다. |
| AC-17 | 자동 생성 task는 사용자가 적용, 거절, 보류, 보관하기 전까지 검토 대상임을 표시한다. |
| AC-18 | task가 없는 상태, 필터 결과 없음, 권한 없음, 네트워크 실패, 삭제/보관 상태에 대한 빈 상태와 오류 처리가 제공된다. |
| AC-19 | 모바일에서는 보드와 상세 패널이 겹치지 않도록 상세를 별도 화면 또는 bottom sheet로 표시한다. |
| AC-20 | task 생성/수정/상태 변경/AI 제안/run 위임/연결 변경은 활동 기록 또는 audit log에 남는다. |

## 12. 자체 리뷰 및 엣지케이스 점검

서브에이전트 읽기 전용 검토를 시도했으나 sandbox의 app-server 초기화 권한 문제로 실패했다. 외부 권한 상승 재시도는 문서 내용 반출 위험이 있어 진행하지 않았고, 대신 자체 리뷰로 누락 여부를 점검했다.

점검 결과는 다음이다.

| 점검 항목 | 결과 |
| --- | --- |
| 첨부 화면의 보이는 기능 추출 | 상위 탭, 필터, 보드 컬럼, 카드 메타, 선택 카드, 상세 패널 탭, AI 제안, 체크리스트, 연결 대화/파일, 다음 추천, `AI에게 맡기기` 반영 |
| PRD 객체 모델 반영 | task, checklist, dependency, conversation, topic, source, file_asset, run, schedule, ai_suggestion, audit_log 반영 |
| 칸반/목록/맵 전환 | 동일 데이터 view 전환 원칙과 각 view 요구사항 반영 |
| 맡긴 일과의 경계 | task는 사용자 실행 항목, run은 AI 실행 기록으로 구분 |
| edge case | 빈 상태, 중복 생성, 권한 만료, 비용 초과, 연결 장애, 드래그 실패, 동시 수정, 순환 의존성 포함 |

## 13. 오픈 질문

| 질문 | 후보/검토 포인트 |
| --- | --- |
| `오늘` 컬럼과 `오늘` 상위 탭의 관계를 어떻게 정의할지 | 상위 탭은 범위 필터, 컬럼은 상태로 유지. 이름 충돌이 UX상 헷갈리면 컬럼명을 `오늘 할 일`로 조정 |
| `scheduled` task가 오늘 날짜가 되면 자동으로 `today`로 이동할지 | 자동 이동, 추천만 표시, 사용자 설정 중 선택 필요 |
| task가 여러 topic에 연결될 때 카드에 무엇을 표시할지 | 대표 topic 1개 + 추가 개수, 또는 주제별 탭에서는 현재 topic 우선 |
| checklist와 subtask를 분리할지 | MVP는 checklist 중심. 맵 view 고도화 시 subtask 별도 모델 검토 |
| AI 제안 적용 시 사용자 확인을 매번 받을지 | 체크리스트/마감 변경은 미리보기 후 적용, 단순 제안 숨김은 즉시 처리 가능 |
| `AI에게 맡기기` 후 task 완료 기준은 무엇인지 | run 완료 시 자동 완료, 사용자 확인 후 완료, checklist 완료 후 완료 중 정책 필요 |
| 반복 모니터링 task는 task인지 schedule인지 | 사용자가 보는 목표는 task, 실제 반복 실행은 schedule/run으로 분리 |
| 완료 컬럼의 보존 기간은 얼마인지 | 최근 30일 표시, 전체는 완료 필터/보관함에서 조회 후보 |
| 알림 정책은 task별로 얼마나 세분화할지 | 마감 임박, 지연, run 완료, AI 제안, 체크리스트 지연을 별도 토글할지 검토 |
| 공유/협업 기능을 MVP에 포함할지 | 첨부 화면은 개인 사용자 중심. assignee는 확장 필드로 두고 MVP 노출 여부 결정 |
| 맵 view를 MVP에 포함할지 | PRD에는 고급 화면으로 있음. MVP는 탭/진입점만 두고 실제 구현은 Phase 후순위 가능 |
| 자동 생성 task의 신뢰도 기준을 노출할지 | 낮은 신뢰도 제안은 자동 생성 탭에서 숨김 또는 검토 필요 배지 표시 |
