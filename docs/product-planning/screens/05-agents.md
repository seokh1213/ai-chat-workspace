# 에이전트 / Agent Registry 화면 상세 기획

## 1. 화면 목적과 사용자 문제

에이전트 화면은 사용자가 반복적으로 쓰는 AI 실행자들을 만들고, 고르고, 테스트하고, 운영 상태를 확인하는 Agent Registry다. 단순 생성 폼이 아니라 `내 에이전트`, `갤러리`, `템플릿`, `실행 기록`을 한 화면에서 오가며 에이전트의 역할, 지침, 모델, 도구, 지식, 권한, 비용, 최근 실행 상태를 관리하는 운영 화면이다.

이 화면이 해결해야 하는 사용자 문제는 다음이다.

| 사용자 문제 | 화면에서의 해결 방식 |
| --- | --- |
| 어떤 에이전트가 이미 있는지 모름 | 카드 목록에서 이름, 역할, 모델, 도구, 권한, 최근 실행, 월 비용을 한 번에 표시 |
| 에이전트가 켜져 있는지, 비용이 얼마나 쓰였는지 불안함 | 카드 활성 토글과 `비용 (이번 달)`을 항상 노출 |
| 도구나 모델 연결이 바뀌면 에이전트가 깨지는지 모름 | 우측 상세 패널에서 연결 도구, 지식, 권한, 모델 상태를 확인하고 변경 |
| 새 에이전트를 처음부터 만들기 어려움 | 갤러리/템플릿에서 복제 후 수정하는 동선 제공 |
| 배포 전 품질을 확인하기 어려움 | 우측 상세 패널의 테스트 채팅에서 실제 응답과 생성 산출물을 확인 |
| 실패 원인과 성능을 추적하기 어려움 | 실행 기록과 분석 탭에서 run 상태, 비용, 지연, 실패 도구를 확인 |

제품 원칙상 에이전트는 `맡긴 일`, `주제`, `기억`, `연결`, `무한캔버스`를 이어주는 실행자다. 이 화면은 개인 워크스페이스 안에서 사용할 수 있는 agent registry이면서, Dify식 builder와 운영 관측을 함께 제공한다.

## 2. 정보 구조와 레이아웃

### 전체 레이아웃

PC 기준 3열 구조다.

| 영역 | 구성 | 목적 |
| --- | --- | --- |
| 좌측 사이드바 | 전역 메뉴, 현재 `에이전트` 활성 표시, 설정/도움말, 사용자 플랜 | 화면 이동과 계정/플랜 상태 확인 |
| 중앙 메인 | 헤더, 생성 버튼, 탭, 검색/필터/정렬, 에이전트 카드 그리드, 페이지네이션 | 에이전트 탐색, 활성화, 선택, 복제/편집 진입 |
| 우측 상세 패널 | 선택 에이전트 요약, 빌더/설정/실행 기록/분석 탭, 테스트 채팅 | 선택 에이전트의 상세 설정과 테스트/운영 확인 |

첨부 화면 기준 중앙 메인에는 `에이전트` 제목, `나만의 AI 에이전트를 만들고 관리하세요.` 보조 문구, `+ 새 에이전트 만들기` 버튼, 더보기 버튼이 있다. 상단 탭은 `내 에이전트`, `갤러리`, `템플릿`, `실행 기록` 순서이며, 현재 `내 에이전트`가 활성 상태다.

### 좌측 사이드바

사이드바는 오늘 화면과 같은 전역 shell을 사용한다. 메뉴 순서는 `오늘`, `주제`, `맡긴 일`, `기억`, `에이전트`, `연결`, `스크랩`, `캘린더`, `할 일`, `파일`이며, 이 화면에서는 `에이전트`가 파란색 활성 상태로 표시된다.

에이전트 화면에서 사이드바 전환 시 입력 중인 에이전트 설정 draft나 테스트 채팅 draft가 있으면 저장 여부를 확인한다. 읽기 권한만 있는 허브에서는 `새 에이전트 만들기`, 토글 변경, 권한 변경을 비활성화한다.

### 중앙 탭 구조

| 탭 | 목적 | 기본 표시 |
| --- | --- | --- |
| 내 에이전트 | 사용자가 만든 개인/허브 소유 에이전트 관리 | 카드 그리드, 검색, 필터, 정렬 |
| 갤러리 | 설치 가능한 추천 에이전트 탐색 | 카테고리, 제작자, 평점/사용량, 미리보기, 설치/복제 |
| 템플릿 | 새 에이전트 생성용 템플릿 선택 | 용도별 템플릿 카드, 복제, 수정 시작 |
| 실행 기록 | 모든 에이전트 run의 통합 기록 | 상태 필터, 기간 필터, 비용/시간, 상세 로그 진입 |

탭 전환은 URL query 또는 route state로 유지한다. 우측 상세 패널은 선택 대상이 유지될 수 있으면 유지하고, 탭 전환으로 대상 타입이 달라지면 닫는다.

### 검색/필터/정렬

첨부 화면에는 검색창 `에이전트 검색...`, 필터 `전체 유형`, `모든 권한`, 정렬 `최근 사용`이 보인다.

| 요소 | 기능 |
| --- | --- |
| 검색창 | 이름, 설명, 역할, 도구명, 지식 태그, 모델명 기준 검색 |
| 전체 유형 | 여행, 투자, 글쓰기, 리서치, 일정, 스크랩, 커스텀 등 agent type 필터 |
| 모든 권한 | 읽기 전용, 읽기+쓰기, 승인 필요, 비활성/차단 필터 |
| 최근 사용 | 최근 실행, 최근 수정, 월 비용 높은 순, 이름순, 성공률순 정렬 |

필터 변경 시 페이지는 1페이지로 돌아간다. 검색어와 필터는 브라우저 뒤로가기와 공유 링크를 위해 URL에 반영한다.

### 에이전트 카드 그리드

첨부 화면은 3열 카드 그리드와 6개 카드, 하단 `6개 중 1-6 표시`, 이전/다음 페이지 버튼을 보여준다. 선택된 `여행 플래너` 카드는 파란색 테두리로 강조되고 우측 상세 패널에 연결된다.

보이는 에이전트 예시는 다음이다.

| 에이전트 | 설명 | 모델 | 권한 | 최근 실행 | 월 비용 |
| --- | --- | --- | --- | --- | --- |
| 여행 플래너 | 여행지 추천부터 일정, 예약, 현지 정보까지 도움 | GPT-4o | 읽기 + 쓰기 | 2분 전 | $0.42 |
| 투자 분석가 | 시장 동향 분석과 투자 리포트 제공 | Claude 3.5 Sonnet | 읽기 전용 | 15분 전 | $1.28 |
| 스크랩 정리자 | 스크랩한 글과 자료를 분류하고 요약 | GPT-4o mini | 읽기 + 쓰기 | 1시간 전 | $0.18 |
| 글쓰기 코치 | 초안 작성과 피드백, 문장 교정 지원 | GPT-4o | 읽기 + 쓰기 | 3시간 전 | $0.31 |
| 리서처 검증자 | 사실 확인과 출처 검증 전문 | Claude 3.5 Sonnet | 읽기 전용 | 어제 | $0.27 |
| 일정 비서 | 일정 조율과 알림, 회의 준비 자동화 | GPT-4o mini | 읽기 + 쓰기 | 어제 | $0.16 |

카드 내 도구 아이콘은 최대 4개까지 직접 표시하고, 초과분은 `+1`, `+2` 배지로 접는다. 아이콘은 tooltip으로 도구명과 연결 상태를 보여준다.

## 3. 진입/종료/전환 동선

### 진입

| 진입 경로 | 처리 |
| --- | --- |
| 사이드바 `에이전트` 클릭 | `내 에이전트` 탭으로 진입, 최근 필터 상태 복원 |
| 오늘/주제/맡긴 일에서 담당 agent 클릭 | 에이전트 화면으로 이동하고 해당 agent 상세 패널 열기 |
| 연결 화면에서 영향받는 agent 클릭 | 해당 agent 선택, 연결/도구 상태를 상세 패널에서 강조 |
| 템플릿 설치 완료 후 이동 | 새로 복제된 agent를 선택하고 설정 탭 또는 빌더 탭 열기 |
| 실행 기록 알림 클릭 | `실행 기록` 탭으로 진입하고 해당 run을 강조 |
| 무한캔버스 저장 후 복귀 | 저장된 agent를 선택하고 빌더 탭에 최신 draft/deployed 상태 표시 |

### 종료

| 종료 동작 | 처리 |
| --- | --- |
| 사이드바 다른 메뉴 클릭 | 변경 사항이 있으면 저장/폐기 확인 후 이동 |
| 우측 패널 닫기 | 중앙 목록 선택 해제, URL의 selectedAgentId 제거 |
| 카드 더보기에서 삭제/보관 | 확인 후 목록에서 제거하거나 archived 필터로 이동 |
| 실행 기록 상세에서 산출물 열기 | 파일/작업면/주제/맡긴 일 상세로 이동 |
| 새 에이전트 만들기 완료 | 목록 첫 위치에 agent 추가, 상세 패널 열기 |

### 화면 내 전환

에이전트 카드를 클릭하면 우측 상세 패널이 열린다. 카드의 활성 토글과 더보기 메뉴는 카드 선택과 이벤트가 충돌하지 않아야 한다.

`+ 새 에이전트 만들기`는 생성 플로우를 시작한다. MVP에서는 템플릿 선택 모달 또는 기본 정보 입력 모달을 열고, 고급 편집은 `무한캔버스에서 편집`으로 전환한다. 생성 완료 후에는 `내 에이전트` 탭으로 돌아와 신규 카드와 상세 패널을 표시한다.

`갤러리`와 `템플릿`에서 `복제`를 누르면 새 agent draft가 생성된다. 사용자가 이름, 모델, 도구 권한을 확정하기 전까지는 비활성 상태로 둔다.

`실행 기록` 탭에서 run을 선택하면 우측 패널은 agent 요약 대신 run 상세 모드로 전환할 수 있다. 단, 화면 제목과 breadcrumb에서 agent context를 잃지 않게 한다.

## 4. 핵심 시나리오와 happy path

### 시나리오 A. 기존 에이전트 상태 확인 후 테스트

1. 사용자가 사이드바에서 `에이전트`를 클릭한다.
2. `내 에이전트` 탭에서 `여행 플래너` 카드를 확인한다.
3. 카드에서 활성 토글, 모델, 권한, 최근 실행, 월 비용을 빠르게 확인한다.
4. 카드를 클릭해 우측 상세 패널을 연다.
5. `빌더` 탭에서 역할, 지침, 도구, 지식, 권한을 확인한다.
6. 테스트 채팅에 `3박 4일 도쿄 여행 일정 추천해줘`를 입력한다.
7. 시스템은 agent test chat scope로 응답을 생성하고 PDF 같은 테스트 산출물을 표시한다.
8. 사용자는 응답 품질과 산출물을 확인하고 설정 변경 또는 실제 실행으로 이어간다.

### 시나리오 B. 템플릿에서 새 에이전트 생성

1. 사용자가 `템플릿` 탭을 연다.
2. 용도별 템플릿에서 `여행 플래너` 또는 `리서처 검증자`를 선택한다.
3. 미리보기에서 역할, 기본 지침, 필요한 도구, 권한, 예상 비용을 확인한다.
4. `복제해서 만들기`를 누른다.
5. 시스템은 agent draft를 생성하고 이름/모델/도구/권한 확인을 요구한다.
6. 필수 연결이 없으면 연결 화면 또는 연결 모달로 안내한다.
7. 테스트 채팅을 통과하면 사용자가 활성화한다.
8. 새 에이전트가 `내 에이전트` 목록에 표시된다.

### 시나리오 C. 갤러리 에이전트 설치

1. 사용자가 `갤러리` 탭에서 추천 에이전트를 검색한다.
2. 카테고리, 제작자, 필요 연결, 권한 범위, 비용 예상을 확인한다.
3. 설치 또는 복제를 선택한다.
4. 외부 쓰기 도구나 민감 권한이 있으면 승인 카드를 표시한다.
5. 설치 후 개인 허브 소유 agent copy를 만든다.
6. 기본 비활성 상태로 두고, 사용자가 권한과 모델을 확인한 뒤 활성화한다.

### 시나리오 D. 실행 실패 원인 확인

1. 사용자가 `실행 기록` 탭을 연다.
2. 실패 상태 run을 선택한다.
3. 우측 상세에서 실패 단계, 실패 도구, provider 오류, 비용 사용량, 재시도 가능 여부를 확인한다.
4. 연결 만료가 원인이면 `연결` 화면으로 이동한다.
5. 모델 응답 실패가 원인이면 설정 탭에서 모델 fallback 또는 재시도를 선택한다.
6. 재시도 성공 시 run 상태와 분석 지표가 갱신된다.

### 시나리오 E. 활성 에이전트 비용 제한 처리

1. 사용자가 카드의 활성 토글을 켠다.
2. 시스템은 agent의 예상 월 비용, 연결된 schedule, 모델 단가, 도구 권한을 확인한다.
3. 한도 이내면 활성화하고 audit log를 남긴다.
4. 한도 초과 가능성이 있으면 예상 비용과 축소 옵션을 표시한다.
5. 사용자가 모델 변경, schedule 비활성화, 비용 한도 상향 중 하나를 선택해야 활성화된다.

### 시나리오 F. 무한캔버스로 고급 편집

1. 사용자가 상세 패널에서 `무한캔버스에서 편집`을 선택한다.
2. agent builder canvas로 이동한다.
3. LLM, tool call, 조건 분기, 승인 요청, 스케줄 노드를 편집한다.
4. 저장 시 agent draft version이 생성된다.
5. 테스트 통과 후 배포하면 registry 카드의 모델/도구/권한/최근 수정 정보가 갱신된다.

## 5. 컴포넌트별 상세 기능

### 화면 헤더

| 요소 | 기능 |
| --- | --- |
| 제목 `에이전트` | 현재 화면 식별 |
| 보조 문구 | 화면 목적 안내 |
| `+ 새 에이전트 만들기` | 신규 agent 생성 플로우 시작 |
| 더보기 버튼 | 가져오기, 내보내기, 전체 비활성화, 문서 보기 같은 화면 단위 액션 |

`새 에이전트 만들기`는 쓰기 권한이 없거나 플랜 한도를 초과하면 비활성화하고 이유를 tooltip/toast로 안내한다.

### 탭 내비게이션

탭은 같은 화면 안에서 registry 탐색 모드를 바꾸는 장치다. 현재 탭은 파란색 텍스트와 하단 underline으로 표시한다. 탭별 badge가 필요하면 `실행 기록`에 실패/승인 대기 건수를 표시할 수 있다.

### 검색창

검색창은 입력 즉시 debounce 검색한다. 엔터 입력 시 서버 검색을 확정하고 URL query를 갱신한다. 검색 결과가 없으면 빈 상태에서 `템플릿에서 만들기`, `갤러리에서 찾기` CTA를 제공한다.

### 필터/정렬 드롭다운

| 드롭다운 | 옵션 예시 | 비고 |
| --- | --- | --- |
| 전체 유형 | 전체, 여행, 투자, 스크랩, 글쓰기, 리서치, 일정, 커스텀 | agent.type 기준 |
| 모든 권한 | 전체, 읽기 전용, 읽기+쓰기, 승인 필요, 차단됨 | effectivePermission 기준 |
| 최근 사용 | 최근 사용, 최근 수정, 이름순, 비용 높은 순, 성공률 높은 순 | 실행 기록 없는 agent는 하단 배치 |

권한 필터는 agent 자체 권한과 연결/허브 정책이 합쳐진 effective permission 기준으로 동작한다.

### Agent 카드

카드는 에이전트 운영 상태를 빠르게 판단하는 단위다.

| 필드 | 표시/동작 |
| --- | --- |
| 아이콘 | agent.icon 또는 타입별 기본 아이콘 |
| 이름 | 1줄 우선, 길면 2줄 말줄임 |
| 설명 | 역할/용도 요약, 2줄 말줄임 |
| 활성 토글 | agent 활성/비활성 전환 |
| 모델 | 현재 기본 모델명 표시 |
| 도구 | 연결된 tool 아이콘 최대 4개와 추가 개수 배지 |
| 권한 | 읽기 전용, 읽기 + 쓰기, 승인 필요 등 |
| 최근 실행 | relative time, 실행 기록 없으면 `실행 없음` |
| 비용 (이번 달) | 실제 비용, 집계 중이면 skeleton 또는 `계산 중` |
| 더보기 | 편집, 복제, 실행 기록 보기, 보관, 삭제 |

카드 선택은 우측 상세 패널을 여는 동작이다. 활성 토글 변경은 즉시 저장을 시도하되, 승인/비용/연결 문제가 있으면 토글을 확정하지 않고 확인 플로우를 먼저 띄운다.

### 활성 토글

| 상황 | 처리 |
| --- | --- |
| 비활성에서 활성으로 전환 | 필수 모델/도구/지식/권한/비용 한도 확인 후 활성화 |
| 활성에서 비활성으로 전환 | 연결된 schedule, 진행 중 run, 주제 자동화 영향 범위 표시 |
| 진행 중 run 있음 | 새 run 생성을 막되 기존 run 중지 여부는 별도 확인 |
| schedule 연결됨 | schedule도 함께 멈출지, agent만 비활성화할지 선택 |
| 권한 승인 필요 | 승인 카드 완료 전까지 토글은 pending 상태 |
| 서버 저장 실패 | 이전 상태로 rollback하고 오류 표시 |

토글 변경은 `audit_log`에 actor, 이전 상태, 변경 상태, 영향받은 schedule/run 수, 사유를 남긴다.

### 카드 더보기 메뉴

| 액션 | 기능 |
| --- | --- |
| 편집 | 상세 패널 설정 탭 또는 무한캔버스로 이동 |
| 복제 | 같은 설정의 draft agent 생성 |
| 실행 기록 보기 | `실행 기록` 탭으로 전환하고 agentId 필터 적용 |
| 템플릿으로 저장 | 개인 템플릿 생성 |
| 보관 | 목록에서 숨기고 archived 상태로 변경 |
| 삭제 | 실행 기록/산출물 보존 정책 확인 후 삭제 |

삭제는 hard delete보다 archived를 기본값으로 한다. 실제 삭제가 필요하면 실행 기록, schedule, topic 연결 해제 정책을 확인해야 한다.

### 우측 상세 패널 공통

첨부 화면 기준 우측 패널은 선택된 `여행 플래너`의 아이콘, 이름, `활성` 배지, 닫기 버튼을 표시한다. 탭은 `빌더`, `설정`, `실행 기록`, `분석` 순서다.

| 요소 | 기능 |
| --- | --- |
| 아이콘/이름 | 선택 agent 식별 |
| 상태 배지 | 활성, 비활성, 승인 대기, 오류, 초안 표시 |
| 닫기 버튼 | 패널 닫기와 선택 해제 |
| 탭 | 상세 정보, 설정, run history, analytics 전환 |
| 변경 감지 | 저장되지 않은 설정이 있으면 탭/닫기/이동 전 확인 |

패널은 중앙 목록과 독립적으로 스크롤된다. 모바일에서는 bottom sheet 또는 전체 화면 상세로 전환한다.

### 빌더 탭

첨부 화면의 `빌더` 탭은 역할, 지침, 도구, 지식, 권한, 테스트 채팅을 보여준다.

| 섹션 | 표시 필드 | 기능 |
| --- | --- | --- |
| 역할 | 예: 여행 전문가 | agent의 핵심 persona/role 확인 |
| 지침 | 예: 취향/예산 고려, 일정 예약, 현지 정보 제공 | system prompt 요약 또는 전문 보기 |
| 도구 | 웹/항공/숙소/지도/기타 도구 아이콘 | 연결 상태와 tool permission 확인 |
| 지식 | 여행 가이드, 항공/호텔 정보, 비자/입국 정보 등 chip | 연결된 source/topic/file 확인 |
| 권한 | 읽기 + 쓰기, 변경 버튼 | effective permission 확인/변경 |
| 테스트 채팅 | prompt, 응답, 산출물, 초기화, 전송 | 배포 전 품질 테스트 |

빌더 탭은 빠른 확인용이다. 복잡한 노드/분기/스키마 편집은 무한캔버스에서 처리한다.

### 설정 탭

설정 탭은 agent 동작을 실제로 변경하는 영역이다.

| 그룹 | 필드 |
| --- | --- |
| 기본 정보 | 이름, 설명, 아이콘, 유형, 공개 범위, 소유 허브 |
| 지침 | system prompt, 말투, 금지사항, 응답 형식, citation 요구 여부 |
| 모델 | provider, model, reasoning level, temperature, max tokens, fallback model |
| 도구 | MCP tool, scraper, search, map, stock, calendar, filesystem 등 |
| 지식 | 연결할 기억, 스크랩, 파일, 주제, 문서 |
| 실행 방식 | 단발 실행, 주제 전용, 반복 실행 가능, 여러 담당 참여 가능 |
| 권한 | 읽기 전용, 쓰기 가능, 승인 필요, 차단 규칙 |
| 비용 | 월 한도, 단일 run 한도, 고비용 모델 승인 여부 |
| 배포 | draft 저장, 테스트, 배포, 이전 버전 복원 |

설정 변경은 draft로 저장한 뒤 테스트/배포할 수 있어야 한다. 이미 활성화된 agent의 모델, 도구, 권한을 바꾸면 기존 schedule과 topic 자동화에 미치는 영향을 표시한다.

### 테스트 채팅

첨부 화면의 테스트 채팅에는 초기화 버튼, 사용자 메시지, 시간, 에이전트 응답, PDF 산출물 카드, 다운로드 버튼, 입력창, 전송 버튼, `에이전트가 답변을 생성할 수 있습니다.` 안내가 있다.

| 요소 | 기능 |
| --- | --- |
| 초기화 | 테스트 대화 context와 임시 산출물 초기화 |
| 사용자 메시지 | test conversation message 표시 |
| 에이전트 응답 | 현재 agent 설정으로 생성된 응답 표시 |
| 산출물 카드 | PDF, 문서, 표, 일정, 지도, todo 등 artifact preview |
| 다운로드 | 생성 파일 다운로드 또는 파일 화면 진입 |
| 입력창 | agent test chat scope로 메시지 전송 |
| 전송 버튼 | 빈 입력/실행 중 중복 전송 방지 |

테스트 채팅은 실제 run과 분리된 `agent_test_run`으로 기록한다. 비용은 실제 비용 집계에 포함하되, 실행 기록에서는 테스트 배지로 구분한다. 테스트 중 외부 쓰기 도구는 기본 차단하거나 mock mode로 동작한다.

### 실행 기록 탭

실행 기록 탭은 agent별 run history를 보여준다. 중앙 상단 `실행 기록` 탭은 전체 registry 기록이고, 우측 상세의 `실행 기록` 탭은 선택 agent의 기록이다.

| 필드 | 설명 |
| --- | --- |
| runId | 실행 식별자 |
| status | queued, running, waiting_approval, paused, succeeded, failed, stopped, retrying |
| triggerType | manual, chat, schedule, topic, test, canvas_test |
| startedAt/endedAt | 실행 시작/종료 시각 |
| duration | 소요 시간 |
| model | 실제 사용 모델 |
| toolsUsed | 호출한 도구 목록과 성공/실패 |
| cost | token/cost 집계 |
| topic/source/artifact | 연결된 주제, 자료, 산출물 |
| errorSummary | 실패 시 원인 요약 |

실행 기록에서 `재시도`, `로그 보기`, `산출물 열기`, `비용 상세`, `같은 설정으로 다시 실행` 액션을 제공한다. 실패 run은 어떤 도구/모델/권한/연결 때문에 실패했는지 한 줄로 보여줘야 한다.

### 분석 탭

분석 탭은 agent 운영 성능과 비용을 보는 영역이다.

| 지표 | 설명 |
| --- | --- |
| 성공률 | 기간 내 succeeded / total run |
| 평균 지연 | 평균 응답 시간 또는 run duration |
| 월 비용 | 이번 달 실제 비용과 한도 대비 비율 |
| 토큰 사용량 | input/output/reasoning token |
| 실패 상위 도구 | 자주 실패한 tool과 원인 |
| 모델별 비용 | provider/model별 비용 분해 |
| 활성 schedule 수 | 이 agent가 담당하는 반복 작업 수 |
| 사용자 만족 | thumbs up/down 또는 재실행 비율 |

분석은 기본 최근 30일 기준이다. 기간 필터를 제공하고, 데이터가 적으면 `분석할 실행 기록이 부족합니다.` 빈 상태를 표시한다.

### 갤러리 탭

갤러리는 플랫폼 또는 커뮤니티/팀에서 제공하는 설치 가능한 에이전트를 보여준다.

| 필드 | 설명 |
| --- | --- |
| 이름/아이콘/설명 | 에이전트 용도 |
| 제작자 | 플랫폼, 팀, 개인 |
| 카테고리 | 여행, 투자, 글쓰기, 개발, 일정 등 |
| 필요 연결 | OpenRouter, 지도, 캘린더, 검색, 파일 등 |
| 권한 범위 | 읽기 전용, 쓰기 가능, 승인 필요 |
| 예상 비용 | 평균 run 비용 또는 월 예상 |
| 설치 상태 | 설치됨, 업데이트 가능, 미설치 |
| CTA | 미리보기, 설치, 복제 |

갤러리 설치는 원본을 직접 수정하지 않고 사용자 허브에 copy를 만든다. 업데이트가 있는 경우 원본 변경 사항과 사용자 수정 사항의 충돌을 보여준다.

### 템플릿 탭

템플릿은 agent 생성 시간을 줄이는 시작점이다. 템플릿은 실행 가능한 agent가 아니라 draft 생성용 blueprint다.

| 템플릿 유형 | 예시 |
| --- | --- |
| 여행 | 여행 플래너, 일정 비서 |
| 리서치 | 투자 분석가, 리서처 검증자 |
| 글쓰기 | 글쓰기 코치, 블로그 초안 작성자 |
| 자료 정리 | 스크랩 정리자, 파일 요약자 |
| 자동화 | 캘린더 비서, 주간 리뷰 알림 |

템플릿 선택 시 필요한 모델, 도구, 권한, 지식 연결 후보, 예상 비용을 보여준다. 복제 후에는 이름, 도구 연결, 권한 승인, 테스트 완료 전까지 비활성 draft 상태를 유지한다.

## 6. 상태/빈 상태/로딩/에러/권한/비용 edge case

### 공통 상태

| 상태 | 처리 |
| --- | --- |
| 초기 로딩 | 중앙 카드 skeleton과 우측 패널 skeleton 표시 |
| 부분 로딩 | 목록, 비용 집계, 실행 기록, 분석 데이터를 독립 로딩 |
| 새로고침 중 | 기존 카드 유지, 상단 또는 카드에 갱신 indicator 표시 |
| 오프라인 | 토글/설정 저장/테스트 전송 비활성, 캐시된 목록 표시 |
| 권한 제한 | 쓰기 액션 비활성, 읽기 가능한 정보만 표시 |

### 빈 상태

| 영역 | 처리 |
| --- | --- |
| 내 에이전트 없음 | `아직 만든 에이전트가 없습니다.`와 `템플릿에서 만들기`, `갤러리 둘러보기` CTA |
| 검색 결과 없음 | 필터 초기화, 템플릿 추천 |
| 갤러리 없음 | 연결/네트워크 오류와 구분해서 빈 상태 표시 |
| 템플릿 없음 | 기본 커스텀 생성 CTA 제공 |
| 실행 기록 없음 | `아직 실행 기록이 없습니다.`와 테스트 채팅 CTA |
| 분석 데이터 부족 | 최소 run 수 또는 기간 안내 |

### 에러 상태

| 에러 | 처리 |
| --- | --- |
| 목록 조회 실패 | 재시도 버튼과 마지막 캐시 시각 표시 |
| 비용 조회 실패 | 비용 영역만 `계산 실패`로 표시하고 목록은 유지 |
| 토글 저장 실패 | 이전 상태로 rollback, toast 표시 |
| 테스트 응답 실패 | 테스트 메시지를 failed 상태로 남기고 재시도 제공 |
| 산출물 다운로드 실패 | artifact 카드 유지, 재다운로드 제공 |
| 설정 저장 실패 | draft 보존, 실패 필드 강조 |
| 실행 기록 조회 실패 | 선택 agent 정보는 유지하고 기록 영역만 재시도 |
| 분석 조회 실패 | 지표 영역별 skeleton 또는 오류 표시 |

### 활성 상태 edge case

| 상황 | 처리 |
| --- | --- |
| 필수 연결 만료 | 카드에 오류 배지, 토글 on 차단, 연결 화면 CTA |
| 모델 provider 비활성 | fallback 모델 제안 또는 비활성 전환 확인 |
| 도구 일부만 실패 | agent 전체 차단 여부를 권한 정책 기준으로 결정 |
| 지식 소스 삭제 | 누락된 지식 chip을 오류 상태로 표시하고 재연결 요구 |
| 진행 중 run 중 비활성화 | 새 run만 차단할지, 진행 중 run도 중지할지 확인 |
| schedule 연결 agent 비활성화 | 영향받는 schedule 목록과 다음 실행 취소 여부 표시 |
| 팀 정책 변경 | effective permission 재계산, 카드/상세 권한 즉시 갱신 |

### 비용 edge case

| 상황 | 처리 |
| --- | --- |
| 월 한도 초과 | agent 활성화와 새 run 생성 차단 |
| 단일 run 예상 비용 초과 | 실행 전 승인 카드 표시 |
| 테스트 채팅 반복으로 비용 증가 | 테스트 비용도 월 비용에 포함하고 임계값 경고 |
| 갤러리 에이전트 설치 후 고비용 모델 사용 | 설치 전 예상 비용과 대체 모델 제안 |
| schedule 누적 비용 초과 | schedule 활성화 차단 또는 실행 주기 축소 제안 |
| 비용 집계 지연 | `집계 중` 상태와 마지막 업데이트 시각 표시 |
| provider 단가 변경 | 다음 실행부터 적용됨을 알리고 예상 비용 재계산 |

### 권한/승인 edge case

| 상황 | 처리 |
| --- | --- |
| 읽기 전용 허브 | 생성/편집/삭제/토글 비활성 |
| 외부 쓰기 도구 포함 | 승인 필요 배지와 실행 전 approval_request 생성 |
| 파일 삭제/캘린더 수정 도구 | agent 권한과 connection 권한을 모두 확인 |
| 갤러리 설치 권한 부족 | 설치 CTA 비활성, 관리자 요청 CTA 표시 |
| 템플릿 복제 후 도구 권한 없음 | 도구를 비활성 chip으로 표시하고 연결/승인 유도 |
| 테스트에서 쓰기 도구 호출 | mock mode 또는 승인 필요 상태로 전환 |

### 자체 edge case 리뷰

nested subagent 리뷰는 실행 오류로 완료하지 못했으므로 자체 리뷰 기준을 문서에 반영한다.

| 리뷰 포인트 | 확인 내용 |
| --- | --- |
| 카드 토글과 카드 선택 이벤트 충돌 | 토글/더보기 클릭이 상세 패널 선택으로 전파되지 않아야 함 |
| 카드의 월 비용과 분석 탭 비용 불일치 | 같은 집계 기준인지, 지연 집계 상태를 표시하는지 확인 |
| `내 에이전트`와 `실행 기록` 탭의 필터 동기화 | agentId 필터가 탭 전환 후 의도대로 유지/해제되는지 확인 |
| 갤러리 원본과 복제본 구분 | 원본 업데이트와 사용자 수정이 섞이지 않아야 함 |
| 템플릿 draft 활성화 조건 | 모델, 도구, 권한, 테스트 통과 전 활성화 차단 필요 |
| 연결 해제 영향 범위 | 연결 화면에서 agent/schedule/run 영향 목록과 같은 기준 사용 필요 |
| 무한캔버스 draft와 registry 배포본 | draft 저장만으로 활성 agent가 바뀌지 않도록 version 상태 분리 필요 |
| 테스트 채팅 산출물 | 테스트 산출물이 실제 파일/기억/주제에 자동 저장되지 않도록 범위 명확화 필요 |
| 권한명 표시 | agent 자체 권한이 아니라 effective permission을 사용자에게 표시해야 함 |
| 시간/비용 timezone/currency | 상대 시간은 사용자 timezone, 비용은 워크스페이스 currency 기준 필요 |

## 7. 다른 화면과의 연계

| 대상 화면 | 연계 방식 |
| --- | --- |
| 오늘 | 빠른 의도/도구 선택에서 agent 실행, 실행 중 상태는 오늘 우측 패널에 표시 |
| 주제 | 주제 전용 agent 연결, topic chat에서 agent 호출, agent run 결과를 surface에 반영 |
| 맡긴 일 | agent 실행은 run으로 생성되고, 장시간/다중 담당/예약 실행은 맡긴 일에서 관리 |
| 기억 | agent 지식으로 memory/source/preference/decision을 연결 |
| 연결 | 모델 provider, MCP server, 외부 API, OAuth, credential 상태를 참조 |
| 스크랩 | 스크랩 정리자 같은 agent가 source 요약/분류를 수행 |
| 캘린더 | 일정 비서 agent가 calendar_event와 schedule을 생성/수정 |
| 할 일 | agent가 task 생성, 체크리스트 생성, 진행 상황 업데이트 가능 |
| 파일 | 테스트/실행 산출물 다운로드, 파일 요약/첨부 도구와 연결 |
| 설정 | 전역 비용 한도, 기본 모델, 승인 정책, Dev Mode 토큰 정책 참조 |
| 무한캔버스 | 고급 agent builder에서 노드/엣지/스키마/분기 편집 후 registry로 배포 |

### 연결/모델/도구 연계

agent의 실행 가능 여부는 agent 설정만이 아니라 연결 상태와 권한 정책으로 결정된다.

| 연계 대상 | 확인 기준 |
| --- | --- |
| model provider | credential 상태, 사용 가능 모델, 비용 단가, fallback 모델 |
| MCP/tool | 서버 health, tool schema, read/write scope, 승인 필요 여부 |
| external API | OAuth 만료, rate limit, 계정 권한 |
| knowledge source | source 존재 여부, 접근 권한, 최신 요약 상태 |
| scheduler | agent 활성 상태, 비용 한도, 반복 실행 권한 |
| canvas version | draft/deployed version, 테스트 통과 여부 |

## 9. 수용 기준

### 레이아웃/표시

- 좌측 사이드바에서 `에이전트` 메뉴가 활성 상태로 표시된다.
- 중앙 상단에 `에이전트` 제목, 보조 문구, `+ 새 에이전트 만들기`, 더보기 버튼이 표시된다.
- 탭은 `내 에이전트`, `갤러리`, `템플릿`, `실행 기록` 순서로 표시된다.
- `내 에이전트` 탭에는 검색창, 유형 필터, 권한 필터, 정렬 드롭다운이 표시된다.
- 에이전트 카드는 아이콘, 이름, 설명, 활성 토글, 모델, 도구, 권한, 최근 실행, 이번 달 비용, 더보기 메뉴를 표시한다.
- 선택된 카드는 파란색 테두리로 강조되고 우측 상세 패널이 열린다.
- 하단에는 전체 개수, 현재 표시 범위, 페이지 이동 버튼이 표시된다.
- 우측 상세 패널은 agent 이름, 상태 배지, 닫기 버튼, `빌더/설정/실행 기록/분석` 탭을 표시한다.
- 빌더 탭은 역할, 지침, 도구, 지식, 권한, 테스트 채팅을 표시한다.
- 테스트 채팅은 초기화, 메시지, 응답, 산출물 카드, 다운로드, 입력창, 전송 버튼을 제공한다.

### 동작

- 카드 클릭 시 해당 agent 상세 패널이 열린다.
- 카드 활성 토글 클릭은 카드 선택 이벤트와 충돌하지 않는다.
- 활성화 전 필수 연결, 모델, 도구, 권한, 비용 한도를 검증한다.
- 비활성화 전 연결된 schedule과 진행 중 run 영향 범위를 보여준다.
- 검색/필터/정렬 변경 시 목록이 갱신되고 페이지는 1페이지로 초기화된다.
- `새 에이전트 만들기`는 신규 agent draft 생성 플로우를 연다.
- 갤러리 설치와 템플릿 복제는 원본이 아닌 사용자 허브의 copy/draft를 만든다.
- 테스트 채팅은 실제 run과 구분되는 test run으로 저장된다.
- 실행 기록에서 run 상세, 재시도, 산출물 열기가 가능하다.
- 분석 탭은 기간 기준 성공률, 지연, 비용, 실패 도구를 표시한다.

### 상태/권한/비용

- 목록, 비용, 실행 기록, 분석은 독립적으로 로딩/에러/빈 상태를 표시한다.
- 쓰기 권한이 없는 허브에서는 생성, 편집, 삭제, 토글 변경을 비활성화한다.
- 연결 만료나 provider 비활성화가 있으면 agent 카드와 상세 패널에 오류 상태를 표시한다.
- 월 비용 한도를 초과하면 agent 활성화와 새 run 생성을 차단한다.
- 테스트 채팅 비용도 비용 집계와 경고 기준에 포함한다.
- 외부 쓰기 도구는 실행 전 승인 카드 또는 mock mode를 거친다.
- schedule이 연결된 agent의 상태 변경은 schedule 영향 범위를 명확히 보여준다.

### 접근성/반응형

- 모든 아이콘 버튼과 도구 아이콘은 접근 가능한 label 또는 tooltip을 가진다.
- 키보드로 탭, 검색, 필터, 카드, 토글, 상세 패널, 테스트 입력창에 접근할 수 있다.
- 카드의 긴 이름/설명은 정해진 줄 수에서 말줄임 처리하고 레이아웃을 깨지 않는다.
- 좁은 화면에서는 우측 상세 패널을 전체 화면 또는 bottom sheet로 전환한다.
- 토글 pending, 저장 중, 테스트 실행 중 상태는 시각적으로 구분된다.
