# 기억 / Memory 화면 상세 기획

## 1. 화면 목적

기억 화면은 사용자가 AI에게 장기적으로 참고시키고 싶은 핵심 정보와 AI가 대화·스크랩·파일·주제에서 추출한 개인 지식을 관리하는 화면이다. PRD의 원칙상 자료는 기억에 쌓이고, 채팅은 이 기억을 다시 꺼내 쓰는 컨트롤 타워다. 따라서 이 화면은 단순 북마크 목록이 아니라 “AI가 나를 어떻게 기억하고 있는지”를 사용자가 검수·수정·삭제하는 신뢰 관리 화면이다.

이 화면이 해결해야 하는 사용자 문제는 다음이다.

| 사용자 문제 | 화면에서의 해결 방식 |
| --- | --- |
| AI가 어떤 정보를 나에 대해 기억하는지 알기 어려움 | 기억 카드와 우측 상세 패널에서 기억 내용, 유형, 신뢰도, 출처 수를 표시 |
| 오래되었거나 틀린 기억이 답변에 계속 반영될 수 있음 | 수정, 편집 이력, 업데이트일, 마지막 사용일, 잊기 정책을 제공 |
| 특정 주제에서만 쓸 기억과 전역 기억을 구분하기 어려움 | 관련 주제 연결, 출처, 관련 대화, 사용 기록을 분리 표시 |
| 스크랩·파일·대화에서 만들어진 정보의 근거를 확인하기 어려움 | 출처 목록, 원본 날짜, 관련 대화 링크, 소스 추가 기능을 제공 |
| 개인정보나 민감 정보가 저장되는 것이 불안함 | 신뢰도·출처 검증, AI 참조 제외, 완전 삭제, 감사 로그를 제공 |

첨부 화면 기준 기억은 `선호도`, `결정`, `자료`, `사람`, `프로젝트` 유형으로 분류된다. 예시는 `여행 선호도`, `투자 기준`, `자주 쓰는 글 스타일`, `도쿄 맛집 기준`, `AI 서비스 방향`이며, 각 항목은 신뢰도와 최근 사용일, 연결된 주제를 가진다.

## 2. 정보 구조

### 전체 레이아웃

PC 기준 3열 구조다.

| 영역 | 구성 | 목적 |
| --- | --- | --- |
| 좌측 사이드바 | 허브 선택, 전역 메뉴, 설정/도움말, 사용자 플랜 | 제품 전체 화면 간 이동 |
| 중앙 메인 | 화면 제목, 주요 액션, 검색/필터, 유형 탭, 정렬, 보기 전환, 기억 카드 목록 | 기억 탐색과 선택 |
| 우측 상세 패널 | 선택 기억의 개요/연결/사용 기록, 출처, 편집 기록, 관련 대화, 주요 액션 | 기억 검수·수정·삭제 |

좌측 사이드바는 PRD의 공통 내비게이션을 따른다. `기억` 메뉴가 파란색 활성 상태로 표시되며, 같은 그룹에 `오늘`, `주제`, `맡긴 일`, `에이전트`, `연결`, `스크랩`, `캘린더`, `할 일`, `파일`이 보인다.

### 중앙 메인 영역

상단에는 제목 `기억`과 보조 문구 `나에 대해 기억하고 참고할 핵심 정보들을 관리합니다.`를 표시한다. 우측 상단에는 `새 기억 추가`, `가져오기`, 더보기 메뉴가 있다.

목록 제어 영역은 다음 순서로 구성한다.

| 요소 | 화면 표시 | 기능 |
| --- | --- | --- |
| 검색 입력 | `기억 검색...`, 단축키 `⌘K` | 제목, 본문, 출처 제목, 관련 주제, 관련 대화 내용 검색 |
| 소스 필터 | `모든 소스` | 채팅, 스크랩, 파일, 수동 입력, 에이전트 추출, 외부 가져오기 기준 필터 |
| 유형 필터 | `모든 유형` | 선호도, 결정, 자료, 사람, 프로젝트 기준 필터 |
| 고급 필터 | `필터` | 신뢰도, 최근 사용일, 생성일, 업데이트일, 출처 수, 연결 여부, 즐겨찾기 |
| 유형 탭 | `전체 42`, `선호도 12`, `결정 8`, `자료 9`, `사람 6`, `프로젝트 7` | 빠른 유형 전환과 개수 확인 |
| 정렬 | `최근 사용순` | 최근 사용순, 최근 업데이트순, 생성일순, 신뢰도순, 제목순 |
| 보기 전환 | 그리드/리스트 아이콘 | 카드형 그리드와 밀도 높은 리스트 전환 |

기본 목록은 그리드 카드 3열이다. 선택된 카드는 파란색 테두리로 강조된다. 카드 마지막에는 점선 테두리의 `새 기억 추가` 카드가 있으며, 클릭 시 새 기억 생성 플로우를 연다.

### 우측 상세 패널

상세 패널은 선택된 기억이 있을 때 표시한다. 첨부 화면의 선택 항목은 `여행 선호도`다.

상단에는 아이콘, 제목, 유형 배지, 즐겨찾기 아이콘, 닫기 아이콘이 있다. 닫기를 누르면 상세 패널을 접고 중앙 목록을 더 넓게 쓴다.

탭은 다음 3개다.

| 탭 | 목적 |
| --- | --- |
| 개요 | 기억 본문, 메타데이터, 출처, 편집 기록, 관련 대화 요약 |
| 연결 | 관련 주제, 파일, 스크랩, 대화, 에이전트 참조 범위 관리 |
| 사용 기록 | AI 답변·검색·주제 작업에서 이 기억이 참조된 이력 확인 |

하단 고정 액션은 `수정`, `주제에 연결`, `잊기`다. `수정`은 기억 본문과 메타데이터 편집, `주제에 연결`은 topic 연결, `잊기`는 삭제/참조 제외/보관 정책 선택으로 이어진다.

## 3. 진입/종료/전환 동선

### 진입

| 진입 경로 | 처리 |
| --- | --- |
| 사이드바 `기억` 클릭 | 기억 목록 화면으로 진입하고 최근 사용순 기본 목록 조회 |
| 오늘 화면 채팅 결과의 `기억에 저장` CTA | 새 기억 추가 모달을 열고 대화 요약을 초안으로 채움 |
| 스크랩 상세의 `기억 저장` | 스크랩 요약·태그·원문 출처를 가진 기억 생성 플로우로 진입 |
| 파일 상세의 `기억 추출` | 파일 요약과 추출 후보를 보여주고 사용자가 저장할 항목 선택 |
| 주제 상세의 관련 기억 클릭 | 해당 기억을 선택한 상태로 진입하고 우측 상세 패널 표시 |
| 채팅에서 “내 여행 선호도 보여줘” | 검색 결과 또는 해당 기억 상세로 딥링크 |
| 알림에서 “기억 업데이트 제안” 클릭 | 검수 대기 상태의 기억 후보를 강조 표시 |

### 종료

| 종료 동작 | 처리 |
| --- | --- |
| 사이드바 다른 메뉴 클릭 | 해당 화면으로 전환, 미저장 편집 draft가 있으면 확인 |
| 상세 패널 닫기 | 선택 상태 해제 또는 패널 접힘, 목록 상태 유지 |
| 기억 카드 더블클릭 또는 Enter | 상세 패널 열기, 이미 열려 있으면 포커스를 상세로 이동 |
| `주제에 연결` 완료 | 현재 화면 유지, 관련 주제 칩과 상세 연결 탭 갱신 |
| `잊기` 완료 | 목록에서 제거 또는 보관/참조 제외 상태로 갱신 |

### 화면 내 전환

검색어 입력 시 목록은 debounce 후 갱신한다. 유형 탭과 필터는 함께 적용되며, 사용자가 `선호도` 탭을 누른 뒤 `모든 유형` 드롭다운을 바꾸면 탭 선택도 일관되게 갱신한다.

그리드/리스트 전환은 같은 데이터와 선택 상태를 유지한다. 상세 패널에서 탭을 전환해도 중앙 목록의 정렬·필터·스크롤 위치는 유지한다.

## 4. 핵심 시나리오

### 시나리오 A. 저장된 기억을 확인하고 출처 검증

1. 사용자가 사이드바에서 `기억`을 클릭한다.
2. 시스템은 기억 목록을 최근 사용순으로 조회한다.
3. 사용자가 `여행 선호도` 카드를 선택한다.
4. 우측 상세 패널의 `개요` 탭에서 기억 본문, 신뢰도, 생성일, 마지막 사용일, 업데이트일, 소스 수를 확인한다.
5. 사용자가 `출처` 섹션의 `도쿄 여행 계획 대화`를 클릭한다.
6. 원본 대화 또는 스크랩 상세가 열린다.
7. 원본 내용과 기억 내용이 다르면 사용자는 `수정`으로 기억을 갱신한다.

### 시나리오 B. 새 기억을 수동으로 추가

1. 사용자가 `새 기억 추가` 버튼 또는 목록의 빈 카드 CTA를 클릭한다.
2. 시스템은 새 기억 생성 모달을 연다.
3. 사용자는 제목, 유형, 본문, 관련 주제, 출처 또는 메모를 입력한다.
4. 시스템은 중복 후보와 민감 정보 포함 가능성을 검사한다.
5. 사용자가 저장하면 기억이 생성되고 목록 최상단 또는 현재 정렬 위치에 반영된다.
6. 상세 패널은 방금 만든 기억을 선택한 상태로 열린다.

### 시나리오 C. 스크랩에서 기억으로 승격

1. 사용자가 스크랩 화면에서 여행 스타일 설문 답변을 저장한다.
2. 스크랩 처리 완료 후 `기억 저장`을 누른다.
3. 시스템은 스크랩 요약에서 기억 후보를 생성한다.
4. 사용자는 유형을 `선호도`로 확정하고 관련 주제 `도쿄 여행`을 연결한다.
5. 저장 후 기억 상세의 출처에 해당 스크랩이 추가된다.
6. 이후 도쿄 여행 채팅에서 AI는 이 기억을 참조할 수 있다.

### 시나리오 D. 잘못된 기억을 잊기

1. 사용자가 `도쿄 맛집 기준` 기억이 오래되었거나 원치 않는다고 판단한다.
2. 상세 패널에서 `잊기`를 클릭한다.
3. 시스템은 `AI 참조 제외`, `보관`, `완전 삭제` 선택지를 보여준다.
4. 사용자가 `완전 삭제`를 선택하면 영향받는 주제, 대화 인용, 문서 citation, 에이전트 지식 연결을 미리 보여준다.
5. 사용자가 확인하면 기억 본문과 연결을 삭제하고 audit log를 남긴다.
6. 원본 스크랩·파일은 별도 객체이므로 함께 삭제할지 추가로 선택하게 한다.

### 시나리오 E. 채팅에서 기억을 사용하고 사용 기록 확인

1. 사용자가 오늘 화면에서 “내 여행 스타일에 맞춰 오사카 일정 추천해줘”라고 입력한다.
2. 시스템은 관련 기억 `여행 선호도`, `도쿄 맛집 기준`을 검색해 답변에 참고한다.
3. 답변 하단에는 사용된 기억 출처를 표시한다.
4. 사용자가 기억 화면으로 이동해 `여행 선호도`의 `사용 기록` 탭을 연다.
5. 방금 생성된 `오사카 여행 추천` 대화가 사용 기록에 표시된다.

## 5. 컴포넌트별 상세 기능

### 화면 헤더

| 요소 | 기능 |
| --- | --- |
| 제목 `기억` | 현재 화면 표시 |
| 보조 문구 | 기억의 목적을 설명 |
| `새 기억 추가` | 수동 생성 모달 또는 우측 편집 패널 열기 |
| `가져오기` | 파일, URL, 외부 앱 export, 브라우저 북마크, 기존 노트 가져오기 |
| 더보기 메뉴 | 중복 기억 정리, 기억 내보내기, 일괄 선택, 보관함 보기, 삭제 기록 보기 |

`가져오기`는 가져온 원본을 곧바로 AI 참조 가능 상태로 만들지 않는다. 처리 완료 후 사용자 검수 또는 자동 신뢰도 기준을 통과해야 활성 기억이 된다.

### 검색과 필터

검색 대상은 제목, 본문, 유형, 관련 주제명, 출처 제목, 관련 대화 제목이다. 검색 결과는 일치 영역을 하이라이트한다.

고급 필터는 다음 조건을 지원한다.

| 필터 | 값 |
| --- | --- |
| 신뢰도 | 높음, 중간, 낮음, 검수 필요 |
| 출처 수 | 없음, 1개, 2개 이상, 충돌 출처 있음 |
| 연결 상태 | 연결된 주제 있음, 연결 없음, 특정 주제 |
| 사용 상태 | 최근 사용됨, 90일 이상 미사용, 한 번도 사용 안 됨 |
| 생성 방식 | 수동, 채팅 추출, 스크랩 추출, 파일 추출, 에이전트 생성, 가져오기 |
| 개인정보 | 민감 가능성 있음, 민감 아님, 삭제 요청 중 |

필터 적용 상태는 URL query에 반영해 딥링크와 새로고침 복원이 가능해야 한다.

### 유형 탭

유형 탭은 기억의 의미 단위를 빠르게 좁히는 장치다.

| 유형 | 설명 | 예시 |
| --- | --- | --- |
| 선호도 | 사용자의 취향, 말투, 선택 기준 | 여행 선호도, 자주 쓰는 글 스타일, 도쿄 맛집 기준 |
| 결정 | 사용자가 명시적으로 확정한 원칙이나 판단 | 투자 기준, AI 서비스 방향 |
| 자료 | 나중에 참조할 요약·사실·문서화된 정보 | 리서치 요약, 회의 메모, 기사 요약 |
| 사람 | 연락처, 관계, 역할, 선호 커뮤니케이션 방식 | 동료, 가족, 협업자 정보 |
| 프로젝트 | 특정 목표나 장기 작업의 배경 지식 | 블로그 아이디어, 서비스 기획 방향 |

카운트는 현재 필터를 적용하기 전의 전체 유형 수를 기본으로 한다. 검색어가 입력된 상태에서는 검색 결과 내 카운트를 보여줄지 전체 카운트를 보여줄지 정책 결정이 필요하다.

### 기억 카드

카드는 다음 정보를 표시한다.

| 필드 | 표시 방식 |
| --- | --- |
| 아이콘 | 유형 또는 사용자가 지정한 이모지/이미지 |
| 제목 | 기억 이름 |
| 즐겨찾기 | 별 아이콘, 클릭 시 즉시 토글 |
| 유형 배지 | 선호도, 결정 등 |
| 요약 | 2~3줄 본문 요약 |
| 신뢰도 | `높음`, `중간`, `낮음`, `검수 필요` 배지 |
| 최근 사용 | 날짜 또는 상대 시간 |
| 연결된 주제 | 주제 칩 1~2개, 초과 시 `+N` |

카드 클릭은 상세 패널 선택이다. 즐겨찾기 클릭, 주제 칩 클릭, 카드 더보기 메뉴는 카드 선택과 이벤트가 충돌하지 않아야 한다.

### 새 기억 추가 카드

목록 마지막의 점선 카드다. 버튼형 `+` 아이콘, `새 기억 추가`, `나에 대한 중요한 정보를 기록해보세요.` 문구를 표시한다. 클릭 시 수동 생성 플로우로 진입한다.

새 기억 생성 필드는 다음이다.

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| 제목 | 필수 | 카드와 상세 패널에 표시되는 이름 |
| 유형 | 필수 | 선호도, 결정, 자료, 사람, 프로젝트 |
| 본문 | 필수 | AI가 참조할 핵심 내용 |
| 신뢰도 | 선택 | 기본은 `높음`, 출처 없으면 `검수 필요` 또는 `중간` 정책 검토 |
| 관련 주제 | 선택 | 하나 이상 연결 가능 |
| 출처 | 선택 | 대화, 스크랩, 파일, URL, 수동 메모 |
| 참조 범위 | 선택 | 전역, 특정 주제 전용, AI 참조 제외 |

### 상세 패널 헤더

상세 패널 헤더는 선택 기억의 현재 상태를 요약한다.

| 요소 | 기능 |
| --- | --- |
| 아이콘 | 기억 유형 또는 사용자 지정 아이콘 |
| 제목 | 인라인 편집은 기본 제공하지 않고 `수정` 플로우에서 변경 |
| 유형 배지 | 현재 유형 표시 |
| 즐겨찾기 | 중요 기억 고정, 목록 정렬 우선순위에 반영 가능 |
| 닫기 | 상세 패널 닫기 |

### 개요 탭

개요 탭은 기억 검수의 기본 화면이다.

| 섹션 | 표시 항목 |
| --- | --- |
| 본문 | 기억 원문 또는 요약된 핵심 내용 |
| 메타데이터 | 신뢰도, 생성일, 마지막 사용일, 업데이트일, 소스 수 |
| 출처 | 출처 제목, 출처 유형 아이콘, 출처 날짜, `출처 추가` |
| 편집 기록 | 날짜, 편집자, 변경 유형 |
| 관련 대화 | 대화 제목, 날짜, `모두 보기` |

첨부 화면의 예시는 다음 데이터를 가진다.

| 항목 | 값 |
| --- | --- |
| 제목 | 여행 선호도 |
| 유형 | 선호도 |
| 본문 | 도시 여행을 선호하고, 현지 음식과 문화를 중요하게 생각하며, 일정은 여유롭게 하루 2~3곳을 둘러보는 스타일을 좋아함 |
| 신뢰도 | 높음 |
| 생성일 | 2024. 1. 15 |
| 마지막 사용 | 2024. 5. 18 |
| 업데이트 | 2024. 4. 20 |
| 소스 수 | 3개 |
| 출처 | 도쿄 여행 계획 대화, 제주 여행 회고 대화, 여행 스타일 설문 답변 |
| 편집 기록 | 2024. 04. 20 Minho 내용 업데이트, 2024. 01. 15 AI 허브 초기 생성 |
| 관련 대화 | 도쿄 여행 일정 짜줘, 오사카 여행 추천, 다음 휴가 계획 |

### 연결 탭

연결 탭은 기억이 어느 객체에 영향을 주는지 관리한다.

| 연결 대상 | 기능 |
| --- | --- |
| 주제 | 특정 topic에 연결하거나 연결 해제 |
| 스크랩 | 근거 source로 추가 또는 제거 |
| 파일 | 파일에서 추출된 기억인 경우 원본 파일 표시 |
| 채팅 | 관련 conversation과 message range 연결 |
| 에이전트 | 특정 agent의 지식으로 사용할지 설정 |
| 자동 작업 | schedule/run이 이 기억을 참조하는지 표시 |

전역 기억은 모든 채팅에서 검색 후보가 된다. 주제 전용 기억은 해당 topic scope에서 우선 검색되고, 전역 답변에는 기본적으로 사용하지 않는다.

### 사용 기록 탭

사용 기록은 AI가 이 기억을 실제로 참조한 흔적이다.

| 필드 | 설명 |
| --- | --- |
| 사용일 | 기억이 검색 또는 답변 생성에 사용된 시간 |
| 사용 위치 | 전역 채팅, 주제 채팅, 문서 생성, 맡긴 일 run, 에이전트 실행 |
| 사용 방식 | 검색 후보, 답변 인용, 추천 근거, 필터 조건, 자동화 조건 |
| 결과 링크 | conversation, topic, artifact, run 상세 |
| 사용자 피드백 | 유용함, 부정확함, 사용하지 말기 |

사용 기록은 프라이버시 검토와 디버깅에 중요하다. 기억이 답변에 직접 노출되지 않았더라도 검색 컨텍스트로 사용되었다면 기록해야 한다.

### 하단 액션

| 액션 | 기능 |
| --- | --- |
| 수정 | 기억 본문, 유형, 신뢰도, 관련 주제, 참조 범위 편집 |
| 주제에 연결 | 기존 topic 검색 후 연결, 새 topic 생성 후 연결 |
| 잊기 | AI 참조 제외, 보관, 완전 삭제 중 선택 |

수정 저장 시 편집 기록이 추가된다. 자동 추출된 기억을 사용자가 수정하면 `user_verified=true`로 표시하고 신뢰도 계산에 반영한다.

## 6. 기억 유형, 신뢰도, 출처, 편집 이력, 잊기 정책

### 기억 상태 모델

| 상태 | 설명 | AI 참조 가능 여부 |
| --- | --- | --- |
| active | 정상 사용 중인 기억 | 가능 |
| draft | 생성 중 또는 가져오기 처리 중 | 불가 |
| review_required | 자동 추출 후 사용자 검수 필요 | 제한적 또는 불가 |
| excluded | 사용자가 AI 참조 제외 | 불가 |
| archived | 목록 기본 보기에서 숨김 | 불가 또는 옵션 |
| deleting | 삭제 처리 중 | 불가 |
| deleted | 삭제 완료 | 불가 |

### 신뢰도 정책

신뢰도는 AI가 이 기억을 얼마나 강하게 참고할지 결정하는 값이다.

| 신뢰도 | 조건 예시 | 사용 정책 |
| --- | --- | --- |
| 높음 | 사용자가 직접 입력·수정했거나, 2개 이상 출처가 일치하고 최근 사용 피드백이 좋음 | 답변 컨텍스트에 우선 포함 |
| 중간 | 출처는 있으나 오래되었거나 자동 추출만 된 기억 | 관련성이 높을 때만 포함 |
| 낮음 | 출처가 약하거나 충돌 출처가 있음 | 답변에 직접 반영하기 전 확인 질문 권장 |
| 검수 필요 | 새로 추출되었거나 민감 가능성이 있음 | 기본 참조 제외, 검수 CTA 표시 |

신뢰도는 단순 수동 배지가 아니라 `source_count`, `user_verified`, `last_confirmed_at`, `conflict_count`, `negative_feedback_count`, `last_used_at`을 함께 고려한다. 단, UI에는 사용자가 이해하기 쉬운 4단계 배지로 표시한다.

### 출처 정책

출처는 기억의 근거다. 출처 없는 기억도 허용하지만, AI 참조 강도는 낮아야 한다.

| 출처 유형 | 예시 | 링크 대상 |
| --- | --- | --- |
| 채팅 | 도쿄 여행 계획 대화 | conversation/message |
| 스크랩 | 여행 스타일 설문 답변, 기사, 유튜브 | source |
| 파일 | PDF, 회의록, 이미지 OCR | file_asset |
| 주제 | 도쿄 여행 작업면에서 확정한 설정 | topic/artifact |
| 수동 입력 | 사용자가 직접 입력한 메모 | memory 자체 |
| 외부 가져오기 | 브라우저 북마크, 노트앱 export | import job/source |

출처 삭제 시 연결된 기억의 `source_count`가 줄고, 출처가 0개가 되면 신뢰도 재계산 또는 검수 필요 상태 전환을 검토한다.

### 편집 이력 정책

편집 이력은 사용자가 “언제, 누가, 무엇을 바꿨는지” 확인하는 기록이다.

| 기록 대상 | 설명 |
| --- | --- |
| 생성 | 수동 생성, 자동 추출, 가져오기 |
| 내용 변경 | 제목, 본문, 유형, 신뢰도, 참조 범위 변경 |
| 연결 변경 | 주제/출처/파일/대화/에이전트 연결 추가·해제 |
| 사용 정책 변경 | AI 참조 제외, 보관, 복원 |
| 삭제 요청 | 삭제 방식, 요청자, 처리 결과 |

편집 기록은 기억 상세에서 요약 목록을 보여주고, 전체 감사 로그는 설정 또는 관리자 화면에서 확장할 수 있다.

### 잊기 정책

`잊기`는 삭제 하나로 처리하지 않는다. 사용자가 원하는 효과가 다르기 때문이다.

| 옵션 | 동작 | 원본 보존 | 복구 |
| --- | --- | --- | --- |
| AI 참조 제외 | 기억은 남기되 검색·답변 컨텍스트에서 제외 | 보존 | 즉시 복구 가능 |
| 보관 | 기본 목록에서 숨기고 AI 참조 제외 | 보존 | 보관함에서 복구 가능 |
| 완전 삭제 | 기억 본문, 연결, 임베딩, 검색 인덱스 제거 | 선택 | 복구 불가 또는 제한적 |

완전 삭제 전에는 영향 범위를 보여준다. 영향 범위에는 연결된 주제, 출처, 파일, 관련 대화, 생성 문서의 citation, 에이전트 지식 연결, 자동 작업 참조가 포함된다.

## 7. 개인정보와 삭제 edge case

| 상황 | 처리 |
| --- | --- |
| 민감 정보 자동 추출 | `검수 필요` 상태로 만들고 AI 참조 제외를 기본값으로 둠 |
| 사용자가 “나에 대한 이 정보 기억하지 마”라고 채팅에서 요청 | 관련 기억 후보를 찾아 잊기 확인 카드 표시 |
| 기억 완전 삭제 후 기존 대화에 해당 내용이 남아 있음 | 기억 객체와 검색 인덱스에서는 제거하되 원본 대화 삭제는 별도 확인 |
| 출처 파일을 삭제했는데 기억이 남아 있음 | 기억을 출처 없음 상태로 갱신하고 신뢰도 재계산 |
| 기억을 삭제했는데 생성 문서에 인용이 남아 있음 | 문서 citation은 깨진 출처로 표시하거나 재검토 필요 상태로 전환 |
| 공유 주제에 연결된 기억 삭제 | 다른 사용자에게 영향이 있으면 권한 확인과 영향 안내 후 처리 |
| 삭제 처리 중 네트워크 실패 | `deleting` 상태 유지, 재시도 큐와 사용자 알림 제공 |
| 임베딩 삭제 지연 | UI에는 삭제 처리 중으로 표시하고 검색 결과에서는 즉시 제외 |
| 법적/보안 보존 정책 대상 | 완전 삭제가 제한될 수 있음을 안내하고 AI 참조 제외를 즉시 적용 |
| 동일 내용 중복 기억 존재 | 삭제 후에도 비슷한 기억이 남을 수 있으므로 중복 후보를 함께 제안 |

개인정보 관련 액션은 audit log를 남긴다. 최소 기록은 요청자, 요청 시각, 대상 기억 ID, 삭제 옵션, 처리 상태, 실패 사유다.

## 8. 스크랩, 파일, 주제, 채팅과의 연계

### 스크랩 연계

스크랩은 원자료 inbox이고 기억은 검수된 장기 지식이다. 스크랩 상세에서 `기억 저장`을 누르면 source 요약을 바탕으로 기억 후보가 생성된다. 기억 상세의 출처 목록에서 스크랩을 열 수 있어야 한다.

연계 규칙은 다음이다.

| 동작 | 결과 |
| --- | --- |
| 스크랩 저장 완료 | 기억 후보 생성 가능 |
| 스크랩을 기억으로 저장 | memory 생성, source 연결 |
| 스크랩 원문 수정 또는 재요약 | 연결 기억 업데이트 제안 생성 |
| 스크랩 삭제 | 연결 기억의 출처 제거 또는 함께 삭제 선택 |

### 파일 연계

파일은 원본 자산이고 기억은 파일에서 추출한 핵심 지식이다. 파일 화면의 `기억 추출`은 한 파일에서 여러 기억 후보를 만들 수 있다.

| 동작 | 결과 |
| --- | --- |
| 파일 업로드 후 요약 완료 | 기억 추출 CTA 활성화 |
| 파일에서 기억 생성 | memory와 file_asset 연결 |
| 파일 권한 변경 | 기억 참조 가능 범위 재검토 |
| 파일 삭제 | 기억 출처 제거, 임베딩 삭제 범위 확인 |

### 주제 연계

주제는 기억의 사용 맥락이다. `여행 선호도`는 전역 선호도이면서 `도쿄 여행` 주제에 연결될 수 있다. 주제 전용 기억은 해당 주제의 채팅과 작업면에서 우선 사용된다.

| 동작 | 결과 |
| --- | --- |
| 기억을 주제에 연결 | topic-memory relation 생성 |
| 주제에서 기억 사용 | topic scope 검색 우선순위 상승 |
| 주제 삭제 또는 보관 | 연결 기억은 삭제하지 않고 관계만 비활성화 |
| 주제 작업면에서 결정 확정 | `결정` 유형 기억 생성 제안 |

### 채팅 연계

채팅은 기억 생성과 사용의 양쪽 출발점이다.

| 채팅 요청 | 처리 |
| --- | --- |
| “이거 기억해둬” | 현재 대화 내용을 기억 후보로 생성 |
| “이건 잊어줘” | 관련 기억 검색 후 잊기 확인 카드 표시 |
| “내 글 스타일 반영해줘” | 관련 선호도 기억 검색 후 답변 컨텍스트에 포함 |
| “왜 그렇게 추천했어?” | 답변에 사용된 기억과 출처 표시 |

채팅에서 생성된 기억은 원본 message range를 출처로 가져야 한다. 나중에 원본 대화가 삭제되면 기억의 출처 상태도 갱신한다.

## 9. 데이터 필드와 API 힌트

### 주요 객체

PRD의 내부 객체 모델과 맞춰 `memory`는 별도 도메인 객체로 두되, 원자료는 `source`, 업로드 파일은 `file_asset`, 사용 흔적은 `audit_log` 또는 `memory_usage`로 관리한다.

```ts
type MemoryType = 'preference' | 'decision' | 'material' | 'person' | 'project';
type MemoryStatus = 'active' | 'draft' | 'review_required' | 'excluded' | 'archived' | 'deleting' | 'deleted';
type ConfidenceLevel = 'high' | 'medium' | 'low' | 'review_required';
type MemoryScope = 'global' | 'topic' | 'agent' | 'excluded';
type SourceType = 'conversation' | 'scrap' | 'file' | 'topic' | 'manual' | 'import';
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | memory ID |
| hubId | string | 허브/워크스페이스 범위 |
| title | string | 기억 제목 |
| icon | string | 카드 아이콘 |
| type | MemoryType | 기억 유형 |
| status | MemoryStatus | 상태 |
| summary | string | 카드용 요약 |
| content | string | AI 참조용 본문 |
| confidenceLevel | ConfidenceLevel | UI 신뢰도 배지 |
| confidenceScore | number | 내부 계산 점수 |
| scope | MemoryScope | 참조 범위 |
| topicIds | string[] | 연결 주제 |
| sourceCount | number | 출처 수 |
| sourceIds | string[] | 연결 source/file/conversation relation |
| favorite | boolean | 즐겨찾기 여부 |
| userVerified | boolean | 사용자 검수 여부 |
| sensitive | boolean | 민감 가능성 |
| createdBy | string | 사용자 또는 시스템 |
| createdAt | string | 생성일 |
| updatedAt | string | 업데이트일 |
| lastUsedAt | string \| null | 마지막 사용일 |
| lastConfirmedAt | string \| null | 마지막 사용자 확인일 |
| deletedAt | string \| null | 삭제일 |

### API 힌트

| API | 설명 |
| --- | --- |
| `GET /api/memories` | 목록 조회. 검색, 유형, 소스, 신뢰도, 연결 상태, 정렬, 페이지네이션 지원 |
| `POST /api/memories` | 수동 기억 생성 |
| `GET /api/memories/{memoryId}` | 상세 조회. 출처, 편집 기록, 관련 대화 요약 포함 |
| `PATCH /api/memories/{memoryId}` | 제목, 본문, 유형, 신뢰도, 참조 범위 수정 |
| `POST /api/memories/{memoryId}/sources` | 출처 추가 |
| `DELETE /api/memories/{memoryId}/sources/{sourceId}` | 출처 연결 해제 |
| `POST /api/memories/{memoryId}/topics` | 주제 연결 |
| `DELETE /api/memories/{memoryId}/topics/{topicId}` | 주제 연결 해제 |
| `POST /api/memories/{memoryId}/forget` | AI 참조 제외, 보관, 완전 삭제 요청 |
| `GET /api/memories/{memoryId}/usage` | 사용 기록 조회 |
| `GET /api/memories/{memoryId}/history` | 편집 이력 조회 |
| `POST /api/memories/import` | 외부 자료 가져오기 job 생성 |
| `POST /api/memories/extract` | 대화, 스크랩, 파일에서 기억 후보 추출 |

목록 API는 우측 상세 패널에 필요한 상세 데이터를 모두 싣지 않는다. 카드 렌더링용 필드만 받고, 선택 시 상세 API를 호출한다. 단, 선택 상태 복원을 위해 URL의 `memoryId`가 있으면 목록과 상세를 병렬 조회할 수 있다.

### 라우팅과 URL 상태

| URL 예시 | 의미 |
| --- | --- |
| `/memory` | 기본 목록 |
| `/memory?type=preference` | 선호도 탭 |
| `/memory?query=여행&confidence=high` | 검색과 필터 적용 |
| `/memory/{memoryId}` | 특정 기억 상세 선택 |
| `/memory/{memoryId}?tab=usage` | 사용 기록 탭 선택 |

## 10. 수용 기준

### 목록과 탐색

| 기준 | 수용 조건 |
| --- | --- |
| 검색 | 제목, 본문, 출처, 관련 주제 기준으로 검색되고 결과가 500ms 내 갱신된다 |
| 유형 탭 | 전체/선호도/결정/자료/사람/프로젝트 탭과 카운트가 표시된다 |
| 필터 | 소스, 유형, 신뢰도, 연결 상태, 최근 사용일 필터를 조합할 수 있다 |
| 정렬 | 최근 사용순, 업데이트순, 생성일순, 신뢰도순, 제목순 정렬을 지원한다 |
| 보기 전환 | 그리드와 리스트 전환 후 선택 기억과 필터 상태가 유지된다 |
| 빈 상태 | 기억이 없거나 검색 결과가 없을 때 생성/필터 초기화 CTA를 제공한다 |

### 상세와 편집

| 기준 | 수용 조건 |
| --- | --- |
| 상세 패널 | 카드 선택 시 우측 패널에 개요/연결/사용 기록 탭이 열린다 |
| 메타데이터 | 신뢰도, 생성일, 마지막 사용일, 업데이트일, 소스 수가 표시된다 |
| 출처 | 출처 목록과 출처 추가 액션을 제공하고 원본으로 이동 가능하다 |
| 편집 기록 | 생성과 내용 업데이트 이력이 날짜, 편집자, 변경 유형으로 표시된다 |
| 관련 대화 | 관련 대화 3개 이상이면 `모두 보기`로 확장 가능하다 |
| 수정 | 본문, 유형, 신뢰도, 관련 주제, 참조 범위를 수정할 수 있고 history가 남는다 |

### 기억 정책

| 기준 | 수용 조건 |
| --- | --- |
| 신뢰도 | 높음/중간/낮음/검수 필요 상태가 UI와 API에서 일관된다 |

| 완전 삭제 | 기억 본문, 연결, 임베딩, 검색 인덱스 제거 요청이 수행된다 |
| 감사 로그 | 수정, 연결 변경, 잊기, 삭제는 audit log에 남는다 |
| 사용 기록 | 기억이 답변 컨텍스트에 쓰이면 usage에 기록된다 |

## 11. 엣지케이스 자체 리뷰

중첩 리뷰가 불가능한 경우를 대비해, 개발 착수 전 아래 항목을 별도 점검한다.

| 점검 항목 | 확인 내용 |
| --- | --- |
| 값 변경 후 읽는 곳 | 신뢰도, 상태, 출처 수, 주제 연결 변경 시 목록 카드, 상세 패널, 채팅 검색 컨텍스트가 모두 갱신되는지 확인 |
| 이름 충돌 | `source`가 PRD의 원자료 객체와 기억 출처 relation을 동시에 의미하므로 API에서는 `memorySourceLink` 같은 relation 명칭 검토 |
| BE-FE prop 이름 | `confidenceLevel`, `sourceCount`, `lastUsedAt`, `topicIds`, `userVerified`, `sensitive`를 목록/상세에서 동일하게 사용 |
| 리스트 key | 기억 카드, 출처 목록, 편집 이력, 관련 대화, 사용 기록은 모두 안정적인 ID를 key로 사용 |
| 삭제 동시성 | 삭제 처리 중 수정/연결/사용 기록 추가가 들어오면 `deleting` 상태 기준으로 거절 또는 큐잉 |
| 인덱스 지연 | 완전 삭제 직후 검색 결과에 재노출되지 않도록 UI와 검색 API 모두 제외 조건 적용 |
| 원본 삭제 | 원본 파일·스크랩·대화 삭제가 기억 신뢰도와 출처 수에 미치는 영향 반영 |
| 권한 | 공유 주제나 팀 허브 기억은 수정/삭제 권한과 AI 참조 범위를 분리 |

## 12. 오픈 질문

| 질문 | 후보/검토 방향 |
| --- | --- |
| 기억 객체를 `source`의 하위 유형으로 둘지 별도 `memory` 객체로 둘지 | UI와 정책상 편집/사용 기록/잊기 정책이 강하므로 별도 객체가 유리 |
| 출처 없는 수동 기억의 기본 신뢰도 | 사용자가 직접 입력하면 `높음`, 근거 없으면 `중간`으로 둘지 결정 필요 |
| 검색 결과 카운트 기준 | 유형 탭 카운트를 전체 기준으로 둘지 현재 검색/필터 결과 기준으로 둘지 결정 필요 |
| 완전 삭제의 복구 가능 기간 | 즉시 물리 삭제와 7~30일 soft delete 중 보안/UX 정책 결정 필요 |
| 원본 대화 삭제 시 기억도 자동 삭제할지 | 기본은 출처 제거와 신뢰도 재계산, 민감 정보 요청은 함께 삭제 후보 제안 |
| 팀/공유 허브에서 개인 기억 노출 | 개인 기억과 공유 기억을 완전히 분리할지, 주제 연결 시 제한적으로 공유할지 결정 필요 |
| AI가 기억을 자동 생성하는 임계값 | 매 대화 자동 추출은 과도하므로 명시 요청, 반복 패턴, 주제 결정 확정 시점 위주 검토 |
| 사용 기록 보존 기간 | 프라이버시와 디버깅 사이에서 90일, 1년, 무기한 중 정책 필요 |
| `가져오기` MVP 범위 | 파일/URL만 우선할지, 브라우저 북마크/노트앱 export까지 포함할지 결정 필요 |
| `잊기`와 법적 보존 정책 충돌 | 사용자에게 어떤 문구와 상태를 보여줄지 보안/법무 검토 필요 |
