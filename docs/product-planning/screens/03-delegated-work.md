# 맡긴 일 / Delegated Work 화면 상세 기획

## 1. 화면 목적

`맡긴 일`은 사용자가 AI에게 위임한 장시간 작업, 여러 에이전트가 나눠 수행하는 작업, 예약 실행, 승인 대기 작업을 한곳에서 감시하고 제어하는 운영 화면이다.

이 화면의 핵심 목적은 세 가지다.

| 목적 | 설명 |
| --- | --- |
| 진행 상황 파악 | 실행 중인 run의 진행률, 담당 에이전트, 사용 도구, 비용, 최근 로그를 목록에서 빠르게 확인한다. |
| 개입 필요 작업 처리 | 외부 예약, 비용 초과, 권한 요청처럼 사용자 승인이 필요한 작업을 우측 패널에서 즉시 승인/거절한다. |
| 실행 제어 | 특정 run을 일시정지, 재개, 중지, 재시도하거나 에이전트 구성과 지시를 수정한다. |

PRD 기준으로 `맡긴 일`은 내부 객체 `run`, `schedule`, `approval_request`, `agent`, `tool`, `artifact`, `audit_log`가 만나는 실행 관제면이다. 사용자에게는 `swarm` 같은 내부 용어 대신 “여러 담당에게 맡긴 작업”으로 설명한다.

## 2. 정보 구조

### 2.1 전체 레이아웃

```text
좌측 글로벌 내비
  └─ 맡긴 일 메뉴 활성화

중앙 메인 영역
  ├─ 화면 제목 / 설명 / 작업 맡기기 CTA / 더보기
  ├─ 상태 탭 / 필터 / 검색 / 보기 전환
  ├─ 맡긴 일 목록 테이블
  └─ 더 많은 작업 보기

우측 상세 패널
  ├─ 선택 run 헤더 / 상태 / 닫기
  ├─ 탭: 개요 / 상세 로그 / 파일 & 결과 / 설정
  ├─ 에이전트 스웜 트리
  ├─ 승인 대기 카드
  ├─ 작업 제어
  └─ 이 작업에 말하기
```

### 2.2 좌측 글로벌 내비

화면 이미지에 보이는 글로벌 내비 항목은 다음과 같다.

| 영역 | 항목 | 동작 |
| --- | --- | --- |
| 상단 | 프로필 이미지, `내 AI 허브`, 드롭다운, 알림 | 허브/계정 전환, 알림 센터 진입 |
| 주요 메뉴 | 오늘, 주제, 맡긴 일, 기억, 에이전트, 연결 | 각 상위 화면으로 이동. 현재 화면에서는 `맡긴 일`이 파란색 활성 상태 |
| 보조 메뉴 | 스크랩, 캘린더, 할 일, 파일 | 관련 관리 화면으로 이동 |
| 하단 | 설정, 도움말 | 전역 설정과 도움말로 이동 |
| 계정 카드 | `Minho`, `프로 플랜`, 드롭다운 | 플랜/계정 메뉴 표시 |

### 2.3 중앙 목록 정보 구조

상태 탭은 run을 큰 상태별로 나눈다.

| 탭 | 이미지 카운트 | 포함 대상 |
| --- | ---: | --- |
| 진행 중 | 4 | 현재 실행 중, 일시정지 가능, 로그가 계속 쌓이는 run |
| 승인 대기 | 2 | 사용자의 명시 승인이 필요한 approval_request가 연결된 run |
| 예약됨 | 5 | 아직 실행 전인 schedule 기반 run 또는 다음 실행 예정 항목 |
| 완료 | 28 | 성공, 실패, 중지, 만료 등 종료 상태 run |

목록 컬럼은 다음 순서를 기본으로 한다.

| 컬럼 | 표시 내용 |
| --- | --- |
| 작업 | 아이콘, 작업명, 분류 태그, 생성 시각 |
| 진행률 | percent, progress bar, 남은 시간 |
| 담당 에이전트 | 대표 담당자 1~2명, 추가 인원 배지 |
| 도구 | 사용 중이거나 예정된 도구 아이콘, 추가 도구 수 |
| 비용 / 시간 | 누적 비용, 실행 시간 |
| 최근 로그 | 최근 이벤트 2개, 이벤트 시각, 상태 dot |
| 행 메뉴 | run별 더보기 메뉴 |

### 2.4 우측 상세 패널 정보 구조

선택한 run의 상세 패널은 목록을 벗어나지 않고 해당 작업을 제어하는 영역이다.

| 섹션 | 표시/기능 |
| --- | --- |
| 헤더 | 작업 아이콘, 작업명, 상태 배지, 닫기 버튼 |
| 상세 탭 | 개요, 상세 로그, 파일 & 결과, 설정 |
| 에이전트 스웜 | 오케스트레이터와 하위 에이전트 트리, 진행률, 역할, 추가 버튼 |
| 승인 대기 | 승인 요청 카드, 예상 비용, 대상 일정/범위, 승인/거절 |
| 작업 제어 | 일시정지, 재개, 중지 |
| 이 작업에 말하기 | run scope chat 입력, 전송, 빠른 지시 버튼 |

## 3. 진입 / 종료 / 전환 동선

### 3.1 진입

| 진입 지점 | 조건 | 랜딩 상태 |
| --- | --- | --- |
| 좌측 내비 `맡긴 일` 클릭 | 기본 진입 | `진행 중` 탭, 최근 업데이트순 목록, 첫 번째 run 선택 |
| 오늘 화면의 진행 중 작업 카드 | 특정 run 클릭 | 해당 run이 선택된 상태로 우측 상세 패널 오픈 |

| 주제 화면 자동화/작업 탭 | topic scope run 클릭 | 해당 topic에 연결된 run 목록으로 필터 적용 |

## 4. 핵심 시나리오

### 4.1 진행 중인 여러 작업을 한눈에 확인

1. 사용자가 좌측 내비에서 `맡긴 일` 진입.
2. 중앙 목록에서 `진행 중 4` 탭이 기본 선택됨.
3. 각 작업의 진행률, 남은 시간, 담당 에이전트, 비용, 최근 로그를 비교.
4. 사용자가 `도쿄 여행 조사 중` 행을 클릭.
5. 우측 패널에서 에이전트 스웜과 승인 대기 항목을 확인.

### 4.2 승인 대기 요청 처리

1. 우측 패널 또는 `승인 대기` 탭에서 승인 요청 확인.
2. 카드에 “숙소 예약 후보 3곳을 예약할까요?”가 표시됨.
3. 예상 비용 `₩128,400`, 세금/수수료 포함 여부, 여행 날짜, 인원 정보를 확인.
4. `승인하기` 클릭 시 해당 approval_request가 승인 상태가 되고 run이 다음 단계로 진행.
5. `거절` 클릭 시 run은 대체 후보 탐색, 사용자 추가 지시 대기, 또는 부분 중지 상태로 전환.

### 4.3 실행 중인 작업에 추가 지시

1. 사용자가 `이 작업에 말하기` 입력창에 “예산 더 낮춰줘” 입력.
2. 메시지는 전역 채팅이 아니라 선택 run scope에 저장.
3. 오케스트레이터가 현재 계획을 수정하고 하위 에이전트에게 새 제약을 전파.
4. 비용/시간 추정치와 최근 로그가 갱신.
5. 변경이 외부 예약/결제/쓰기 작업을 유발하면 승인 카드가 새로 생성됨.

### 4.4 작업 일시정지 후 재개

1. 사용자가 `일시정지` 클릭.
2. run은 새 도구 호출과 하위 에이전트 작업 생성을 중단.
3. 이미 진행 중인 취소 불가 외부 API 호출은 완료까지 기다리고 결과를 보관.
4. 상태가 `paused`로 바뀌며 버튼은 `재개`로 변경.
5. 사용자가 `재개` 클릭 시 마지막 체크포인트부터 이어서 실행.

### 4.5 작업 중지

1. 사용자가 `중지` 클릭.
2. 확인 모달에서 중지 영향과 이미 발생한 비용을 표시.
3. 확인 시 run 상태가 `stopping`을 거쳐 `stopped`로 종료.
4. 생성된 중간 파일, 로그, 부분 결과는 유지.
5. 외부 예약/결제 등 되돌릴 수 없는 작업은 별도 취소 가능 여부를 결과에 표시.

### 4.6 실패 run 재시도

1. 사용자가 `완료` 탭에서 실패 run 선택.
2. 최근 로그 또는 상세 로그에서 실패 원인 확인.
3. `재시도` 클릭.
4. 기본값은 실패한 step부터 재시도.
5. 입력/권한/비용 조건이 바뀌었으면 재시도 전 승인 요청을 다시 생성.

### 4.7 여러 담당 추가

1. 우측 `에이전트 스웜`에서 `+ 에이전트 추가` 클릭.
2. 역할 템플릿 또는 기존 에이전트 선택.
3. 추가 에이전트의 권한, 도구, 비용 제한을 확인.
4. 오케스트레이터가 새 담당에게 하위 작업을 배정.
5. 목록의 담당 에이전트 배지와 스웜 트리가 갱신.

### 4.8 예약된 자동 작업 확인/수정

1. 사용자가 `예약됨` 탭으로 이동.
2. 다음 실행 예정인 자동 작업과 반복 주기, 연결 주제, 예상 비용을 확인.
3. 특정 예약 작업을 선택하면 우측 패널의 설정 탭에서 실행 시간, 반복 주기, 비용 상한, 승인 정책을 수정할 수 있다.
4. 수정 후 다음 실행부터 새 설정을 적용한다.
5. 이미 queued 상태로 넘어간 실행 건은 별도 run으로 보고, schedule 수정과 run 제어를 분리한다.

## 5. 컴포넌트별 상세 기능

### 5.1 페이지 헤더

| 요소 | 기능 |
| --- | --- |
| 제목 `맡긴 일` | 현재 화면의 상위 목적 표시 |
| 설명 문구 | “여러 에이전트에게 맡긴 작업의 진행 상황을 한눈에 확인하세요.” |
| `+ 작업 맡기기` | 새 run/schedule 생성 플로우 시작 |
| 더보기 버튼 | 일괄 작업, CSV 내보내기, 표시 설정, 도움말 진입 |

`작업 맡기기` 클릭 시 사용자가 직접 작업명/목표/담당 에이전트/도구/반복 여부/비용 상한/승인 정책을 설정하거나 채팅형 생성 플로우로 진입한다.

### 5.2 상태 탭

| 기능 | 상세 |
| --- | --- |
| 카운트 표시 | 탭명 옆 숫자는 현재 필터 적용 전 상태별 전체 개수 |
| 기본 탭 | 진입 시 `진행 중` |
| 카운트 갱신 | run 상태 변경, approval 생성/처리, schedule 생성/삭제 시 실시간 또는 폴링 갱신 |
| 빈 상태 | 탭별 목적에 맞는 안내와 CTA 표시 |

### 5.3 정렬 / 필터 / 보기 전환

목록 기본 정렬은 `최근 업데이트 내림차순`이다. 사용자는 필터 팝오버와 보기 전환 버튼으로 표시 범위를 조정한다.

| 기능 | 상세 |
| --- | --- |
| 기본 정렬 | 최근 로그 또는 상태 변경 시각 기준 내림차순 |
| 보조 정렬 | 생성 시각, 비용, 진행률, 남은 시간, 승인 만료 임박순 |
| 필터 초기화 | 적용 중인 필터가 있으면 버튼에 활성 상태 표시, 팝오버에서 전체 초기화 제공 |
| 보기 전환 | 테이블, 컴팩트 리스트, 트리 보기 중 선택 |
| URL 동기화 | 탭, 검색어, 주요 필터, 선택 runId는 URL query로 복원 가능 |

### 5.4 필터

필터 버튼은 팝오버로 열린다.

| 필터 | 값 예시 |

| 담당 에이전트 | 여행 조사원, 웹 서처, 리서치 분석가 |
| 도구 | 웹 검색, 파일, 캘린더, 결제/예약, YouTube, 코드 |
| 상태 | running, approval_waiting, paused, failed 등 세부 상태 |
| 비용 | 무료, $0.01 미만, $0.01~$0.10, 직접 입력 |
| 생성/예약 시각 | 오늘, 이번 주, 사용자 지정 |
| 권한 위험도 | 읽기 전용, 쓰기 승인 필요, 결제 승인 필요 |

### 5.11 에이전트 스웜

이미지 기준 구조는 다음과 같다.

```text
여행 매니저 (Orchestrator) - 진행 중 65%
  ├─ 여행 조사원 - 웹 검색 - 진행 중 70%
  ├─ 맛집 탐색기 - 맛집 데이터 - 진행 중 60%
  └─ 가격 비교봇 - 숙소/항공권 - 진행 중 55%
      └─ + 에이전트 추가
```

| 기능 | 상세 |
| --- | --- |
| 오케스트레이터 표시 | 전체 목표, 하위 작업 분배, 종합 진행률 표시 |
| 하위 에이전트 카드 | 역할, 사용 도구/데이터 소스, 개별 상태, 개별 진행률 표시 |
| 연결선 | 부모-자식 관계와 병렬 실행 구조 표시 |
| 접기/펼치기 | 스웜 섹션 전체 또는 하위 노드 접기 |
| 에이전트 추가 | 실행 중인 run에 새 담당 추가. 권한/비용 확인 필요 |
| 에이전트 카드 클릭 | 해당 에이전트 로그와 산출물로 상세 패널 내용 필터 |

진행률 계산은 단순 평균이 아니라 오케스트레이터가 정의한 step 가중치 기준을 우선한다. 가중치가 없으면 하위 에이전트의 완료 step 비율 평균으로 표시한다.

### 5.12 승인 대기 카드

이미지에 보이는 승인 카드 필드는 다음과 같다.

| 필드 | 예시 | 설명 |
| --- | --- | --- |
| 제목 | 숙소 예약 후보 3곳을 예약할까요? | 사용자가 승인해야 할 외부 쓰기/결제/예약 액션 |
| 예상 비용 | ₩128,400 (세금/수수료 포함) | 승인 시 발생 가능한 금액 |
| 대상 | 도쿄 · 5월 20일 ~ 5월 24일 · 성인 2명 | 액션 범위와 조건 |
| 거절 | 버튼 | 요청을 거절하고 대체 플로우로 전환 |
| 승인하기 | 버튼 | 승인 후 다음 step 진행 |

승인 카드가 여러 개면 최신/긴급 순으로 1개를 우선 표시하고 `모두 보기`에서 전체 승인 대기를 연다.

### 5.13 작업 제어

| 버튼 | 표시 조건 | 동작 |
| --- | --- | --- |
| 일시정지 | running, approval_waiting 중 일부 | 새 작업 할당과 도구 호출 중단 |
| 재개 | paused | 마지막 체크포인트부터 실행 재개 |
| 중지 | running, paused, approval_waiting | run 종료 플로우 시작 |
| 재시도 | failed, stopped, expired 중 재시도 가능 상태 | 실패 step 또는 전체 run 재실행 |

`중지`는 빨간 테두리/텍스트로 위험 동작임을 명확히 표시한다.

### 5.14 이 작업에 말하기

| 요소 | 기능 |
| --- | --- |
| 입력창 | 선택 run에 추가 지시 전달 |
| 전송 버튼 | 메시지 전송. 입력이 없으면 비활성 또는 회색 상태 |
| 빠른 지시 | `예산 더 낮춰줘`, `온천 숙소 위주로`, `일정 1일 추가` |

빠른 지시는 run의 주제/유형에 따라 동적으로 추천한다. 예를 들어 투자 리서치 run에는 `리스크 요약 먼저`, 블로그 run에는 `톤 더 캐주얼하게` 같은 제안을 보여준다.

## 6. Run 상태 모델

### 6.1 내부 상태

| 상태 | 의미 | 사용자 표시 |
| --- | --- | --- |
| draft | 생성 중이며 아직 실행 전 | 작성 중 |
| queued | 실행 대기열에 있음 | 대기 중 |
| scheduled | 예약되어 아직 시작 전 | 예약됨 |
| running | 실행 중 | 진행 중 |
| approval_waiting | 사용자 승인 필요 | 승인 대기 |
| paused | 사용자가 일시정지함 | 일시정지 |
| resuming | 재개 준비 중 | 재개 중 |
| stopping | 중지 처리 중 | 중지 중 |
| stopped | 사용자 중지로 종료 | 중지됨 |
| retrying | 재시도 중 | 재시도 중 |
| succeeded | 성공 종료 | 완료 |
| failed | 실패 종료 | 실패 |
| partially_succeeded | 일부 성공, 일부 실패 | 일부 완료 |
| expired | 승인/예약/credential 만료로 종료 | 만료됨 |
| cancelled_by_system | 정책/권한/비용 제한으로 종료 | 시스템 취소 |

### 6.2 탭 매핑

| 탭 | 포함 상태 |
| --- | --- |
| 진행 중 | queued, running, resuming, retrying, stopping |
| 승인 대기 | approval_waiting |
| 예약됨 | draft 중 예약 생성 완료, scheduled |
| 완료 | succeeded, failed, partially_succeeded, stopped, expired, cancelled_by_system |

### 6.3 상태 전이

```text
draft
  ├─ scheduled
  │   └─ queued
  └─ queued
      └─ running
          ├─ approval_waiting
          │   ├─ running
          │   ├─ paused
          │   └─ stopped
          ├─ paused
          │   ├─ resuming
          │   └─ stopped
          ├─ retrying
          ├─ succeeded
          ├─ partially_succeeded
          ├─ failed
          ├─ expired
          └─ cancelled_by_system
```

상태 전이는 모두 audit log로 남긴다. 사용자 액션, 시스템 정책, 에이전트 판단으로 발생한 전이를 구분해 저장한다.

## 7. 승인 대기 / 비용 / 권한 Edge Case

### 7.1 승인 대기

| 케이스 | 정책 |
| --- | --- |
| 승인 요청이 여러 개 | 우측 패널에는 가장 긴급한 1개 표시, `모두 보기`에서 일괄 확인 |
| 승인 만료 | 카드에 만료 시각 표시. 만료 후 `expired` 또는 대체 후보 탐색 |
| 승인 중 가격 변경 | 승인 직전 최종 비용 재검증. 증가분이 허용 범위를 넘으면 재승인 요청 |
| 사용자가 거절 | run 목표를 유지할 수 있으면 대체안 탐색, 불가능하면 사용자 지시 대기 |
| 승인 후 외부 작업 실패 | 비용 발생 여부와 실패 원인을 분리해 표시 |
| 승인 권한 없는 계정 | `승인하기` 비활성화, 필요한 권한/계정 전환 안내 |

### 7.2 비용

| 케이스 | 정책 |
| --- | --- |
| 모델/API 비용 상한 접근 | 목록 비용 영역과 상세 패널에 경고 표시 |
| 비용 상한 초과 예상 | 실행 전 approval_request 생성 |
| 외부 결제 포함 | 모델 비용과 외부 결제 금액을 분리 표시 |
| 통화 혼재 | 사용자 결제 통화 기준으로 환산하고 원금액도 보조 표시 |
| 비용 산정 지연 | `계산 중` 표시 후 정산 완료 시 갱신 |
| 무료 도구와 유료 도구 혼합 | 비용 breakdown을 상세 로그 또는 설정 탭에서 제공 |

### 7.3 권한

| 케이스 | 정책 |
| --- | --- |
| credential 만료 | run 일시정지 후 연결 화면으로 복구 동선 제공 |
| 도구 권한 없음 | 해당 step은 실행하지 않고 승인/권한 요청 생성 |
| 읽기 전용 도구만 허용 | 예약/결제/파일 쓰기 같은 액션은 실행 전 차단 |
| 외부 계정 전환 필요 | 승인 카드 또는 설정 탭에서 계정 선택 |
| workspace/topic 접근 권한 없음 | 해당 자료를 제외하고 실행하거나 사용자에게 권한 요청 |
| 정책 위반 감지 | run을 `cancelled_by_system`으로 종료하고 audit log에 사유 기록 |

## 8. Pause / Resume / Stop / Retry 정책

### 8.1 Pause

| 항목 | 정책 |
| --- | --- |
| 적용 대상 | running, 일부 approval_waiting |
| 즉시 중단 범위 | 새 step 생성, 새 tool call, 새 subagent 할당 |
| 즉시 중단 불가 범위 | 이미 요청된 외부 API, 취소 불가 결제/예약, 파일 업로드 완료 처리 |
| 데이터 처리 | 현재 체크포인트, 중간 artifact, 로그 유지 |
| UI | 상태 배지를 `일시정지`로 변경, `일시정지` 버튼을 `재개`로 교체 |

### 8.2 Resume

| 항목 | 정책 |
| --- | --- |
| 시작 지점 | 마지막 성공 체크포인트 |
| 사전 검증 | credential, 비용 상한, schedule 유효성, approval 만료 여부 |
| 변경 지시 반영 | pause 중 입력된 run chat 메시지를 계획에 반영 |
| 실패 시 | resume 실패 원인을 로그에 남기고 `paused` 또는 `failed` 유지 |

### 8.3 Stop

| 항목 | 정책 |
| --- | --- |
| 확인 | 중지 확인 모달 필수 |
| 종료 방식 | `stopping` 상태로 전환 후 가능한 작업 취소 |
| 결과 보존 | 로그, 비용, 중간 결과, 생성 파일 유지 |
| 외부 작업 | 취소 가능 여부와 별도 취소 링크 표시 |
| 재시도 가능성 | stopped run은 조건이 맞으면 복제 실행 또는 재시도 가능 |

### 8.4 Retry

| 항목 | 정책 |
| --- | --- |
| 기본 범위 | 실패 step부터 재시도 |
| 전체 재시도 | 사용자가 옵션으로 선택 |
| 입력 변경 | 재시도 전 목표/도구/에이전트/비용 상한 수정 가능 |
| 권한 재확인 | 승인, credential, 비용 상한을 다시 검증 |
| 중복 방지 | 외부 쓰기/결제 step은 idempotency key 기준으로 중복 실행 차단 |

## 9. Multi-agent Tree

### 9.1 역할 모델

| 역할 | 설명 |
| --- | --- |
| Orchestrator | 목표 해석, 계획 수립, 하위 에이전트 배정, 결과 통합 |
| Worker Agent | 특정 역할/도구를 맡아 하위 step 수행 |
| Reviewer Agent | 결과 검증, 출처 확인, 품질 평가 |
| Tool-only Step | 별도 에이전트 카드 없이 도구 호출만 수행하는 step |

### 9.2 트리 표시 규칙

| 규칙 | 설명 |
| --- | --- |
| 최상단 | 오케스트레이터 1개를 기본 표시 |
| 하위 카드 | 최대 3개까지 한 줄 표시, 초과 시 접기 또는 가로 스크롤 |

| 상태 dot | 진행 중, 완료, 실패, 승인 대기를 색상으로 구분 |
| 연결선 | 병렬/종속 관계를 시각적으로 구분 |
| 추가 버튼 | 실행 중에도 담당 추가 가능. 단 비용/권한 검증 필요 |

### 9.3 하위 에이전트 상세

에이전트 카드 클릭 시 상세 패널 내용이 해당 에이전트 기준으로 필터링된다.

| 표시 정보 | 예시 |
| --- | --- |
| 역할명 | 여행 조사원 |
| 사용 도구 | 웹 검색 |
| 상태 | 진행 중 |
| 진행률 | 70% |
| 현재 step | 숙소 가격 비교 |
| 산출물 | 후보 숙소 표, 맛집 리스트 |
| 비용 | 해당 에이전트 누적 비용 |

## 12. 수용 기준

### 12.1 기본 표시

- 좌측 글로벌 내비에서 `맡긴 일`이 활성 상태로 표시된다.
- 중앙 상단에 제목, 설명, `작업 맡기기`, 더보기 버튼이 표시된다.
- `진행 중`, `승인 대기`, `예약됨`, `완료` 탭과 카운트가 표시된다.
- 필터, 검색, 보기 전환 컨트롤이 표시된다.
- 목록 행은 작업명, 태그, 생성 시각, 진행률, 남은 시간, 담당 에이전트, 도구, 비용/시간, 최근 로그를 표시한다.
- 선택된 run은 우측 상세 패널에 표시되고 목록 행은 선택 상태로 강조된다.

### 12.2 상세 패널

- 상세 패널은 작업명, 상태 배지, 닫기 버튼을 표시한다.
- `개요`, `상세 로그`, `파일 & 결과`, `설정` 탭 전환이 가능하다.
- 개요 탭은 에이전트 스웜, 승인 대기, 작업 제어, 이 작업에 말하기를 표시한다.
- 에이전트 스웜은 오케스트레이터와 하위 에이전트 관계를 트리로 표시한다.
- 승인 요청이 있으면 예상 비용, 대상 조건, 승인/거절 버튼이 표시된다.
- 승인 요청이 없으면 승인 대기 섹션은 숨기거나 “승인 대기 없음” 상태를 표시한다.

### 12.3 실행 제어

- running run에서 `일시정지`를 누르면 상태가 `paused`로 전환되고 새 tool call이 생성되지 않는다.
- paused run에서 `재개`를 누르면 마지막 체크포인트부터 실행된다.
- `중지`를 누르면 확인 모달을 거쳐 `stopping` 후 종료 상태로 전환된다.
- failed run은 조건이 맞을 때 `재시도`가 가능하다.
- 모든 제어 액션은 audit log에 사용자, 시각, 이전 상태, 이후 상태를 남긴다.

### 12.4 승인 / 비용 / 권한

- 외부 예약, 결제, 비용 상한 초과, 권한 상승이 필요한 작업은 실행 전 approval_request를 생성한다.
- 승인 직전 예상 비용과 권한 유효성을 재검증한다.
- 승인 권한이 없는 사용자는 승인 버튼을 사용할 수 없다.
- credential 만료 시 run은 중단 없이 무한 재시도하지 않고 사용자 복구 동선을 제공한다.
- 외부 결제 비용과 모델/API 비용은 구분해 표시한다.

### 12.5 연계

- run 결과 artifact는 파일, 작업면, 주제 중 연결 대상 화면에서 열 수 있다.
- scheduled run은 캘린더 화면과 동기화된다.
- topicId가 있는 run은 주제 화면에서 조회 가능하다.
- agentId가 있는 run은 에이전트 빌더의 최근 run에 노출된다.

### 12.6 접근성 / 반응형

- 모든 버튼은 키보드 포커스와 스크린리더 레이블을 가진다.
- 상태는 색상만으로 구분하지 않고 텍스트 배지를 함께 표시한다.
- 검색 입력, 승인 버튼, 작업 제어 버튼은 탭 순서가 자연스럽다.
- 좁은 화면에서는 우측 상세 패널이 drawer로 전환되고 목록은 단일 컬럼 카드로 축약된다.

## 13. 자체 엣지케이스 리뷰

nested subagent 리뷰는 로컬 PRD/작성 문서/이미지의 외부 전송 위험 때문에 실행하지 않고, 자체 리뷰로 대체한다.

| 항목 | 점검 결과 |
| --- | --- |
| 이미지 기능 누락 | 좌측 내비, 상태 탭, 필터/검색/보기 전환, 목록 컬럼, 우측 탭, 스웜, 승인 카드, 제어 버튼, 작업 말하기, 빠른 지시를 반영함 |
| 승인/비용/권한 | 승인 만료, 가격 변경, 권한 없음, credential 만료, 비용 상한, 외부 결제 분리를 포함함 |
| 상태 모델 | 진행/승인/예약/완료 탭에 매핑 가능한 내부 상태와 전이를 정의함 |
| 제어 정책 | pause/resume/stop/retry의 데이터 보존, 외부 호출, 재시도 범위를 정의함 |
| 연계 | 오늘, 주제, 작업면, 기억, 캘린더, 파일, 에이전트, 연결, 설정과의 이동/데이터 연계를 포함함 |
| 예약 작업 | 예약 탭, schedule 수정 시나리오, schedule API와 캘린더 연계를 포함함 |
| 구현 힌트 | 목록/상세/로그/승인/제어/schedule API와 주요 타입 필드를 포함함 |
| 목록 상태 | 로딩, 빈 목록, 검색 결과 없음, 오류, 부분 갱신 실패 상태를 포함함 |

## 14. 오픈 질문

| 질문 | 결정 필요 이유 |
| --- | --- |
| 진행률 산정 기준을 step 수, 예상 소요시간, 오케스트레이터 가중치 중 무엇으로 표준화할지 | 목록 정렬과 남은 시간 추정 정확도에 영향 |
| 비용 표시는 달러 기준으로 통일할지, 사용자 지역 통화 기준으로 환산할지 | 이미지에는 모델 비용은 달러, 외부 예약 비용은 원화로 표시됨 |
| `승인 대기` 탭에 approval_request 단위로 보여줄지 run 단위로 보여줄지 | 같은 run에 여러 승인 요청이 있을 때 UX와 API 구조가 달라짐 |
| 중지된 run의 `재시도`를 허용할지, `복제 실행`으로만 제공할지 | 외부 쓰기/결제 중복 실행 위험 관리 필요 |
| 실행 중 에이전트 추가를 MVP에 포함할지 | 스웜 트리에는 버튼이 보이나 구현 복잡도가 높음 |
| 상세 로그에서 tool call 입력/출력을 얼마나 노출할지 | 보안, 개인정보, 디버깅 가치 균형 필요 |
| run chat의 메시지가 전역 대화 히스토리에 함께 노출되는지 | 사용자가 나중에 같은 지시를 어디서 찾는지에 영향 |
| 완료 탭에서 실패/중지/만료를 별도 필터 chip으로 제공할지 | 완료 탭 카운트가 커질수록 탐색성이 중요 |
| 예약됨 탭에서 반복 schedule의 다음 실행만 보여줄지 전체 미래 실행을 보여줄지 | 캘린더와 중복 표시 정책 필요 |
| 승인 요청 알림의 기본 채널을 앱 내 알림만으로 할지 이메일/푸시까지 포함할지 | 장시간 unattended 작업의 실사용성에 영향 |
