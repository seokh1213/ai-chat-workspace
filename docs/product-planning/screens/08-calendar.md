# 08. 캘린더 / Calendar 화면 상세 기획

## 1. 화면 목적

`캘린더` 화면은 사용자의 수동 일정과 AI에게 예약한 자동 작업을 같은 시간축에서 보고, 충돌을 조정하고, 반복 실행을 켜고 끄는 시간 기반 작업 관리 화면이다.

PRD 기준으로 캘린더는 단순 일정 조회 화면이 아니라 `calendar_event`, `schedule`, `run`, `task`, `topic`, `approval_request`가 만나는 실행 조정면이다. 사용자는 “언제 무엇을 해야 하는지”와 “AI가 언제 무엇을 대신 실행하는지”를 한눈에 확인하고, 오른쪽 패널에서 오늘 일정·일정 제안·반복 자동 작업을 바로 처리한다.

| 사용자 문제 | 화면에서의 해결 방식 |
| --- | --- |
| 수동 일정과 자동 작업이 따로 보여 전체 시간을 파악하기 어려움 | 주간 캘린더에 두 유형을 함께 표시하되 `AI 자동 작업` 배지와 색상/아이콘으로 구분 |
| AI가 예약한 작업이 내 일정과 충돌할 수 있음 | 일정 제안 영역에서 이동/변경/충돌 해소안을 제시하고 개별 적용 또는 모두 적용 제공 |
| 반복 자동 작업이 실제로 켜져 있는지 기억하기 어려움 | 우측 `반복 자동 작업` 목록에서 다음 실행 규칙과 토글 상태를 노출 |
| 특정 날짜의 일정만 빠르게 보고 싶음 | 우측 날짜 상세 패널에서 오늘 일정, 제안, 반복 작업을 요약 |
| 일정 변경을 메뉴 조작 없이 요청하고 싶음 | 하단 입력창 `일정에 대해 말하기...`에서 자연어로 일정 생성/변경/예약 요청 |

## 2. 화면 범위와 전제

- 이 문서는 첨부 이미지와 `/docs/personal-agent-platform-prd.md` 기준의 PC 웹 화면 상세다.
- 소유 파일은 이 문서 하나이며, 글로벌 좌측 내비게이션은 공통 셸로 간주한다.
- 화면명은 한국어 `캘린더`, 영문 라우트/내부 개념은 `Calendar`를 사용한다.
- 월/주/일/목록 보기를 모두 제공하되, 첨부 이미지 기준 기본 보기는 `주`다.
- 일정 생성은 수동 입력, 채팅 명령, 할 일/주제/맡긴 일에서의 승격, 자동 schedule 생성 모두에서 발생할 수 있다.
- 외부 캘린더 연동이 없어도 내부 캘린더는 동작한다. 외부 캘린더 쓰기, 항공권 확인, YouTube 요약처럼 외부 서비스가 필요한 자동 작업은 연결/권한 상태를 확인한다.

## 4. 정보 구조

### 4.1 전체 레이아웃

```text
좌측 글로벌 내비게이션
  └─ 캘린더 메뉴 활성화

중앙 메인 영역
  ├─ 화면 제목 / 설명 / 자동 작업 예약 CTA / 더보기
  ├─ 캘린더 툴바: 오늘 / 이전 / 다음 / 날짜 범위 / 보기 전환
  ├─ 주간 시간 그리드
  ├─ 일정 카드
  └─ 색상 및 AI 자동 작업 범례

우측 날짜 패널
  ├─ 선택 날짜 / 모든 일정
  ├─ 오늘의 일정
  ├─ 일정 제안
  ├─ 반복 자동 작업
  └─ 일정 채팅 입력
```

### 4.2 좌측 글로벌 내비게이션

좌측 내비게이션은 공통 셸이다. 현재 화면에서는 `캘린더`가 활성 상태다.

| 영역 | 항목 | 동작 |
| --- | --- | --- |
| 상단 | 프로필 이미지, `내 AI 허브`, 드롭다운, 알림 | 허브/계정 전환, 알림 센터 진입 |
| 주요 메뉴 | 오늘, 주제, 맡긴 일, 기억, 에이전트, 연결 | 상위 화면 이동 |
| 보조 메뉴 | 스크랩, 캘린더, 할 일, 파일 | 관련 관리 화면 이동. 현재 `캘린더` 활성 |
| 하단 | 설정, 도움말 | 전역 설정과 도움말 이동 |
| 계정 카드 | `Minho`, `프로 플랜`, 드롭다운 | 플랜/계정 메뉴 표시 |

허브가 바뀌면 캘린더 이벤트, 반복 자동 작업, 일정 제안, 연결 권한 범위를 해당 허브 기준으로 재조회한다.

## 5. 진입 / 종료 / 전환 동선

### 5.1 진입 동선

| 진입점 | 랜딩 상태 |
| --- | --- |
| 좌측 내비게이션 `캘린더` 클릭 | 마지막 보기 모드와 날짜 범위를 복원. 없으면 현재 주 `주` 보기 |
| 오늘 화면의 예정된 자동 작업 클릭 | 해당 schedule이 포함된 날짜 범위로 이동하고 이벤트 선택 |
| 맡긴 일의 예약됨 run 클릭 | 연결된 schedule/run 이벤트를 선택하고 우측 패널에 관련 제안 표시 |
| 할 일 상세의 일정 클릭 | task dueDate 또는 scheduledAt 기준 날짜로 이동 |
| 주제 화면의 일정 탭 클릭 | topicId 필터가 적용된 캘린더로 진입 |
| 채팅에서 “이번 주 일정 보여줘” | 캘린더 화면 또는 인라인 카드로 주간 보기 제공 |
| 알림에서 충돌/승인 요청 클릭 | 해당 날짜와 approval_request 또는 conflict suggestion 선택 |

| 종료 액션 | 결과 |
| --- | --- |
| 다른 좌측 메뉴 클릭 | 현재 보기 모드, 날짜 범위, 선택 날짜, 필터를 세션 범위에서 보존 |
| `모든 일정` 클릭 | 목록 보기 또는 전체 일정 필터 화면으로 전환 |

| 반복 작업 `관리` 클릭 | 맡긴 일의 예약됨 탭 또는 schedule 관리 화면으로 이동 |
| 자연어 입력으로 주제/할 일 생성 | 생성된 topic/task/run 화면으로 이동하거나 현재 캘린더에 반영 |

### 5.3 화면 내 전환

| 전환 | 기대 동작 |
| --- | --- |
| `오늘` 클릭 | 현재 날짜가 포함된 범위로 이동하고 선택 날짜를 오늘로 설정 |
| 이전/다음 클릭 | 보기 모드에 따라 이전/다음 월, 주, 일로 이동 |
| 날짜 범위 드롭다운 | 미니 캘린더 또는 날짜 선택 팝오버 표시 |

| 이벤트 카드 클릭 | 이벤트 상세 표시, 관련 run/schedule/task/topic 액션 노출 |

| 일정 제안 적용 | 이벤트 시간/날짜 변경 후 캘린더와 우측 패널 동시 갱신 |
| 반복 자동 작업 토글 | schedule 활성/비활성 변경, 다음 실행 시간 재계산 |

## 6. 핵심 시나리오

### 6.1 이번 주 일정과 자동 작업을 확인

1. 사용자가 `캘린더` 화면에 진입.
2. 시스템은 현재 주 기준 수동 일정과 자동 작업을 함께 조회.
3. 사용자는 색상 범례와 `AI 자동 작업` 배지로 이벤트 성격을 구분.
4. 우측 패널에서 선택 날짜의 일정 4개와 duration을 확인.
5. 필요한 경우 `모든 일정`을 눌러 목록 보기로 전환.

### 6.2 자동 작업을 새로 예약

1. 사용자가 상단 `자동 작업 예약` 클릭.
2. 시스템은 작업명, 연결 주제, 실행 도구, 반복 주기, 실행 시간, 결과 전달 방식, 비용 한도, 승인 정책 입력 플로우를 연다.
3. 사용자가 “항공권 가격 확인, 매일 오전 9시”처럼 입력.
4. 시스템은 필요한 connection, credential, permission, cost limit을 검사.
5. 승인 필요 없음 또는 승인 완료 시 `schedule`을 생성.
6. 캘린더에 `AI 자동 작업` 배지가 붙은 이벤트가 표시되고 우측 반복 자동 작업 목록에 추가됨.

### 6.3 일정 제안을 개별 적용

1. 시스템이 충돌 또는 더 적합한 빈 시간을 감지.
2. 우측 `일정 제안`에 “블로그 초안 피드백을 5/23 (목) 오후 4:00로 이동 제안”을 표시.
3. 사용자가 해당 제안의 `적용` 클릭.
4. 시스템은 대상 이벤트의 시간 변경 가능 여부와 권한을 재검사.
5. 변경 성공 시 캘린더 카드 위치와 우측 오늘 일정 목록이 갱신.
6. 적용된 제안은 목록에서 제거되거나 `적용됨` 상태로 짧게 표시.

### 6.4 일정 제안을 모두 적용

1. 우측 `일정 제안 2` 영역에서 사용자가 `모두 적용` 클릭.
2. 시스템은 각 제안의 충돌 여부와 권한을 순차 검증.
3. 일부 제안이 외부 캘린더 쓰기나 비용 발생 작업이면 승인 모달을 먼저 표시.
4. 적용 가능한 제안은 반영하고, 실패/승인 필요 제안은 남긴다.
5. 결과 toast에 적용 성공 수, 실패 수, 승인 대기 수를 표시.

### 6.5 반복 자동 작업을 끄기

1. 사용자가 `반복 자동 작업`에서 `시장 리포트 요약` 토글을 끔.
2. 시스템은 이미 queued/running 상태인 실행 건이 있는지 확인.
3. queued/running run이 없으면 schedule을 `paused`로 변경.
4. queued/running run이 있으면 `이번 실행 후 끄기`, `지금 중지하고 끄기`, `취소` 선택지를 제공.
5. 변경 결과를 audit log에 남기고 다음 실행 시간을 제거하거나 `일시중지됨`으로 표시.

### 6.6 수동 일정을 생성

1. 사용자가 캘린더 빈 영역을 클릭하거나 자연어 입력에 “화요일 오후 2시에 주간 리뷰 준비 넣어줘” 입력.
2. 시스템은 제목, 시작/종료 시간, 카테고리, 연결 주제/할 일을 추출.
3. 충돌이 있으면 바로 저장하지 않고 충돌 안내와 대체 시간을 제안.
4. 사용자가 확인하면 `calendar_event`를 `manual` 유형으로 생성.
5. 우측 오늘 일정 목록과 중앙 그리드에 새 카드가 표시.

### 6.7 자동 작업 실행 실패를 확인

1. 예약된 자동 작업 실행 중 connection 만료 또는 비용 한도 초과 발생.
2. 캘린더 카드 또는 우측 반복 작업 항목에 실패/승인 필요 상태를 표시.
3. 사용자가 항목 클릭.
4. 맡긴 일 상세 또는 연결 화면으로 이동해 실패 로그, 권한, 비용 한도를 확인.
5. 사용자가 권한을 갱신하거나 재시도하면 다음 실행부터 정상 schedule로 복귀.

## 8. 수동 일정과 자동 작업 구분

수동 일정과 자동 작업은 같은 `calendar_event`로 표시되지만 생성 주체, 권한, 실행 방식이 다르다.

| 구분 | 수동 일정 | 자동 작업 |
| --- | --- | --- |
| 내부 source | `manual`, `task`, `topic` | `schedule`, `run`, `agent` |
| 생성 주체 | 사용자 직접 입력, 할 일/주제에서 일정 추가 | 사용자의 예약 명령, 자동 작업 예약 CTA, agent 제안 적용 |
| 화면 표시 | 카테고리 색상, 제목, 보조 설명 | 카테고리 색상 + `AI` 또는 `AI 자동 작업` 배지 |
| 실행 | 알림/표시 중심 | 지정 시각에 agent/tool/run 실행 |
| 권한 | 내부 일정 쓰기 권한 | 연결, 도구, 비용, 외부 쓰기 권한 필요 가능 |
| 실패 상태 | 저장/동기화 실패 중심 | 실행 실패, 권한 만료, 비용 한도, 승인 대기 |
| 토글 | 일정 자체에는 토글 없음 | 반복 schedule 활성 토글 제공 |
| 리스케줄 | 사용자가 바로 변경 가능 | schedule 규칙 또는 occurrence 변경 여부를 구분 |

자동 작업 이벤트를 드래그할 때는 사용자가 단일 occurrence만 옮기는지, 반복 규칙 전체를 바꾸는지 확인해야 한다.

## 9. 일정 제안 / 충돌 / 리스케줄 / 반복 작업 토글

### 9.1 일정 제안 생성 기준

| 기준 | 예시 |
| --- | --- |
| 시간 충돌 | 같은 시간대에 두 이벤트가 겹침 |
| 실행 불가 | 연결 만료, 권한 부족, 비용 한도 초과로 예약 실행 불가 |
| 더 나은 빈 시간 | 일정 사이 여유, 업무 시간, 사용자의 선호 시간 기반 |
| 주제 흐름 | 도쿄 여행 체크리스트를 여행 확정 일정 앞에 배치 |
| 반복 작업 과밀 | 같은 시간대 자동 작업이 여러 개 몰림 |
| duration 부족 | 이벤트 사이 간격이 예상 실행 시간보다 짧음 |

### 9.2 충돌 표시

| 충돌 유형 | 표시/처리 |
| --- | --- |
| 수동 일정끼리 충돌 | 카드 겹침 표시, 우측 제안에서 이동 시간 제시 |
| 수동 일정과 자동 작업 충돌 | 자동 작업 이동을 우선 제안하되 사용자 선호에 따라 수동 일정 이동도 가능 |
| 자동 작업끼리 충돌 | 비용/도구/연결 부하 기준으로 순서 조정 제안 |
| 외부 캘린더와 충돌 | 외부 동기화 상태와 충돌 원본 표시 |
| all-day 일정과 시간 일정 충돌 | all-day 일정의 busy/free 속성을 확인 |

### 9.3 리스케줄 적용 방식

| 적용 방식 | 동작 |
| --- | --- |
| 단일 이벤트 이동 | 해당 calendar_event만 start/end 변경 |
| 반복 occurrence 이동 | 특정 occurrence만 예외 날짜로 저장 |
| 반복 규칙 변경 | schedule의 recurrenceRule과 nextRunAt 재계산 |
| 자동 작업 실행 시간 변경 | schedule 설정 변경 후 다음 실행부터 적용 |
| 지금 실행 | schedule 규칙은 유지하고 ad-hoc run 생성 |

반복 작업의 특정 occurrence를 옮기면 원 schedule에는 `exceptionDates` 또는 `overrides`를 남겨야 한다.

### 9.4 반복 작업 토글

| 토글 대상 상태 | 처리 |
| --- | --- |
| active → paused | 다음 실행 예약 해제, 기존 기록 보존 |
| paused → active | 다음 실행 시간 재계산, 권한/연결/비용 재검사 |
| active + queued run 존재 | 이번 실행 후 끄기 또는 queued run 취소 선택 |
| active + running run 존재 | 실행 중지 영향 확인 후 중지/유지 선택 |
| failed schedule 재활성화 | 실패 원인 해결 여부 확인 후 재개 |

토글 변경은 optimistic update 가능하지만 실패 시 원래 상태로 되돌리고 오류를 표시한다.

## 10. 권한 / 승인 / 실패 edge case

### 10.1 권한과 승인

| 상황 | 처리 |
| --- | --- |
| 외부 캘린더 쓰기 권한 없음 | 내부 일정만 저장하거나 연결 화면으로 이동 CTA 표시 |
| Google/Outlook OAuth 만료 | 이벤트 읽기/쓰기 중지, 재인증 CTA 표시 |
| 자동 작업이 외부 API 호출 필요 | connection permission과 tool capability 확인 |
| 자동 작업이 외부 쓰기/예약/결제 유발 | approval_request 생성 후 승인 전 실행 보류 |
| 비용 한도 초과 예상 | 비용 승인 또는 schedule 생성 차단 |
| 팀/허브 캘린더 권한 부족 | 읽기 전용 표시, 편집/토글 비활성 |
| schedule 소유자와 현재 사용자가 다름 | 관리자/소유자 권한에 따라 토글·삭제 제한 |

### 10.2 실패와 복구

| 실패 | 사용자 표시 | 복구 동작 |
| --- | --- | --- |
| 이벤트 저장 실패 | toast와 원복 | 재시도, 오프라인 임시 저장 |
| schedule 생성 실패 | 예약 실패 카드 | 권한/연결/비용 원인별 CTA |
| 반복 작업 실행 실패 | 이벤트 카드 실패 배지, 맡긴 일 로그 링크 | 재시도, 다음 실행 유지/중지 선택 |
| 일정 제안 적용 실패 | 제안 카드에 실패 상태 유지 | 단일 재시도, 직접 시간 선택 |
| 외부 캘린더 동기화 지연 | 마지막 동기화 시간 표시 | 수동 동기화 |
| timezone 변환 오류 | 원본 timezone과 표시 timezone 동시 안내 | 사용자 timezone 재설정 |
| 중복 이벤트 생성 | 중복 감지 안내 | 병합, 유지, 삭제 선택 |

### 10.3 시간 관련 edge case

| edge case | 처리 |
| --- | --- |
| 자정 넘어가는 일정 | 시작일과 종료일을 분리해 표시, 목록에는 전체 duration 표시 |
| all-day 일정 | 시간 그리드 상단 영역에 표시 |
| DST 변경일 | event timezone 기준으로 실제 실행 시각 계산 |
| 사용자가 timezone 변경 | 표시 시간 재계산, schedule nextRunAt 재계산 여부 확인 |
| 반복 규칙의 예외 날짜 | occurrence override를 우선 적용 |
| 같은 시간 다중 이벤트 | 같은 컬럼 내 폭 분할, 최소 카드 폭 보장 |
| duration 미정 자동 작업 | 예상 duration으로 표시하고 실제 run duration으로 기록 갱신 |

## 13. 수용 기준

| ID | 기준 |
| --- | --- |
| CAL-01 | 사용자는 주간 보기에서 수동 일정과 AI 자동 작업을 같은 시간축으로 볼 수 있다. |
| CAL-02 | AI 자동 작업은 카드와 우측 목록에서 `AI` 또는 `AI 자동 작업` 배지로 구분된다. |
| CAL-03 | 사용자는 월/주/일/목록 보기로 전환할 수 있고 선택 날짜/필터가 유지된다. |
| CAL-04 | 사용자는 `자동 작업 예약`으로 반복 schedule을 만들 수 있다. |
| CAL-05 | 반복 자동 작업 토글 변경 시 active/paused 상태와 다음 실행 시간이 갱신된다. |
| CAL-06 | 사용자는 일정 제안을 개별 적용하거나 모두 적용할 수 있다. |
| CAL-07 | 제안 적용 중 승인/권한/비용 문제가 있으면 적용 전 차단되고 이유가 표시된다. |
| CAL-08 | 수동 일정과 자동 작업의 단일 occurrence 변경과 반복 규칙 변경이 구분된다. |
| CAL-09 | 오늘의 일정 목록은 선택 날짜의 시간순 이벤트, duration, 카테고리, AI 배지를 표시한다. |
| CAL-10 | 자연어 입력으로 일정 생성, 자동 작업 예약, 리스케줄 요청, 반복 작업 토글 요청을 시작할 수 있다. |
| CAL-11 | 외부 연결 만료, 비용 한도 초과, 실행 실패는 캘린더에서 식별 가능하고 연결/맡긴 일 화면으로 이동할 수 있다. |
| CAL-12 | 이벤트 카드는 겹침, 긴 제목, 짧은 duration에서도 레이아웃이 깨지지 않는다. |
| CAL-13 | timezone은 화면에 표시되고 API 요청/응답에 포함된다. |
| CAL-14 | 이벤트 생성/수정/삭제, schedule 토글, 제안 적용은 audit log에 남는다. |
| CAL-15 | 권한 없는 사용자는 읽기 전용으로 볼 수 있고 편집/토글/삭제 액션은 비활성화된다. |

## 14. 자체 엣지케이스 리뷰

| 점검 항목 | 반영 결과 |
| --- | --- |
| 수동 일정과 자동 작업의 source 혼동 | `sourceType`, `eventType`, `isAiManaged`를 분리해 표시/권한/실행 기준을 명시 |
| 반복 작업 occurrence 변경 누락 | 단일 occurrence, 반복 규칙 변경, exception/override 저장 방식을 분리 |
| 토글 중 queued/running run 처리 누락 | 이번 실행 후 끄기, 지금 중지하고 끄기, 취소 분기 추가 |
| 제안 일괄 적용의 부분 실패 | 성공/실패/승인 대기 수를 나눠 표시하도록 정의 |
| 외부 캘린더 권한과 내부 일정 권한 혼합 | 내부 저장과 외부 쓰기를 분리하고 connection/approval 조건 명시 |
| timezone/DST/자정 넘김 | 시간 관련 edge case 섹션에 별도 처리 기준 추가 |
| 다른 화면으로의 책임 이동 | 연결, 맡긴 일, 할 일, 주제, 설정과의 이동 기준 명시 |
